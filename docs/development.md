# Development

## Architecture

```
Browser (Svelte SPA) ──HTTP/JSON──> ASP.NET Core API ──Dapper──> MariaDB
                                          ├── /app/ingest   input
                                          ├── /app/roms     library (one ZIP per game; Switch ROMs, disc images and, by default, DS ROMs beside their ZIPs)
                                          ├── /app/logs
                                          ├── /app/cache    DATs, work folders
                                          ├── /app/backups  database backups
                                          ├── /app/collections  collection cover images
                                          ├── /app/bios     emulator BIOS files (operator-supplied)
                                          └── HTTPS: raw.githubusercontent.com (DATs, titledb), thumbnails.libretro.com,
                                                     img-eshop.cdn.nintendo.net (Switch images)
```

One container: the API serves the built SPA from `wwwroot` and everything under `/api`. The design is in [specs/completed/initial-application.md](../specs/completed/initial-application.md); the build order in [specs/completed/initial-application-impl.md](../specs/completed/initial-application-impl.md).

- **Library ZIPs are the source of truth**; the database is a mirror rebuilt from them ([ZIP format](zip-format.md)). A system whose handler says `EmbedRomsInZip: false` (Switch) keeps each ROM as a file next to its ZIP, named `<ZipBase>.<rom fileName>` and listed in `info.json` as `externalFileName`. Every path under the configured roots goes through `Core/Storage/ExternalRomPath` (no links or special files, checked handles), and every move through `ExternalRomMove` (exclusive staging, no-replace rename, verified copy across volumes).
- **DAT sources:** a handler's `DatSource` is `Libretro` (its main DAT from `DatFolder`, `no-intro/` or `redump/`, plus the metadat files `MetadatKinds` lists, none to four; matched by SHA1) or `TitleDb` (one shared titledb download, stored per system as a compact file and matched by title id in `Core/Dats/TitleDb.cs`).
- **One job at a time:** ingestion, integrity, DAT refresh, media retry and review resolution run in the background under one in-process lock, and library edits and review dismiss/delete take the same lock synchronously (`409 JobRunning` when busy). A job whose `IJob.Cancellable` is false (review resolution) ignores cancel (`409 NotCancellable`) and shutdown. Progress is kept in memory (`GET /api/jobs/current`), including the current file's streamed step (`JobProgress.BeginStep`/`StepAdvanced`/`EndStep`: an external ROM's hash and copies, a deep integrity re-hash); jobs and their items are stored in the database. That's why only one app instance may use a database.
- **Time** comes from an injected `TimeProvider` everywhere, so tests use `FakeTimeProvider`.
- **API integration tests share one host per class:** `[OneTimeSetUp]` builds the `ApiFactory` and calls `StartSharedAsync`, and every `[SetUp]` starts with `ResetAsync`, which waits for a running job and pending audit events, restores the database rows and the files under the host's root (logs excepted) to their just-started state, and reloads the DATs. Classes whose tests change the host's configuration per test (clock, settings, services) or depend on in-memory state outside that reset (`BackupService`'s last result, the console, the log) keep a host per test. `scripts/test-dotnet.ps1` runs the .NET tests in shards (separate processes, each with its own MariaDB container on tmpfs), in parallel locally and one CI job each.
- **Outbound HTTP** goes through named clients in `Api/Http/HttpClients.cs`. The DAT and thumbnail clients retry transient failures with a 20 s timeout per attempt; that timeout ends with the response headers, so the titledb download (up to 256 MiB) is read under the job token only. Switch images use their own `titledbImages` client (the typed `Core/Media/TitleDbImageClient`), with the same retries and redirects turned off; `MediaService` re-checks every URL against the CDN rule before the request and gives an external system's image body its own 20 s deadline on the injected `TimeProvider`, counted once against the job's circuit breaker. The image-URL client (`ImageUrlDownloader`) has no retries and no proxy, one 15 s timeout over headers and body, a bounded 8 MiB read, and a `ConnectCallback` that resolves the host and connects only when every address passes `Core/Media/PublicAddress.IsPublic` (so redirects and DNS rebinding are checked too). The check and the timeout are one `ImageUrlPolicy` singleton; integration tests replace it to allow a loopback Kestrel stub (`StubImageServer`) and shorten the timeout.

A generated index of routes, pages, jobs, handlers, files, tests and doc sections is in [codemap.md](codemap.md) (`pwsh scripts/codemap.ps1` regenerates it); playbooks for common changes are in [recipes.md](recipes.md).

## Getting started

Needs .NET 10 SDK, Node 24+, Docker (running) and PowerShell 7.

```powershell
pwsh scripts/setup-dev.ps1   # checks tools, restores, npm ci, starts the dev MariaDB, writes config
pwsh scripts/seed-ingest.ps1 # synthetic ROMs + fixture DATs (below)
pwsh scripts/start-dev.ps1   # API on :5080 (dotnet watch) + Vite on http://localhost:5173
```

- `setup-dev.ps1` (`-SkipDb` to leave the database alone) is safe to re-run. It keeps the dev DB password in the git-ignored `.env` (creating one if missing), starts `docker-compose.dev.yml` (MariaDB 11.4 on 3306), creates `.dev/{roms,ingest,logs,cache,backups,collections,bios}`, and writes a git-ignored `src/RnRomManager.Api/appsettings.Development.json` with the connection string and absolute `.dev` paths. An existing settings file is kept (only missing `Paths` entries, such as `Backups`, `Collections` or `Bios`, are added: re-run it after pulling a change that adds a storage root); delete it to regenerate. It also installs the e2e project's packages and Playwright's Chromium (on Linux, run `npx playwright install-deps` once for the system libraries).
- `start-dev.ps1` runs both servers in one console; Ctrl+C stops both. `-ApiOnly` / `-WebOnly` run one. Vite proxies `/api` and `/health` to the API.
- The first API start on an empty database prints the generated `admin` password to the console once; signing in asks you to change it. Then Ingestion → Import all ingests the seeded files.

## Synthetic ingestion data

No real ROMs or downloaded DATs are needed. From any working directory, run `scripts/seed-ingest.ps1` by its path in the checkout. It defaults to the checkout's `.dev/ingest` and `.dev/cache`, with `-Set Basic`. Use `-Path` and `-CachePath` to choose other folders; relative overrides resolve from your working directory. `-Clean` empties only the selected ingest folder, including old `_failed/`, `_duplicates/` and review source files. It preserves the library and unrelated cache contents. Root/overlapping folders, the repository or its ancestors, and linked cleanup targets are rejected. `-NdsDat <file>` (repeatable) makes the seeded Nintendo DS No-Intro DAT list each file instead of the empty catalog (game name: the file name without its extension; ROM name: the file name), hashed in one streamed read and not copied into ingest. `-NdsGenerate <file> -Size <bytes> -Seed <n>` writes one synthetic DS ROM with a valid header CRC instead of seeding, streamed to disk (the TestData CLI options are `--nds-dat` and `--nds-generate … --size … --seed …`). Together they stage maximum-size DS runs outside CI.

The CLI is also available directly:

```powershell
dotnet run --project tests/RnRomManager.TestData -- --ingest .dev/ingest --cache .dev/cache --set Basic
```

Both sets use deterministic builder seeds and fixture DAT version `fixture-1`. ZIP entries have a fixed timestamp; the 7z is the committed synthetic fixture. Input files are dated one minute before the injected clock so an immediate ingest does not skip them as TooRecent. Re-seeding overwrites the generated filenames and fixture DATs, while other ingest files remain unless `-Clean` is supplied. To switch from Full back to Basic, use `-Clean` to remove Full's extra source files first.

## End-to-end tests

`pwsh scripts/test-e2e.ps1` (`-SkipBuild` reuses `niemandr/rnrommanager:e2e`, `-Headed` shows the browser) builds the image for your machine's architecture, seeds `Basic` into a temp folder, starts `tests/e2e/docker-compose.e2e.yml` twice (MariaDB on tmpfs + the app on `127.0.0.1:18080` and `:18081`, `E2E_PORT` to change the first) with random per-run DB and admin passwords and media fetch disabled, waits for `/health/ready` on both, runs Playwright, and always tears both stacks down. The specs split across the two stacks by tag, two workers at once: `@both` (sign-in, ingest) runs on each, `@shard-b` only on the second, the rest only on the first; a `@shard-b` test may rely only on `@both` state and must leave nothing a later untagged test sees. On failure it prints both app logs; the HTML report and traces are in `tests/e2e/playwright-report` and `tests/e2e/test-results` (CI uploads both).

`tests/e2e/specs/mvp.spec.ts` walks one session through sign-in + forced password change, ingesting the seed, Reports (including system drill-down), library search/filters/views, game detail + ZIP/ROM downloads, the Switch game's External badges and a byte-exact per-release download, the PlayStation set's "3 files" list and a byte-exact download of its Track 2, browsing Publishers and Genres (Back/Forward, a shared selection link), browsing a system's games on the Systems tab and its Emulators links (axe scan of the open modal), an Admin replacing and removing a publisher's shared logo while a Site user sees it but has no **Change logo**, resolving the review item, the info.json modal, Images tab, Admin edit/move/delete and the Integrity/Admin pages. It checks ingest audit rows and scrolling after modal-driven release deletion, adds, edits and deletes a release note, plays Orbit Blocks in the emulator (the modal and iframe, the ROM download, **Start Game**, the Gambatte core's `.data` download and the game starting, Escape inside the iframe keeping the modal open, Close removing the iframe; the axe scan of the open modal excludes the iframe, since EmulatorJS's own UI isn't ours), starts Pixel Pioneer from the Library's Quick Play on the local FCEUmm core, plays Disc Runner from its release card (a 404 for `scph5501.bin`, so HLE; the `play-disc` ZIP fetched again through the request context and checked for its signature, canonical cue and Track 2 bytes; the local PCSX ReARMed core starting) and from the Library's Quick Play, shows Turbo Comet's and Star Relay's missing-core messages (no `Emulator:GenesisCorePath` or `Emulator:PicodriveCorePath` in the e2e image; the `HEAD /api/emulator/cores/<core>` returns 404 and nothing else is requested), plays Sky Rally (a 404 for `saturn_bios.bin`, then `play-disc`, then `loader.js`; after **Start Game** the vendored Yabause payload loads, but the synthetic disc isn't expected to boot), plays a game from Global Search (Shift+Enter opens its page with the Play dialog), uses and rebinds a keyboard shortcut, visits Reports → Activity (axe), downloads a DAT from Admin → DATs, runs **Back up now** (the backups folder is the image's anonymous volume, so the e2e compose file needs no mount). A `@shard-b` site-user flow, with its own two Site users, covers account management: an Admin creates a Site user, who must change the password at first sign-in (the same password is refused), sees no edit controls and uploads a save that the Admin sees and a second Site user doesn't; a wrong-password sign-in fails, the Admin disables the user and their next request is signed out, and the audit page lists `UserCreated`, `SignedIn`, `SignInFailed`, `PasswordChanged` and `UserDisabled`. Every page visited is scanned with axe (`specs/axe.ts`) and fails on `serious` or `critical` WCAG A/AA violations.

Run `pwsh scripts/test-e2e.ps1 -Screenshots` to regenerate the README's three screenshots on a fresh seeded stack. The 1440×900 light-theme PNGs are written to `docs/images/`. The screenshots include the current dates and times.

## Web app structure

The SPA in `src/RnRomManager.Web` is SvelteKit (static adapter, Svelte 5 runes) with Bootstrap 5.3. Import shared code through the `#lib/…` subpath import (TypeScript modules with a `.js` extension, e.g. `#lib/api/client.js`; components as `#lib/components/Icon.svelte`).

- `src/lib/api/client.ts` is the only way to call the API. It fetches `/api/auth/antiforgery` once and sends the `XSRF-TOKEN` cookie as `X-XSRF-TOKEN` on every POST/PATCH/DELETE. A `401` redirects to `/login?returnUrl=…` (pass `noRedirect` to handle it yourself), and `403 PasswordChangeRequired` redirects to `/change-password`. Other failures throw an `ApiError` carrying the ProblemDetails `code`, `title` and field `errors`.
- `src/lib/stores/`: `hotkeys` (the user's shortcut bindings, loaded once signed in with the password changed, and the `window` keydown handler the root layout installs), `auth` (the signed-in user), `jobs` (polls `/api/jobs/current` every 1.5 s while a page watches and a job runs, and every 15 s while watched, idle and the tab is visible, plus once when a tab becomes visible; `AppFooter` watches it for Admins and shows the running job, with `jobLabel` from `lib/jobs.ts`), `toasts` (`toasts.jobRunning(error)` shows the standard `409 JobRunning` toast), `navCounts` (the navbar's Review and Deleted ROMs counts; the layout refreshes them on navigation and job end, and pages that change them in place call `refreshCounts()`).
- `src/lib/components/`: `Icon` (semantic names in `icons.ts`; never use icon classes directly), `Loading`, `EmptyState`, `ErrorAlert`, `ConfirmModal` (Bootstrap modal with focus trapping; `size="lg"` for a wide form, `size="xl"` for the emulator; `scrollable` adds `modal-dialog-scrollable` (only `ReviewDeleteModal` uses it); `confirmDisabled` disables only the confirm button; without `onconfirm` it's an info modal with only Close; an optional `beforeclose` promise holds ×, Close/Cancel and Escape (`hide.bs.modal` is prevented) with the buttons disabled until it settles; an optional `onshown` runs on each `shown.bs.modal`, e.g. to focus a field), `Pagination` (Previous / Page x of y / Next, optional rows-per-page selector; sizes persist per table through `src/lib/pageSize.ts`), `SystemBadge` (system icon + name in a fixed colour per system), `AdminOnly` (shows "Not allowed" without the `admin` role), `Navbar` (icon-only Search and Bundle; ## Browser emulators

The Play dialog runs [EmulatorJS](https://emulatorjs.org) 4.2.3 in a same-origin iframe (`static/emulator/play.html`), so the app's CSP and hotkeys stay untouched. PSP is the exception: it opens `static/emulator/play-psp.html` in its own tab (below). Both pages share `play.js` and `play.css`.

- **Vendoring:** `@emulatorjs/emulatorjs`, `@emulatorjs/core-gambatte`, `@emulatorjs/core-mgba`, `@emulatorjs/core-handy`, `@emulatorjs/core-virtualjaguar`, `@emulatorjs/core-beetle_vb`, `@emulatorjs/core-a5200`, `@emulatorjs/core-prosystem`, `@emulatorjs/core-stella2014`, `@emulatorjs/core-gearcoleco`, `@emulatorjs/core-smsplus`, `@emulatorjs/core-fceumm`, `@emulatorjs/core-pcsx_rearmed`, `@emulatorjs/core-ppsspp`, `@emulatorjs/core-yabause`, `@emulatorjs/core-desmume`, `@emulatorjs/core-puae` and `@emulatorjs/core-mednafen_pce` are exact-version npm dependencies. `package.json` `overrides` alias `@emulatorjs/cores` (an optional dependency that would install every core, ~293 MB) to `core-gambatte`, and pin every `@emulatorjs/emulatorjs` to the direct dependency. `scripts/vendor-emulatorjs.mjs` runs from `predev` and `prebuild` and copies `loader.js`, the `src/` scripts, `emulator.css`, `compression/` and `version.json`, all sixteen cores' `-legacy-wasm` and `-wasm` `.data` files and reports (never their `-thread` variants), PPSSPP's `ppsspp-thread-wasm.data`, `ppsspp-assets.zip` and report (its package has only a threaded WebGL 2 build; `ppsspp-NOTICE.txt` traces the asset archive, Sony PSP system fonts included, to its source), EmulatorJS's licence and the reviewed notices and licence texts in `emulator-licenses/` (where each binary's source, submodule and RetroArch revisions, build scripts, flags and compiler come from, and component licences; a payload's own `license.txt` is copied there byte for byte as `<core>-LICENSE.txt`; kept byte-exact by `.gitattributes`) into `static/emulator/vendor/` (git-ignored; the licences land in `licenses/`). A core added later needs its notice there too. It writes `src/emulator.js` and `src/GameManager.js` with guarded edits (each anchor must occur exactly once, or vendoring fails). `getCore()` returns an explicit `smsplus`, `fceumm`, `pcsx_rearmed`, `genesis_plus_gx`, `picodrive`, `yabause`, `snes9x`, `desmume` or `opera` before reading the saved `retroarch_core` setting (Nintendo DS keeps the generic `nds` settings key, so a saved `melonds` is ignored), so Game Gear and Master System never switch to `genesis_plus_gx` or `picodrive`, NES to `nestopia`, PlayStation to `mednafen_psx_hw`, Genesis (whose first group is `segaMS`) to `smsplus` or `picodrive`, or 32X (also `segaMS` first) to `smsplus` or `genesis_plus_gx`; `yabause`, `snes9x` and `opera` are listed only defensively, since their `segaSaturn`, `snes` and `3do` groups hold nothing else. The core download always picks PPSSPP's threaded payload when `SharedArrayBuffer` exists and never a threaded Genesis Plus GX, PicoDrive, Yabause, Snes9x, DeSmuME or Opera one, whatever `ejs_threads` was saved (EmulatorJS 4.2.3's `requiresThreads` lists only `ppsspp` and `dosbox_pure`); a Genesis Plus GX, PicoDrive, Snes9x, DeSmuME or Opera payload that can't be fetched shows *Error downloading core* instead of falling back to `cdn.emulatorjs.org`. For DeSmuME only, `GameManager.saveSaveFiles()` also calls `FS.syncfs(false)` (upstream comments that call out), so the 30-second save interval persists the `.dsv` battery save DeSmuME keeps open in `/data/saves`. For PPSSPP and DeSmuME, a rejected `File` read shows *Error reading the game file*, and for PPSSPP a failed or unreadable `ppsspp-assets.zip` shows a startup error, instead of leaving the loader's promises pending; `getCore(true)` (the `segaMS`, `nes`, `psx` and `snes` groups that controls and settings use) and every other core behave as upstream. Vendoring fails if the upstream `getCore()` fragment changes. It also writes `emulator.min.js` (the `src/` scripts, with the edited `emulator.js`, concatenated in `loader.js`'s order) and `emulator.min.css`, since the package ships no minified build. No localization files are copied. Upgrading EmulatorJS means re-checking that concatenation, the guarded edits and the CSP below. EmulatorJS lists its own build tools as dependencies, so `npm audit` reports issues in packages that are never run or shipped.
- **Play page:** `play.js` validates the query with `params.js` (`parsePlayParams`: a game GUID, a positive release id, one of the modal's cores `gambatte`/`mgba`/`handy`/`virtualjaguar`/`beetle_vb`/`a5200`/`prosystem`/`stella2014`/`gearcoleco`/`smsplus`/`fceumm`/`pcsx_rearmed`/`yabause`/`puae`/`mednafen_pce` (vendored) or `genesis_plus_gx`/`picodrive`/`snes9x`/`opera`/`vice_x64sc` (operator-supplied), a 1–255 char name, and an optional `disc` that must be exactly `1` when present: a repeated or other value is refused). For a core whose `biosFor(core)` names a BIOS (`colecovision.rom` for `gearcoleco`) it first GETs `/api/emulator/bios/<name>` (same origin, with credentials, so `connect-src 'self'` covers it), cancels the unused body and stops with `biosError`'s message on a failure (401 sign in again, 404 names the file and `Paths:Bios`, any other status, or a network error) before the ROM is requested or the loader added. It then fetches the ROM from `/api/games/{id}/roms/{romId}/download`, wraps it as a `File` named after the release (`#` → `_`, since EmulatorJS cuts names at `#`), sets the `window.EJS_*` globals (no save-state, netplay or cheat buttons, and no exit button except for 3DO; no IndexedDB ROM cache; a 30 s battery-save interval) and only then loads `loader.js`. With a BIOS it sets `EJS_biosUrl` to the endpoint URL: EmulatorJS downloads it again and writes it next to the ROM under the URL's last segment, the name Gearcoleco looks for. `EJS_disableDatabases` must stay `true`: EmulatorJS first sends a HEAD (unmapped, so 404), and only with databases off does it skip its cache and go on to the GET. For the pinned cores `smsplus` (Game Gear and Master System), `fceumm` (NES), `pcsx_rearmed` (PlayStation), `genesis_plus_gx` (Genesis), `picodrive` (32X) and `yabause` (Saturn) and `desmume` (Nintendo DS) (`hidesCoreChooser`) it sets `EJS_hideSettings = ['retroarch_core']` (`['retroarch_core', 'ejs_threads']` for DeSmuME), hiding the core selector (the vendored `getCore()` edit ignores a saved alternative core; other emulator and core settings, such as PCSX ReARMed's saved BIOS/HLE option, stay). NES uses the cartridge flow above unchanged. **PlayStation** (`pcsx_rearmed`) differs: it first sends one GET to `/api/emulator/bios/scph5501.bin` and reads the body with a 512 KiB bound (the reader is cancelled as soon as it's exceeded). A 404 means no firmware (the core's HLE BIOS), 401 shows the session-expiry message, and any other failure (status, network or body read) or a file that isn't exactly 512 KiB (`psxBiosSizeError`, naming scph5501.bin) stops before the disc is requested. A good firmware goes to `EJS_externalFiles = { '/scph5501.bin': <ArrayBuffer> }`: the pinned GameManager writes that direct key before the content, where the core finds it in the content root, so there's no second BIOS request and no `EJS_biosUrl`. It then fetches `/api/games/{id}/roms/{romId}/play-disc` ([features](features.md)): 401 shows the session-expiry message, `409 PlayDiscTooLarge` and `409 InvalidPlayDisc` (read from the problem's `code`) their own messages, and any other failure `discError`'s disc-loading message, all before the loader. The bytes are wrapped in a `File` named after the release (`contentFileName`; a standalone image named `scph5501.bin`, any case, becomes `<game id>-<name>` so the firmware can't overwrite it), while `EJS_gameName` stays the release name. EmulatorJS 4.2.3 detects the ZIP by its magic bytes, unpacks it into its file system and picks the cue for a cue-plus-BIN archive; the archive's `track-NN.bin` names never collide with the firmware, and its release-specific cue name keeps saves apart. A standalone `.iso` works because EmulatorJS falls back to the only file when no extension in the core's manifest matches. EmulatorJS 4.2.3 takes controls from the core's group (`segaMS` for `smsplus`, no Start), so `controlSchemeFor(core, name)` sets `EJS_controlScheme = 'segaGG'` for a release whose name ends in `.gg` (any case); a Game Gear release stored as `.sms` keeps Master System controls. `readContent` streams the ROM or disc body through a progress bar: its total is `Content-Length` when the body isn't compressed, else the server's `X-Content-Bytes` (the play-disc cue ZIP's payload size), and the label shows the percent, capped at 100%; with neither the bar is indeterminate (no `value`) and the label counts bytes.
- **PSP page:** `play-psp.html` (`<body data-player="psp">`) accepts only `ppsspp` and `play.html` rejects it (`parsePlayParams(search, pspPage)`), so PSP never runs in the modal. Before any request it checks `isSecureContext`, `crossOriginIsolated`, `SharedArrayBuffer` and a WebGL 2 context (`pspBrowserError`), then fetches the `.iso` from `play-disc` like PlayStation, with PSP wording for `PlayDiscTooLarge` (2 GiB) and `InvalidPlayDisc`. No BIOS is requested. It sets `EJS_threads = true`; after **Start Game** EmulatorJS loads `cores/reports/ppsspp.json`, `ppsspp-thread-wasm.data` and `ppsspp-assets.zip` from the same origin. In the SPA, `emulator.ts`'s `opensInNewTab`/`playUrl` turn both PSP Play actions into `target="_blank" rel="noopener"` links to that page.
- **Operator-supplied cores (Genesis, 32X, SNES, 3DO, Commodore 64):** `genesis_plus_gx`, `picodrive`, `snes9x`, `opera` and `vice_x64sc` (`isOperatorCore`) check `HEAD /api/emulator/cores/<core>` first (`operatorCoreCheckUrl`; `operatorCoreError(core, status)`: 404 names the core's option, `Emulator:GenesisCorePath`, `Emulator:PicodriveCorePath`, `Emulator:Snes9xCorePath`, `Emulator:OperaCorePath` or `Emulator:ViceCorePath`, 409 asks for 4.2.3 files, 401 session expiry), then fetch the ROM like any cartridge (Opera: the 3DO path below). They set `EJS_paths` (`operatorCorePaths(core)`) so EmulatorJS loads the two payloads and the report by basename from `/api/emulator/cores/<core>/<file>`, an explicit control scheme for the Sega cores (`segaMD` or `sega32x`: upstream would take `segaMS`, both cores' first group; Snes9x has none, since its only group is `snes`) and hide the core chooser. `EJS_disableCue` stays unset for cartridges: the pinned loader already skips cue generation for the Sega cores, and Snes9x's cartridge extensions never get one (the Sega CD disc path below sets it to `false`). A failed report fetch stays non-fatal as upstream (the payload is still requested; with no `defaultWebGL2` in the report a fresh browser gets the legacy payload), and a failed payload shows `Error downloading core (<file>)` instead of the CDN fallback. On the API side `OperatorCoreManifest` (a singleton in `AppHost`) maps each core id to its display name, option, mismatch code and pinned files, and one verifier in `EmulatorEndpoints` (logger category `EmulatorEndpoints.OperatorCoreLog`) serves all four; `/api/emulator/genesis` and `/api/emulator/genesis/{name}` remain as aliases of the `genesis_plus_gx` routes. Automated tests use synthetic files with a replaced `OperatorCoreManifest`; the real cores are never in the repository, the image or the npm lockfile.
- **Saturn:** `yabause` plays like PlayStation: one GET of the optional `saturn_bios.bin` through the shared `loadOptionalBios(name, bytes, sizeError)` (512 KiB, `saturnBiosSizeError`; a 404 means Yabause's HLE BIOS), handed over as `EJS_externalFiles['/saturn_bios.bin']` (EmulatorJS 4.2.3 sets no `system_directory`, so RetroArch uses the content root, where Yabause looks for `saturn_bios.bin`, then `sega_101.bin`, then `mpr-17933.bin`), then the disc from `play-disc` with `discError`'s non-PSP wording. `contentFileName` renames a standalone image named after any of those three files. Yabause's `core.json` lists `cue` but not `bin`, so EmulatorJS picks the cue from a set's ZIP and writes its own `MODE1/2352` cue for a lone `.bin`; `EJS_disableCue` stays unset. It sets `EJS_controlScheme = 'segaSaturn'` and hides the core chooser. `canPlay` and the games list's `playRomId` refuse any `.nrg` release, whatever the system.
- **`disc` flag and Sega CD:** `play.js` loads from `play-disc` when the core is `pcsx_rearmed`, `ppsspp` or `yabause`, or when `params.disc` is true; the SPA's `playUrl(gameId, rom, core, disc)` appends `&disc=1` for any external release (the game page from `rom.externalFileName`, the Library quick play from the list item's `playDisc`). Genesis Plus GX serves Mega Drive cartridges (no `disc`, ROM from `/download`, unchanged) and Sega CD discs (`disc=1`). The Sega CD path runs the operator-core HEAD check, then GETs `bios_CD_U.bin`, `bios_CD_E.bin` and `bios_CD_J.bin` one after another through `loadOptionalBios` (128 KiB each, `segaCdBiosSizeError(name)`): a 404 skips a file, a wrong size or any other failure stops the launch at that file, and no file at all stops it with `segaCdBiosMissing` before the disc is requested. Every BIOS found goes into `EJS_externalFiles` at `/<name>` (EmulatorJS 4.2.3 sets no `system_directory`, so Genesis Plus GX looks next to the content); the disc then loads from `play-disc` with `discError`'s non-PSP wording, and the page sets `EJS_paths`, the `segaMD` scheme and `EJS_disableCue = false` (the pinned loader otherwise skips cue generation for the Sega cores, and a lone `.bin` would boot as a cartridge). `contentFileName` renames a content file named after any of the three BIOS files (any case) to `<game id>-<name>` for `genesis_plus_gx`, with or without `disc`.
- **3DO (`opera`):** like `yabause`, `opera` always loads from `play-disc`, with or without `disc`. After the operator-core HEAD check it GETs `panafz10.bin`, `panafz1.bin`, `panafz1j.bin`, `goldstar.bin` and `sanyotry.bin` one after another (`threeDoBios`) through `loadOptionalBios` (1 MiB each, `threeDoBiosSizeError(name)`): a 404 skips a file, a wrong size or any other failure stops the launch at that file, and none at all stops it with `threeDoBiosMissing` before the disc. Every BIOS found goes into `EJS_externalFiles` at `/<name>`: Opera reads its BIOS from the system directory, which RetroArch resolves to the content root when EmulatorJS sets none. No Opera core option is set: `opera_bios` has no default, so Opera boots the first BIOS present in its own order (`panafz1`, `panafz1j`, `panafz10`, `goldstar`, `sanyotry`). `EJS_disableCue` stays unset (upstream keeps cue generation on for `opera`). `contentFileName` renames a content file named after any of the five BIOS files (any case) to `<game id>-<name>`. **Saves:** Opera never exposes its NVRAM as SRAM (`retro_get_memory_data(RETRO_MEMORY_SAVE_RAM)` is NULL); it writes `/data/saves/opera/per_game/<content name>.0.srm` itself, only in `retro_reset` and `retro_unload_game`. So `play.js` shows EmulatorJS's Exit for `opera` (its `exit` event resets the core, and IDBFS's `autoPersist` saves the closed file) and listens for `{ type: 'rnrm-emulator-close' }` from `window.parent` (same origin, exactly that object): it calls `EJS_emulator.gameManager.restart()`, waits 250 ms, runs `FS.syncfs(false, …)` and then posts `{ type: 'rnrm-emulator-closed' }` back; before the game starts it replies at once, and a second request during a save shares the one reply. `EmulatorModal` sends the request from `ConfirmModal`'s `beforeclose` and closes on the reply or after 3 s. - **Library saves (Saves B17–B19):** `parsePlayParams` also takes `save` (32 lowercase hex) with `saveKind` (`state`|`battery`), both or neither; `playUrl(gameId, rom, core, disc, save)` adds them. With a save, `play.js` GETs `/api/games/{id}/saves/{saveId}/download` after the ROM and before the loader, and sets `EJS_onGameStart` (loader.js runs it once, at the end of `startGame()`; `restart()` doesn't). The handler applies the save once, 10 ms later as EmulatorJS's own start state is: a state through `gameManager.loadState` (or a message when `!supportsStates()`), a battery save as EmulatorJS's import does (missing folders created, the old file unlinked, the new one written, `loadSaveFiles()`), then `restart()` and `FS.syncfs(false)`. The page's one `message` listener (every `play.html` core) takes only `{type: 'rnrm-emulator-close'}` (acted on for `opera`) or `{type: 'rnrm-emulator-export', kind}` from `window.parent` at `location.origin`, and answers an export with `{type: 'rnrm-emulator-export-result', kind, ok: true, bytes, extension}` (a transferred `ArrayBuffer`: `getState()` with `.state`, or `getSaveFile()` with the save path's extension, `.srm` when it has none) or `{…, ok: false, reason}` (`not-started`, `busy` while the 3DO close sync runs, `unsupported`, `empty`, `error`). `EmulatorModal` checks the size (≤ 256 MiB) and uploads through `POST /api/games/{id}/saves`.
- **Battery saves (release editing B22–B24):** for a core with a battery export, `EmulatorModal` looks up the user's newest battery save of the release (`savesApi.list`, once per opening) before rendering the iframe, and passes `storeBeforeClose` as `ConfirmModal`'s `beforeclose`: it waits for a running **Save … to library**, asks the player for the battery save with a 5 s timeout (`requestExport(target, kind, timeoutMs)`; a timeout resolves `timeout`), then replaces the played save when it is the user's own battery save, else stores like the manual button. Opera keeps `saveBeforeClose`. Screenshots are trimmed by `trimScreenshot` (decode with `createImageBitmap`, `trimBounds` on the pixels, re-encode with `canvas.toBlob`); a decode or encode failure keeps the original.
- **Local PSP development:** the Vite dev server doesn't send the isolation headers, so the PSP tab isn't cross-origin isolated there. Use the built API host on loopback instead: build the image (`pwsh scripts/build-docker.ps1`), run it with its port mapped to `127.0.0.1` (as the e2e stack does on `http://127.0.0.1:18080`), and open it on that loopback address; it serves `play-psp.html` with COOP/COEP.
- **`/emulator` CSP:** paths under `/emulator` get their own policy (`SecurityHeaders.EmulatorPolicy`): `'unsafe-eval'` (the 7z worker that unpacks each core builds its `cwrap` wrapper with `eval`), `'wasm-unsafe-eval'`, `blob:` scripts and workers, and `frame-ancestors 'self'`. `/emulator/play-psp.html` alone gets `SecurityHeaders.PspEmulatorPolicy` (the same with `frame-ancestors 'none'`) plus `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`; the modal page, the SPA and every asset stay non-isolated. Every other path keeps the strict policy with `frame-ancestors 'none'`. EmulatorJS's update check to `cdn.emulatorjs.org` is blocked on purpose (console noise only).
- **Static files:** `.data` is served as `application/octet-stream`, and an unknown `/emulator/*` path is a plain 404, never the SPA: paths with an extension already miss the `{*path:nonfile}` fallback, and `/emulator/{**rest:nonfile}` covers extensionless ones (keep `:nonfile`, or the route would shadow every vendored file).
- **Adding a core:** a handler opts in with `ISystemHandler.BrowserCore` ([adding a system](adding-a-system.md)); `params.js`'s core list (and `biosFor` if it needs a BIOS), the vendor script and `licenses.json` need the new core too. A core that needs threads must run on the isolated PSP-style page, and a release stored outside the ZIP needs its core in `LibraryEndpoints.ExternalBrowserCores` and `emulator.ts`'s `externalBrowserCores` plus a `play-disc` entry in `PlayDisc.SupportedSystems`. A core the operator must supply (one whose licence forbids bundling it) goes in `OperatorCoreManifest` and `params.js`'s `operatorCores` instead of the vendor script ([adding a system](adding-a-system.md#operator-supplied-cores)).

## Reports and curation helpers

Reports live under `routes/reports/`: Newly Added (`ReportRepository.ListNewlyAddedGamesAsync`, `ROW_NUMBER() OVER (PARTITION BY system_id …)`, grouped and ordered by system name in the endpoint), Library Size (`?system=` drill-down), Missing Images, Duplicates, Games With Hacks (`ListHackedGamesAsync`, a copy of Multiple Releases' paging and sort over `JSON_CONTAINS(r.flags, '"Hack"')`), Multiple Releases (`?system=` filters the list and `maxReleases`; server-side sort and paging, `?min=&sort=&dir=&page=` URL state; the sort key maps from `MultipleReleaseSort`, never from query text), Missing Metadata (filters, sort and page as URL state under the API's names; `MissingMetadataField`/`MissingMetadataSort` build the SQL, never query text) and Activity, backed by `Core/Reports`, `ReportRepository` and `/api/reports`. **Activity** and **Missing Metadata** are Admin-only twice over: their routes (`/activity`, `/missing-metadata` and `/missing-metadata/next`) add `.RequireAuthorization(AuthSetup.AdminOnly)` (the `/reports` group itself only needs a signed-in user), and `reports/+layout.svelte` hides their tabs for Site users and renders only `NotAllowed` on their routes (one `<h1>`). The endpoint combines `IReportRepository.ListRecentlyAddedRomsAsync` (`RecentRom`, the release size as `CAST(SUM … AS SIGNED)` since `SUM` is `DECIMAL`), `IUserRepository.GetLastSignInAsync` (`LastSignIn`) and five `IAuditRepository.ListRecentAsync(actions, 20)` calls, marking DB times UTC. The page loads it, `/api/jobs?pageSize=10` and `/api/admin/backups` in parallel, each with its own Loading/ErrorAlert; a deleted game's name falls back to the file name of the row's `path` on the client. `src/lib/treemap.ts` is a dependency-free squarified layout with proportional area and no overlaps; the system view caps graphics at 300 games plus others, while the table remains complete. `systemColours.ts` supplies both tiles and SystemBadge. The SVG has a labelled `group` role: `img` containing clickable links fails axe nested-interactive. Tiles are pointer shortcuts with aria-hidden and negative tabindex; the table supplies keyboard/screen-reader links.

`JsonTree` uses native details/summary, open at depths 0 and 1, with expand/collapse controls, a named root and padded summary touch targets. Its root takes an optional `actions` snippet (right end of the Expand/Collapse row) and `paneClass`/`paneStyle` for a wrapper around the tree only, which `InfoJsonModal` uses for the scrolling pane. `InfoJsonModal` calls `api.getText`, preserving invalid JSON as raw text. `/api/games/{id}/info-json` uses `LibraryFiles.ReadEntry` to buffer and limit bytes before sending a 200.

`googleSearch.ts` owns explicit-click Google query construction. `review.ts` shares the delete request and error handling between confirmation and Shift+click paths; archive entries always confirm. `reviewFilter.ts` parses, serializes and saves review filters under `rnrm.review.filter`. Review's bare URL restores its saved filter; explicit URL values win. The game's load effect keys only on id and keeps both panels mounted.

## Backups, notes and hotkeys

- **Migrations** 0015 adds `app_settings` (`name` PK, `value`; runtime settings, missing row = default) and 0016 adds `users.hotkeys` (JSON overrides, `NULL` = defaults).
- **Backups:** `Core/Backups` holds `BackupService` (create with its own lock, temp file + rename, ` (2)` names, retention, the in-memory last result, settings and the change signal), `BackupRestorer` (the startup restore rules), `BackupCheck` (the bare-name rule and the pre-drop checks both restores share) and `BackupSettings`; `Data/MySqlBackupStore` dumps every base table inside `START TRANSACTION WITH CONSISTENT SNAPSHOT` and restores with `FOREIGN_KEY_CHECKS = 0` and multi-row inserts of at most 500 rows or 4 MiB of dumped JSON (whichever comes first, so tables of 512 KiB publisher logos stay under MariaDB's 16 MiB `max_allowed_packet`), converting values back by each column's type. `Api/BackupScheduler` waits on `ScheduleCalculator.NextDaily` with the injected `TimeProvider` and wakes when settings are saved. `StartupRunner` calls the restorer between the database wait and the migrations. The Api tests' stub settings turn scheduled backups off, so stub-database tests never connect to MariaDB.
- **Live restore:** `BackupService.RestoreAsync` checks the name, takes the job lock and its own backup lock, opens and checks the file (`BackupCheck`), then opens the maintenance window through `Core/Backups/IMaintenanceWindow`. The Api's `MaintenanceGate` implements it: its middleware runs right after the security headers (before static files and auth, since cookie validation reads `users`) and answers every `/api` and `/health/ready` request but the owning one (its `HttpContext`, from `IHttpContextAccessor`) with `503 Maintenance`; it counts in-flight `/api` requests, except endpoints carrying `MaintenanceExempt` (downloads, play-disc, the bundle file, the log stream), and waits up to 10 s for them; it also holds `AuditWriter` (`HoldAsync` flushes then stops inserting, `Release` resumes). The service then writes the safety backup through its private `RunAsync` (keeping the source out of retention) and, from the drop on with `CancellationToken.None`, restores, migrates, aborts stale Running jobs, rotates every security stamp (`IUserRepository.RotateAllSecurityStampsAsync`), calls `IDiscoveryRepository.Invalidate()`, wakes both schedulers and records `BackupRestored`. The endpoint signs the caller out like logout.
- **ROM storage setting:** `Core/Storage/RomStorageSettings` (`IRomStorageSettings`) holds `storage.embedRoms.<id>` from `app_settings` for the `RomStorageConfigurable` systems only; `StartupRunner` loads it after migrations, `BackupService.RestoreAsync` after a restore, and `ApiFactory.ResetAsync` in tests. Only the storage job (`StorageMigrationJob.Change`, under the job lock) writes it, so `EmbedRomsInZip` never changes while another job or edit runs. Path-safety (G4) checks use `RomStorage.MayHoldExternalFiles` and so never depend on it; `RomStorage.IsEmbedded`/`IsPending` decide per game. It also holds every registered system's `storage.zipCompression.<id>` (`Compression(id)`, `Med` when unset or not exactly `Store`/`Med`/`High`), which every `new LibraryZipWriter(reader, level)` takes for the game's own system; only `ZipRepackJob` (started through `ZipRepackJobFactory` by `PUT /api/admin/zip-compression/{id}` and `POST …/repack`, under the job lock) writes it with `SetCompressionAsync`, then rewrites each of the system's ZIPs through `WriteCheckedAsync` and mirrors it.
- **DAT schedule:** `Core/Dats/DatRefreshSettings` and `DatRefreshSettingsService` (load, save, `SettingsChanged`, `NotifySettingsChanged()`) follow the backup settings; `DatRefreshJobFactory` builds the `DatRefreshJob` for the manual route and the schedule. `Api/DatRefreshScheduler` waits on `ScheduleCalculator.NextDaily`, starts the job with trigger `Schedule` and no user, and retries a busy lock every minute until the next day's due time. It's registered with `AddHostedService<DatRefreshScheduler>()`, so `ApiFactory` removes it unless a test sets `RunDatRefreshScheduler`.
- **Library folders:** `StorageFolders.EnsureSystemFolders` creates only the ingest tree; writers create `roms/<system>/<letter>` when they write. `StorageFolders.RemoveEmptyLibraryFolders` (called by `StartupRunner` right after crash recovery) removes empty bucket folders and then empty system folders, classifying each with `ExternalRomPath.ClassifyDirectory` so it never deletes through a link.
- **Notes:** `LibraryZipWriter` copies `notes/<listed rom>.md` on every write and takes `RemovedEntries`; `LibraryEditor` carries notes on move and merge and saves/deletes them under the job lock through the normal write + mirror path (so `zip_size_bytes`/`zip_mtime_utc` stay in sync without touching `updatedAt`).
- **Hotkeys:** `Core/Users/Hotkeys.cs` holds the action table and rules; the SPA mirror is `src/lib/hotkeys.ts`. Adding an action means a row in both tables, a case in the store's `run`, and docs in [features](features.md#keyboard-shortcuts).

## File action auditing

Migration 0014 adds `audit_events`: auto-increment id, occurred_at, action, optional system/game/user/username/job, path, target_path and details. Time, action/time, system/time and user/time indexes support the newest-first queries; no foreign keys preserve history after deletion. Text is truncated to its column length on insert. `IAuditRepository.ListAsync` applies validated filters before count and paging. `AuditItem` is a positional record that Dapper maps by constructor, so every query selecting it (`ListAsync`, `ListRecentAsync`) selects `GameTitle` as its last column, from `LEFT JOIN games g` (`g.display_title`), with the audit table aliased `a` because both tables have `id` and `system_id`. `/api/admin/audit` and its `/actions` endpoint require Admin; `/admin/audit` keeps filters and page in its URL and converts local date boundaries to UTC instants.

`IAuditLog.Record` stamps an event with injected TimeProvider and synchronously TryWrites a bounded 10,000-event channel. It never blocks or throws; full queues or internal failures warn and drop. `AuditWriter` inserts in the background, logging/dropping failed inserts and continuing. It is registered before JobShutdownService so reverse shutdown order finishes jobs before draining the log (best effort within the host timeout). Tests await `AuditWriter.FlushAsync` before reading rows. `AuditLog.Retention` is 30 days; Scheduler purges at startup and with the 00:05 UTC log purge, independently catching audit failures.

Build `AuditActor` once per request from claims or once per job from the requester lookup (a failed/missing lookup warns, keeps the user id and starts with a null username); pass it through file-changing services. Record immediately after a successful file change, including when the subsequent DB mirror fails. Keep each action's single writer; no-op metadata/cover changes, ratings, integrity and temporary cleanup are excluded. Account events are recorded too: `UserAdminService` records the Admin's user operations and `AccountService` sign-ins, failed sign-ins, lockouts and password changes, through the same `IAuditLog`. The `--reset-password` CLI host never starts `AuditWriter`, so `ResetPasswordCommand` inserts its `PasswordReset` row synchronously through `IAuditRepository.InsertAsync` (stamped from the injected `TimeProvider`) after printing the password, and only warns on stderr if that fails. Tests that read every `audit_events` row exclude the sign-in events their own logins write. Review resolves/dismissals use the pipeline's row, not an extra review row. `AuditPaths` turns absolute paths under configured roots into `roms/` or `ingest/`; archive sources use archive + entry instead of cache/work, and outside-root paths use filename only. Stored relative ZIP paths use `AuditPaths.Library`.

**Browser plays** are the one read that's audited: `POST /api/games/{id}/roms/{romId}/played` records `GamePlayed` (the game's ZIP path, the release file name as details) for the Activity report. It takes no job lock and isn't `MaintenanceExempt`. The SPA calls it through one helper in `src/lib/emulator.ts`, fire-and-forget with `noRedirect` (a `401` mid-play mustn't navigate): `EmulatorModal` on each false→true change of `open` (mounting open counts) while `open && rom && core && gameId`, never on prop changes while open, and every PSP `target="_blank"` link on `click` and middle-button `auxclick`. The missing-core e2e checks skip URLs ending in `/played`, since the POST can land after the core `HEAD`.

## Collections discovery

The Publishers and Genres tabs on `/collections` (spec `2026-11-15-collections-discovery`) group games by each entry of `games.publishers` / `games.genres`, with no index or mirror table.

- **Normalization lives in MariaDB only.** `Data/Repositories/DiscoverySql` holds the one expression every read uses: `JSON_TABLE … FOR ORDINALITY` only numbers the entries and each full value is extracted by ordinal (no column width can cut it); string entries only; `REGEXP_REPLACE` trims `\s` and `\p{Z}`; blanks are dropped; `LOWER(… COLLATE utf8mb4_uca1400_as_cs)` (named, since the JSON columns are `utf8mb4_bin`) cast to binary is the normalized name; `SHA2(…, 256)` is the public key. The app never trims, lowercases or hashes names, it only compares the bytes MariaDB returns.
- **Cached index.** A live scan took 0.7–1.5 s at 50,000 games (`DiscoveryRepositoryTests.Budget_50000Games_PagesUnder500Milliseconds`, `Explicit`), so `DiscoveryRepository` (a singleton) builds each kind's index in one pass (every entry's key, normalized bytes, trimmed bytes and game id, plus the game order by display title, system and id, in one snapshot) and reuses it for `IDiscoveryRepository.IndexLifetime` (60 s). Concurrent callers share one build; a caller's cancellation doesn't cancel it; a failed build isn't kept. Groups sort by normalized bytes and are labelled with the binary-smallest trimmed spelling, cut to 255 code points. A group's game page takes its slice of ids and reuses the library list's projection through `GameQuery.GameIds`. API tests that share a host register their own `DiscoveryRepository` with a `FakeTimeProvider` and advance it past the lifetime in `SetUp`, so no index outlives a database reset.
- **Logos.** Migration 0021 added `publisher_logos`; migration 0026 renames it `discovery_logos` and adds `kind` (`publishers`, `genres`, `systems`) to the primary key (`kind`, `key_digest BINARY(32)`), with `media_type`, `bytes MEDIUMBLOB`, `updated_by` → `users` `ON DELETE SET NULL` and `updated_at`, so backups carry the bytes. Systems are keyed by `DiscoveryKey.ForSystem` (SHA-256 of the lowercase id). `Api/Endpoints/DiscoveryLogoEndpoints` serves `/api/discovery/{kind}/logo`: the file upload buffers at most 576 KiB of the body before reading the form (413 for fixed-length and chunked bodies alike, under Kestrel and TestServer); `from-url` downloads through `ImageUrlDownloader`; both pass the same `CheckLogo` (PNG/JPEG by content, 512 KiB, 2048 px), check that the group or system exists, upsert in one statement and record the kind's `…LogoReplaced` / `…LogoRemoved`. Group lists and `/api/systems` carry `logoUrl` with `v=<updated_at ticks>`.
- **Search.** `ListGroupsAsync(kind, page, pageSize, q, cancellationToken)` filters the cached index by label (ordinal ignore-case contains) before paging; it's a display filter, so grouping and keys never change. `DiscoveryEndpoints` trims `q` and refuses over 100 characters. The Systems list filters on the client. In the SPA the search box lives in `SystemList` and `DiscoveryGroups` (`find` prop, `onfind` callback, 300 ms debounce cancelled on unmount and on a `kind` change), outside the list's loading branch so it keeps focus.
- **SPA.** `src/lib/discovery.ts` owns the tab URL state (`tab`, `key`, `groupPage`, `gamePage`, and `find`, the search, since `q` is taken by User collections: optional, trimmed and capped at 100 characters by the parsers, kept by `discoverySearch`/`systemsSearch`, dropped by `tabSearch`, written with `replace`; `discoveryApi.groups` sends it as `q` only when non-empty), the API calls (`logoApi`), the starter catalogs and `logoSources`' fallback order (shared logo, starter art; then `GroupLogo`'s text banner; a source that fails to load falls through). `DiscoveryGroups`, `DiscoveryGames`, `SystemList`, `SystemGames`, `GroupLogo` and `LogoModal` are the components.
- **Starter art.** `static/genres/` holds one SVG tile per starter genre (a Bootstrap Icons glyph plus the name) with `manifest.json` naming each glyph and its licence, listed in `starterGenres`. `static/publishers/` holds one SVG name tile per starter publisher and `manifest.json` with each file's source and license; every file needs an entry. The catalog's keys are precomputed (`crypto.subtle` is missing over plain HTTP on a LAN); `discovery.test.ts` recomputes each from its alias and checks the manifest and that no SVG references anything external. To add a publisher or alias, add the asset and manifest entry, then a catalog row with `sha256(<lowercase ASCII alias>)`. Only add a publisher's own logo when its redistribution terms are verified, and record them in the manifest.

## Bundle Creator

The cart, saved queues and sequential downloads (spec `2026-11-15-rom-bundles`).

- **Stable identities.** Numeric release and file ids change on every mirror rewrite, so entries store `Core/Bundles/BundleFile`'s identity (game GUID, release SHA-1, optional set-file SHA-1 + stored name; `BundleFile.Key` and the SPA's `entryKey` must agree). `LibraryRepositories.ResolveBundleFilesAsync` resolves a batch to the current ids in one bounded lookup; anything not resolving to exactly one file is unavailable, never a substitute.
- **Queues.** Migration 0022 adds `bundle_queues` (GUID id, `user_id` → `users` `ON DELETE CASCADE`, name in `utf8mb4_uca1400_as_ci` unique per user, `revision`, `item_count`, the validated entries as relaxed-escaped JSON in `MEDIUMTEXT`). `BundleQueueRepository` locks the owner's `users` row (`SELECT … FOR UPDATE`) before a create's name and cap checks; replace and delete are conditional on owner and revision. Limits are in `BundleQueueLimits`, validation in `BundleQueueValidation`; the SPA mirrors them in `src/lib/bundles.ts` and `stores/bundle.svelte.ts`.
- **Downloads.** `Api/Endpoints/LibraryDownload` is the shared opener of the normal release and set-file routes and of bundle downloads: it returns a `LibraryAttachment` that owns its stream (and the ZIP behind it) with the expected length and canonical file name. `Core/Bundles/BundleDownloadTickets` (a singleton with the injected `TimeProvider`) keeps tickets in memory: one pending or sending ticket per user, 100 globally, 30 s pending lifetime, terminal states for 5 min / 2,000 records, oldest evicted first. `BundleDownloadEndpoints` claims a ticket once, re-resolves the identity, copies with a two-minute read/write inactivity timeout and marks `sent` only after writing the expected length and completing the response; any cancellation or I/O error aborts the response, disposes the stream and marks `failed` before the slot is released. The single-instance deployment is assumed; a restart loses tickets.
- **SPA.** `stores/bundle.svelte.ts` is the cart (`localStorage` key `rnrm.bundle.cart.<userId>`, followed from `auth.me` in the root layout; a generation counter drops stale refresh answers). `SavedBundleQueues.svelte` uses `bundleQueuesApi`. `src/lib/bundleDownload.ts`'s `BundleDownloadRun` drives a run through injectable `DownloadDeps` (issue, status, click, wait), so `bundleDownload.test.ts` fakes the server and the 500 ms polling; `clickDownload` clicks a hidden same-origin `download` link. Its requests use `noRedirect`, so a 401 pauses the run instead of leaving the page. `BundleDownload.svelte` ends the run on destroy and when `bundle.userId` changes.
