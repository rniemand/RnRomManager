# Game collections and wider global search

## Summary
Every signed-in user can make **game collections**: named, private groupings of library games from any system ("Pokemon", "My favourites"), each with an optional cover image and Markdown notes. Collections get a top-level **Collections** page, can be filled from the collection page, the game page and a bulk selection in the Library, and are found by the global search, which now also shows up to 10 games.

## Out of scope
- Sharing collections between users, or an Admin view of other users' collections.
- Collections of individual releases (ROM files): a collection holds games.
- Manual (drag) ordering inside a collection.
- Storing collections in library ZIPs / `info.json`: they're database-only and not rebuilt from the library.
- Including cover image files in database backups (documented as a limitation).
- Auditing collection changes (audit is for library/ingest file actions).
- A cap on collections per user, and purging memberships of deleted games (see B17).

## Behaviour

### Collections
- **B1 Ownership.** A collection belongs to the user who created it. Every collection endpoint acts only on the caller's own collections; another user's collection id answers `404` exactly like a missing one. Any signed-in user (no role needed) may use every collection feature, including cover upload and cover-from-URL; `mustChangePassword` users are blocked by the existing guard.
- **B2 Fields.** `name` (required, trimmed, 1–100 characters, unique per user **case-insensitively but accent-sensitively**: column collation `utf8mb4_uca1400_as_ci`, as `games.zip_path`, so "Pokemon" and "Pokémon" can coexist but "pokemon" clashes), `notes` (optional Markdown, line endings normalised to `\n`, whitespace-only → `null`, at most 65,536 UTF-8 bytes; same rules as release notes, `LibraryEndpoints.ParseNote`), a cover image (optional), `createdAt`, `updatedAt`. No limit on the number of collections per user or games per collection.
- **B3 Errors.** Empty/too-long name or too-long notes → `400` validation (`name` / `notes`). Duplicate name for the same user → `409 CollectionNameTaken` ("You already have a collection with this name."). Unknown or foreign id → `404`.
- **B4 Create / edit.** `POST /api/collections {name, notes?}` → `201` with the detail. `PATCH /api/collections/{id} {name?, notes?}` → `200` with the detail; an absent field is unchanged, `notes: null` or `""` clears it.
- **B4a `updatedAt`.** Set only when an owner's request actually changes stored data: create, a PATCH, cover set/remove, an add with `added > 0`, a remove that deleted a row. Not touched by no-op requests or by B18 moves.
- **B5 Delete.** `DELETE /api/collections/{id}` → `204`: hard-deletes the row and its memberships (FK cascade), then deletes its cover file(s) (a failed file delete is logged as a warning, not an error). Games are never touched.
- **B6 List.** `GET /api/collections?q=&page=&pageSize=` → the caller's collections as the standard page DTO, sorted by name (ascending, then id): `id, name, gameCount, coverUrl|null, updatedAt`. `q` (≤ 255 chars, ≤ 8 words, as `/api/games`) matches when every word appears in the name (case/accent-insensitive via `name COLLATE utf8mb4_unicode_ci LIKE @w{i}`, the override `GameRepository.JsonLike` uses; `%`/`_` literal, via `SqlLike`). `pageSize` 1–200, default the shared page default. `gameCount` counts only games that still exist.
- **B7 Detail.** `GET /api/collections/{id}` → `id, name, notes, coverUrl|null, gameCount, createdAt, updatedAt`.

### Cover image
- **B8 Upload.** `POST /api/collections/{id}/cover` (multipart `file`, PNG/JPEG checked with `ImageFormats.Read` as the game image editor does, so unreadable dimensions → `400` `file` "The image's dimensions can't be read.", ≤ 8 MiB, the same `413 PayloadTooLarge` and request-size handling as game image upload; the file-reading part of `ReadUploadAsync` is extracted and shared, without its `type` field) → `200` detail. Replaces any existing cover.
- **B9 From URL.** `POST /api/collections/{id}/cover/from-url {url}`: the `url` rule of the existing game from-url validation (≤ 1024 chars, absolute http(s), no user info; extracted into a shared helper, no `type` field) and the downloaded-bytes check (≤ 8 MiB, PNG/JPEG) are shared with `/api/games/{id}/images/from-url`; it downloads through `ImageUrlDownloader` with the same error codes, then stores it like an upload. Open to plain users on purpose (Decisions).
- **B10 Storage.** Covers live in the new `Paths:Collections` folder (default `/app/collections`) as `<collectionId>.png` or `<collectionId>.jpg`. Order: write a uniquely named temp file (`<collectionId>.<guid>.tmp`) in the same folder → rename over `<collectionId>.<ext>` → update the row (`cover_format` `png`/`jpg`, `cover_updated_at`) → delete the other format's file if present. If the row update fails and the new format differs from the row's current `cover_format` (or there was none), the new file is deleted again (best effort); with the same format the file is kept, since the row still points at it.
- **B11 Serve / remove.** `GET /api/collections/{id}/cover` streams the file named by `cover_format` with its content type and `Cache-Control: private, max-age=86400`; `coverUrl` is `/api/collections/{id}/cover?v=<cover_updated_at ticks>`. No cover, or the file is missing (e.g. after a DB restore) → `404`, and the UI shows a placeholder icon. `DELETE /api/collections/{id}/cover` → `200` detail, clears the columns, then deletes both possible files.
- **B12** Collection writes don't take the job lock: they never touch library ZIPs.

### Membership
- **B13 Add.** `POST /api/collections/{id}/games {gameIds: [guid…]}` (1–500 ids, else `400` `gameIds`) adds games idempotently; ids that aren't (or are no longer) library games are skipped. → `200 {added: <newly added count>}`.
- **B14 Remove.** `DELETE /api/collections/{id}/games/{gameId}` → `204`; removing a game that isn't in the collection is also `204`.
- **B15 Games in a collection.** `GET /api/games?collection=<id>` adds a collection filter to the existing library list (all other filters, search, sorts and paging still apply). `collection` is parsed as a string in `ParseQuery`: not a GUID → `400` field `collection`; well-formed but unknown/foreign → `404`. With `collection`, `sort=added` orders by when the game was added to the collection (default `desc`), not when it entered the library.
- **B16 A game's collections.** `GET /api/games/{id}/collections` → the caller's collections containing that game, `[{id, name}]` sorted by name. Unknown game → `404`.
- **B17 Stable across edits.** Memberships reference `game_id` without a foreign key, because the library mirror deletes and re-inserts a game's row on every edit (`LibraryRepositories.ApplyAsync`). Queries inner-join `games`, so a missing game simply doesn't show, and reappears if the same game id comes back (e.g. a library volume that was briefly unmounted). Orphan rows are never purged: they're tiny and purging would turn a temporary loss into a permanent one.
- **B18 Merge and move.** When `LibraryEditor.MergeAsync` succeeds, or `MoveReleaseAsync` deletes the source game because its last release moved away (to an existing game or a new one created by the move), the source game's memberships move to the target (the new game's id in the latter case). Where a collection already holds the target, one entry stays with the earlier `added_at`. A failure here is logged as an error and doesn't change the edit's result (the library change has already committed).

- **B19** (unused: numbering kept stable.)

Filter and page live in the URL (`?q=&page=`), updated with `goto(url, { replace: true, reset: false })`. Clicking a card opens the collection.
- **B23 Collection form** (`CollectionModal`, a `ConfirmModal size="lg"`): name, notes (View/Edit/Preview + byte counter like `ReleaseNoteModal`, rendered only through `src/lib/markdown.ts`), cover (choose a file, or a URL). **Create:** Save posts name + notes, then, if a cover was chosen, uploads it; then navigates to the new collection's page. Field errors from the API show inline; `409 CollectionNameTaken` shows on the name field.
- **B24 Collection page** (`/collections/[id]`): header with cover, name, rendered notes, **Edit** and **Delete** (a `ConfirmModal` naming the collection and saying games aren't affected; on success → `/collections` with a toast). Below, the collection's games with the Library's grid/list view, search box, system filter, Favourites toggle, sort (title, year, added-to-collection, rating; default added-to-collection desc) and paging; filters, sort and page are kept in the URL through `libraryQuery.ts` (without letter and region; `favourite` kept), so Back from a game returns to the same view. Each game has a **Remove from collection** icon button (`aria-label`). An **Add games** typeahead searches all systems (`GameTypeahead` with `system` made optional, showing a `SystemBadge` when no system is set) and adds the picked game: toast "Added <title>" when `added` is 1, "Already in this collection" when 0, then the list refreshes (members aren't excluded from the typeahead). An unknown or foreign collection id (`404`) shows the same not-found state as the game page.

Under the title, badges link to each collection containing the game (from B16); none → no badge row.
- **B26 Library bulk add.** A **Select** toggle in the Library toolbar shows a checkbox on each card/row and a **Select all on this page** control; the selection is cleared when the page, filters or sort change or Select is turned off. **Add to collection…** (enabled with ≥ 1 selected) opens `CollectionPickerModal` (same filter + first-200 list and `/collections` link as B25, single choice); on success a toast says "Added N games to <name>" (N = `added`) and the selection clears.
- **B27 Global search.** Results show two groups in one combobox list: **Collections** (up to 5, from `/api/collections?q=…&pageSize=5`, cover thumbnail + name + game count) then **Games** (up to 10; `pageSize` 5 → 10). Arrow keys move across both groups; Enter opens the collection or game. Both requests start after the same debounce and minimum length; one failing shows the error but keeps the other group's results. No matches in either → the existing "no results" text.

## Risks
- **Mirror delete/re-insert would wipe memberships** if `collection_games` had an FK with cascade to `games`. Handled by B17 (no FK, inner joins, no purge). Test: re-applying a game keeps its memberships.
- **Restore without covers:** restoring a DB backup restores collections but not cover files → covers 404 and show the placeholder (B11). Documented in deployment.md.
- **Leftover files:** a crash between temp write and rename leaves a `*.tmp`; a restore can leave cover files with no row; two concurrent uploads in different formats can briefly leave both formats (the row decides which is served; the next upload/remove/delete clears both). Accepted: files are small and never served without a matching row.
- **Disk and outbound requests from plain users:** any signed-in user can store 8 MiB covers with no collection cap and make the server fetch public image URLs (through the same SSRF-safe `ImageUrlDownloader`). Accepted by the user (Decisions); users are created by Admins only.
- **Existing deployments** need the new volume mapped to keep covers across container recreation; without it, covers live in the anonymous volume. Called out in deployment docs; startup still works (folder is created).
- **Privacy:** every route checks ownership; covered by tests with two users.
- **Large collections:** listing is paged and `gameCount` uses the `(collection_id, game_id)` PK; bulk add caps at 500 ids per request.
