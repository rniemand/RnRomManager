# SG-1000 / SC-3000 system

## Summary
Adds Sega SG-1000 / SC-3000 as its own system (`sg1000`): `.sg` and `.sc` cartridges, matched against libretro's No-Intro `Sega - SG-1000` DAT, played in the browser with the bundled SMS Plus GX (`smsplus`). Master System stops taking `.sg`, and a one-off job moves the SG-1000 games already stored under Master System to the new system, renaming their releases to `.sg` so SMS Plus GX runs them in SG-1000 mode (today it runs them as Master System games, since they're stored as `.sms`).

## Out of scope
- SF-7000 disk images (`.sf`, three entries in the DAT): SMS Plus GX doesn't list `.sf`; the DAT's `.sf` entries are filtered out (DatStore keeps only `RomExtensions`).
- SC-3000 keyboard emulation: SMS Plus GX has none, so BASIC and keyboard-only titles boot but can't be used (S7).
- `.bin`/`.rom` aliases: the DAT lists only `.sg`; a `.bin` SG-1000 dump must be renamed `.sg` before ingest.
- Moving SG-1000 games stored under Master System that were dropped with another extension (`.sms`, `.bin`, `.rom`), or games that mix SG-1000 and Master System releases: they stay under `sms` (S10). No general "move a game to another system" action.
- Re-identifying moved games against the SG-1000 DAT (names, metadata, IGDB link stay as they were).
- A seeded SG-1000 game and new e2e flows (seed counts churn across `mvp.spec.ts`; ingest and play are covered by integration and vitest cases).

## Behaviour

### System
- **S1** `Sg1000Handler` (new, `RnRomManager.Systems.Sega`): `Id` `sg1000`, `DisplayName` `SG-1000 / SC-3000`, `ShortName` `SG-1000`, `Family` `sg1000`, `RomExtensions` `[".sg", ".sc"]`, `MinRomSizeBytes` 2,048, `MaxRomSizeBytes` 1,048,576 (DAT `.sg` sizes are 8–48 KiB; the margin covers homebrew and Taiwanese multicarts), `DatName` `Sega - SG-1000`, `EmbedRomsInZip` true, `KeepsSourceExtension` true (Review keeps `.sg`/`.sc`, so an SC-3000 cart stays `.sc`), default `DatSource`, `DatFolder` and `MetadatKinds` (libretro has all four SG-1000 metadat files, checked 2026-11-27), `BrowserCore` `smsplus`, box art `boxart.sg1000.png`, `ReadHeader` always null (no cartridge header, as `Atari2600Handler`), `NormalizeForHashing` unchanged.
- **S2** Ingest: drop `.sg`/`.sc` files (or `.zip`/`.7z` archives of them) into `ingest/sg1000/`. A DAT match is stored under the DAT's ROM name (`.sg`). With no header there's no `InvalidHeader`: an unmatched file always goes to Review (`NoDatMatch`, suggestions from the file name) and keeps its extension when resolved. Other families' extensions in `ingest/sg1000/` (e.g. `.sms`) and `.sg`/`.sc` in another system's folder fail `UnsupportedType` (S3).
- **S3** `MasterSystemHandler.RomExtensions` becomes `[".sms", ".bin", ".rom"]`. A `.sg` dropped into `ingest/sms/` now fails `UnsupportedType` (moved to `_failed/`), as a `.gba` in a GB folder does.
- **S4** Registration: `services.AddSystemHandler<Sg1000Handler>();` directly after the `MasterSystemHandler` line in `AppHost.AddSystemHandlers`, so registry order is `…, "gg", "sms", "sg1000", "md", …`. `GET /api/systems` (ordered by display name) lists `sg1000` between `segacd` and `sufami`. `ingest/sg1000/` is created at startup (`StorageFolders.EnsureSystemFolders`); `roms/sg1000/` appears with the first ZIP written there. Ingestion is refused with `DatsMissing` until **Admin → DATs → Refresh DATs** downloads the SG-1000 DAT and metadat; the move (S10–S15) doesn't need them.
- **S5** Catalogs: IGDB platform `["sg1000"] = 84` in `IgdbPlatforms` (after `["sms"] = 64`; step 2 confirms 84 on igdb.com's SG-1000 platform page before committing); `systemEmulators.json` `sg1000` entry, after `sms`: `[{ "name": "Emulicious", "url": "https://emulicious.net/", "os": ["windows", "macos", "linux"] }, { "name": "RetroArch", "url": "https://www.retroarch.com/?page=platforms", "os": ["windows", "macos", "linux", "android", "ios"], "note": "RetroArch core: Genesis Plus GX" }]`; system colour `--bs-sg1000: #343a40` with white text (`.text-bg-sg1000`, comment "SG-1000 system colour: dark grey, same in both themes; white on it is AA (~11.5:1).") in `app.css` after the `sms` block, and `sg1000: { name: 'sg1000', foreground: '#fff' }` after `sms` in `systemColours.ts`. ### Browser play
- **S7** `sg1000` plays with `smsplus` from the ZIP, no BIOS, core chooser hidden (already true for `smsplus`), default `segaMS` controls. SMS Plus GX runs content in SG-1000 mode only when the content path ends in lowercase `.sg` (`retro_load_game` in `source/ports/libretro/smsplus_libretro.c` at the vendored revision `c642bbd`: `strcmp(strrchr(info->path, '.'), ".sg") == 0` → `option.console = 5`); it doesn't list `.sc` and has no `.sc` case, so a `.sc` would run as a Master System game. Hence `contentFileName(core, game, name)` in `static/emulator/params.js`: for `smsplus`, a name ending in `.sg` or `.sc` (any case) has that extension replaced by `.sg` (after the existing `#` → `_` step); every other core and extension is unchanged. `EJS_gameName` stays the release name. SC-3000 titles that need the keyboard boot but can't be used.
- **S8** `BrowserCoreExtensionsTests`: `Exceptions` gains `[("sg1000", ".sc")] = "play.js names a .sc release .sg for smsplus, whose retro_load_game runs .sg content in SG-1000 mode (smsplus_libretro.c at c642bbd); keyboard titles don't work"`. `NotIngested`: `(NewSystem, ["picodrive"], [".sc", ".pco"])` becomes `(NewSystem, ["picodrive"], [".pco"])`, and `(OtherSystem, ["picodrive"], [...])` gains `".sc"` at its end. The `genesis_plus_gx` and `picodrive` `.sg` rows stay (`OtherSystem` is still the reason); `smsplus` `.sg` needs no entry (ingested by `sg1000`). `ProblemsAreNamed`'s expected list gains `"sg1000 .sc: stale exception (no such system)"` at the end.
- **S9** Play gating needs no change: `canPlay` and the API's quick play already allow every embedded release of a system with a `BrowserCore`.

### Moving existing SG-1000 games
- **S10** Candidates: games with `system_id` `sms` whose every ROM row has an `original_file_name` ending in `.sg` (case-insensitive; `roms` uses `utf8mb4_unicode_ci`). New `IGameRepository.ListByOriginalExtensionAsync(string systemId, string extension, CancellationToken)` returns their `GameRow`s ordered by `zip_path`, as `ListStorageMovesAsync` does (`WHERE g.system_id = @systemId AND EXISTS (roms of g) AND NOT EXISTS (SELECT 1 FROM roms r WHERE r.game_id = g.id AND r.original_file_name NOT LIKE CONCAT('%', @extension))`). It also requires `AND NOT EXISTS (SELECT 1 FROM roms r WHERE r.game_id = g.id AND r.id_method = 'Dat')` (`id_method` holds `IdentificationMethod.ToString()`): a release that matched the Master System DAT by hash is a real Master System game, whatever its file was called, and moving it would break it. A game with any other release (mixed, DAT-matched, or SG-1000 dumps dropped as `.sms`/`.bin`/`.rom`) is never a candidate, so it never starts the job.
- **S11** `LibraryEditor.MoveToSg1000Async(GameRow row, AuditActor actor, CancellationToken ct)` (new, **internal**: `Sg1000MoveJob` is in the same assembly and `RnRomManager.Core.Tests` has `InternalsVisibleTo`; implemented in `Sg1000Mover` (new, internal, built like `ReleaseEditor` through a `LibraryEditor.Sg1000Mover` property, with access to `LibraryEditSupport` and `ReleaseEditor`). It does **not** take the job lock: only `Sg1000MoveJob`, which holds it, calls it. Per game:
  1. `LibraryEditSupport.OpenForEdit(row)`. A missing ZIP at `row.ZipPath` (the file doesn't exist) returns `LibraryEditResult.NotSg1000` (new const `"NotSg1000"`), not an error: after a database-only restore (backups hold only the DB) the row may point at a ZIP this job already moved. Any other open failure returns its code as is (`TargetZipUnreadable`…).
  2. The ZIP's `info.json` `gameId` must equal `row.Id` (`OpenForWrite` checks it only for external systems, and a different game may now sit at the old path), `system` must still be `sms`, every release's `originalFileName` must end in `.sg` (ordinal ignore case) and no release's `identification.method` may be `Dat` (S10); otherwise it returns `NotSg1000`, writing nothing.
  3. Each release whose `fileName` doesn't end in `.sg` (ordinal ignore case) is renamed to its name without the extension plus `.sg`, made unique among the game's new names with `LibraryEditSupport.FreeName`. Each rename moves the ROM entry (`LibraryZip.RomEntry`), carries its note (`LibraryEditSupport.CarryNote`) and, when a save names the release, its saves (`LibraryEditSupport.CarrySaves(existing, null, LibraryEditSupport.Renames(...))` with every rename at once), exactly as `ReleaseEditor`'s release rename does; an unreadable saves index returns `SavesUnreadable` and writes nothing.
  4. The placeholder box art follows the system: the image with `IsDefault` true (the Master System placeholder `MediaService.Default` stored at ingest) is replaced by `MediaService.Default(sg1000Handler).ToInfoJson(now, isCover: old.IsCover)` (new bytes, size, SHA-1 and file name), its old `images/` entry removed and the new one added, as `ImageEditor`'s delete adds a placeholder. A game without a default image keeps its images.
  5. The new `info.json` is the current one with `System = "sg1000"`, the renamed releases, that image list and `Metadata = LibraryEditSupport.Touched(current)`; everything else (id, title, identification, headers, other images, notes, saves, rating, IGDB id) is kept.
  6. Target path: a leftover of an earlier interrupted move is reused first: every `*.zip` in `roms/sg1000/<Bucket.For(title + ".zip")>/` whose `info.json` reads (`InfoJsonReader`) with `gameId` equal to `row.Id` is the target (the first by ordinal name; a ZIP that can't be read is ignored). Otherwise `LibraryEditSupport.NewZipPath("sg1000", title)` (bucket and clash suffix as any new ZIP); an `IOException` or `UnauthorizedAccessException` from it returns `IoError` with the message, as `PatchAsync` does.
  7. Write, then mirror, separately: `LibraryEditSupport.WriteZipAsync(existing, newPath, game, entries, removed, saves)` (a write failure returns its code; the old ZIP and DB are untouched), then `LibraryEditSupport.MirrorAsync(() => mirror.ReplaceAsync(LibraryEditSupport.Mirror(newPath, game), CancellationToken.None), newPath)`, as `ImageEditor` does. If the mirror fails (`DbWriteFailed`), the new ZIP is deleted with `ReleaseEditor.UndoTargetWriteAsync(newPath, null)` (move it to `LibraryEditSupport` if `Sg1000Mover` can't reach it) and the code returned: the DB still says `sms` at the old path, which is untouched, so the next start retries cleanly. On success the DB rows move to `sg1000` with the same game id and rom ids (`LibraryMirror` keeps rom ids by SHA-1), so collections, favourites, ratings, bundle queues and save counts follow; the old ZIP is then deleted with `LibraryEditSupport.DeleteOldZip` (a failure there is logged; the leftover is a `DuplicateGameId` that integrity reports and an Admin deletes by hand, as after any title change).
  8. Only after a successful mirror it audits `AuditActions.GameUpdated` with system `sg1000`, the old and new library paths and details `Moved from Master System to SG-1000`; a failed or undone move audits nothing.
- **S12** `Sg1000MoveJob` (new, `RnRomManager.Core.Library`, `JobType.Sg1000Move` (new, appended after `IgdbSync`; `jobs.type` is `VARCHAR(16)`, 10 chars), `Mode` null), modelled on `SaveFoldersJob`: lists the candidates (S10), one job item per game (`FileId`/`GameId` the game id, `SystemId` `sms`, `SourcePath` the old library path) with outcome `Moved` (code null), `Skipped` (`NotSg1000`) or `Error` (any other code, or `Unexpected` with the exception message, logged); progress total = candidates, current item = ZIP path; cancel and shutdown stop between games, never inside one. Summary `{ moved, skipped, error }`. No `app_settings` flag.
- **S13** `Sg1000MoveStarter` (new, `RnRomManager.Api`, `BackgroundService`), as `StorageMigrationStarter`: after `ApplicationStarted`, if `ListByOriginalExtensionAsync("sms", ".sg")` is non-empty, starts the job (`JobTrigger.Startup`, through `Sg1000MoveJobFactory` (new delegate, as `SaveFoldersJobFactory`)); a busy lock or a failed check retries every 5 minutes (`RetryInterval`); a started run is never retried in that process. Log lines: `SG-1000 move job {JobId} started for {Count} game(s)`, `SG-1000 move waits: another job is running; trying again in {Interval}`, `SG-1000 move couldn't start; trying again in {Interval}`. Because there's no flag, every startup re-checks: a `.sg` Review item resolved under `sms` later is moved on the next start, and a game that errored is retried. After restoring a database backup from before the move, the `sms` rows point at ZIPs that are now under `roms/sg1000/`: the job reports them `Skipped` (S11.1) until an Admin runs **Integrity → Run quick**, which re-reads the library and drops those rows (the deployment note says so).
- **S14** Jobs UI: `jobs.ts` label `Sg1000Move: 'Moving Games to SG-1000'` (after `IgdbSync`), the `CurrentJob['type']` union gains `'Sg1000Move'`, cancellable (default). Outcome badges reuse `Moved`/`Skipped`/`Error`.
- **S15** Pending Review items for `.sg` files in `ingest/sms/`: see Open question Q1 (a `.sg` inside a pending archive may no longer be extracted once `sms` drops `.sg`). A loose one resolved under `sms` is stored as `.sms` and moved on the next start (S13).

## Risks
- **The move rewrites user data.** One ZIP at a time through the existing checked write; the old ZIP is deleted only after the new one is written and mirrored. A mirror failure deletes the new ZIP (S11.7). A crash after the write but before the mirror commits leaves a new ZIP with the same game id under `roms/sg1000/` while the DB still says `sms`: DbSync doesn't heal that (it skips duplicate game ids, `DbSyncSkip.DuplicateGameId`), so the next run reuses that leftover as its target (S11.6) instead of writing `X (2).zip`. A crash after the mirror but before `DeleteOldZip` leaves the old ZIP as a `DuplicateGameId` integrity issue for an Admin to delete, as after any title change.
- **Files waiting in `ingest/sms/`.** Unprocessed `.sg` files there fail `UnsupportedType` after upgrade; the deployment upgrade note tells Admins to move them to `ingest/sg1000/` first.
- **Battery saves in IndexedDB.** EmulatorJS keys a game's in-browser battery save by content name; moved games now load as `….sg`, so an in-browser save made under the old `.sms` name isn't picked up (library saves in the ZIP are carried, S11.3). SG-1000 carts have no battery RAM, so in practice nothing is lost.
- **Overlap with other specs.** The Sega Pico spec (if implemented) edits the same `NotIngested` picodrive rows (S8); whichever lands second merges them.
- **IGDB id.** 84 is from memory of IGDB's platform list; step 2 checks it.
