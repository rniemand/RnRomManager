# 3DS browser play

## Summary
Adds a **Play** button for Nintendo 3DS (`3ds`, `Nintendo3DsHandler`) using EmulatorJS's `azahar` core. EmulatorJS 4.2.3 (the vendored version, and the latest on npm) has no 3DS core: `azahar` exists only in the GitHub prerelease **4.3.0-pre**, whose cores don't load in 4.2.3 (`build.json` `minimumEJSVersion` `4.3.0`). So 4.3.0-pre's scripts and the `azahar` payload are vendored **side by side** with 4.2.3, pinned by SHA-256, and used only by a new cross-origin isolated page, `play-3ds.html` (azahar has only a threaded WebGL 2 build). Play is offered for `.3ds`/`.cci` releases whose header doesn't say they're encrypted; a new `encrypted` header field is read at ingest.

## Out of scope
- Moving any other core to EmulatorJS 4.3.0-pre, or upgrading 4.2.3.
- New ingest formats: `.3dsx`, `.cxi`, `.app`, `.elf`, `.axf` stay unsupported (`RomExtensions` unchanged). `.cia` stays library-only (azahar's libretro build can't load a CIA).
- Re-reading the header of releases already in the library (no backfill job): their header has no `encrypted` field, so Play shows for them (P2).
- A size cap: 3DS dumps up to 4 GiB are offered; the docs say large dumps may fail to load in the browser.
- AES keys, NAND or system archives for azahar; encrypted dumps simply get no Play button.
- Library saves (Saves tab play-with-save, copying the running game's save) for 3DS: an isolated tab has no modal, as for PSP and MS-DOS (`GameSaves.svelte` already skips `opensInNewTab` cores).
- `checkForUpdates()` in 4.3.0-pre fetches `https://cdn.emulatorjs.org/stable/data/version.json`; the page's CSP (`connect-src 'self'`) blocks it and only a console error results. No edit.

## Behaviour

### Header (H)
- **H1** `Nintendo3DsHeaderReader.Read` adds a field `encrypted` to an NCSD header: `true` when the first partition's NCCH header was read and its flags byte 7 (`partition[0x18F]`) lacks the `NoCrypto` bit (`0x04`), `false` when it has it, and `null` whenever the NCCH fields are null (partition past the span, no `NCCH` magic). The NCSD dictionary initialiser lists `["encrypted"] = null` after `programId`. The no-magic header (`format` null only) and CIA (null header) are unchanged. Layout per 3dbrew's NCCH page (flags at 0x188, `flags[7]` bit 2 = NoCrypto).
- **H2** Only newly ingested or re-identified releases get the field; existing `info.json`/`roms.header` values keep their stored header (no migration, no job).

### Play rules (P)
- **P1** `Nintendo3DsHandler.BrowserCore` returns `"azahar"`. Its doc comment drops "No browser play: EmulatorJS 4.2.3 ships no 3DS core" and says Play uses azahar from the side-by-side EmulatorJS 4.3.0-pre.
- **P2** A 3DS release is playable when its file name ends in `.3ds` or `.cci` (case-insensitive) and its header's `encrypted` isn't `true` (missing header, missing field or `null` count as playable). New `LibraryEndpoints.AzaharRomLoads(string fileName, bool encrypted)` (static, next to `JaguarRomLoads`) and `azaharRomLoads(fileName: string, header: Record<string, unknown> | null): boolean` (new, `src/lib/emulator.ts`, next to `jaguarRomLoads`) implement it; each doc comment names the other, as `jaguarRomLoads` does.
- **P3** Game page / Saves tab: `canPlay` in `emulator.ts` adds `!(game.browserCore === 'azahar' && rom.fileName !== undefined && !azaharRomLoads(rom.fileName, rom.header ?? null))`; its `rom` parameter's `Partial<Pick<RomDetail, …>>` adds `'header'`. A hidden Play shows nothing in its place, as for a Jaguar `.abs`.
- **P4** Quick play (Library, Global Search, `GET /api/games`, and the Discovery games list `/api/discovery/{kind}/games`, which `DiscoveryRepository.ListGamesAsync` builds from the same projection): `GameListItem` (Core) gets `bool PrimaryEncrypted = false` as its last parameter; `GameRepository.ListAsync`'s list query in `LibraryRepositories.cs` (and its `ListRow`) selects `(SELECT JSON_VALUE(r.header, '$.encrypted') = 'true' FROM roms r WHERE r.game_id = g.id AND r.is_primary = 1 ORDER BY r.id LIMIT 1) AS PrimaryEncrypted` next to `PrimaryHasFiles` (row property `bool? PrimaryEncrypted`, mapped `== true`). `ToListItemDto` adds `&& !(core == "azahar" && game.PrimaryRomFileName is { } file && !AzaharRomLoads(file, game.PrimaryEncrypted))`.
- **P5** External releases play: `LibraryEndpoints.ExternalBrowserCores` and `externalBrowserCores` in `emulator.ts` add `azahar`; `PlayDiscCores`/`playDiscCores` don't, so the page loads `/api/games/{game}/roms/{rom}/download` (as `desmume` and `dosbox_pure` do), for embedded and external storage alike.
- **P6** Isolated tab: `isolatedPages` in `emulator.ts` adds `azahar: 'play-3ds.html'`, so `opensInNewTab('azahar')` is true and `playUrl` builds `/emulator/play-3ds.html?game=…&rom=…&core=azahar&name=…`. The existing new-tab link (`aria-label="Play {rom.fileName} (opens in a new tab)"`), `GameResults.svelte` and `GlobalSearch.svelte` need no change.

### Play page (G)
- **G1** `static/emulator/play-3ds.html` (new): a copy of `play-dos.html` with `<title>3DS · RnRomManager</title>`, `<body data-player="3ds">` and the comment `<!-- 3DS G1: served cross-origin isolated (COOP/COEP) as its own tab, for azahar's threads. -->`. `SecurityHeaders.IsolatedDocumentPaths` adds `/emulator/play-3ds.html`; its doc comment names PSP, MS-DOS and 3DS.
- **G2** `params.js`: `cores` adds `'azahar'` (after `'mupen64plus_next'`); `isolatedPlayers` becomes `{ ppsspp: 'psp', dosbox_pure: 'dos', azahar: '3ds' }`; `parsePlayParams`'s JSDoc lists `3ds` (play-3ds.html). `hidesCoreChooser` is unchanged (azahar is the only member of 4.3's `3ds` group).
- **G3** `isolatedBrowserError(browser, core)` gains an `azahar` branch, checked in this order, each message exact:
  - not secure: `3DS games need a secure page: open RnRomManager over HTTPS or on localhost. A plain-HTTP network address can't run them.`
  - not isolated or no `SharedArrayBuffer`: `This page isn't cross-origin isolated, so 3DS games can't use threads. Ask an Admin to check that the proxy keeps the Cross-Origin-Opener-Policy and Cross-Origin-Embedder-Policy headers.`
  - no WebGL 2: `3DS games need WebGL 2, which this browser or graphics driver doesn't provide.`
  PSP and DOS messages are unchanged.
- **G4** `play.js` for `azahar` (`const is3ds = params.core === 'azahar'`): runs the G3 check before any request (as `isPsp || isDos` does); no BIOS, no optional firmware; shows `Downloading ROM…` and loads `/download` (the existing non-disc branch); sets `EJS_threads = true`; `EJS_Buttons` hides `saveSavFiles` and `loadSavFiles` (as for `desmume`/`dosbox_pure`: azahar keeps saves in its own virtual SD/NAND, not RetroArch SRAM); and points EmulatorJS at the 4.3 copy (V2):
  - `EJS_pathtodata = '/emulator/vendor/ejs-4.3/data/'`
  - `EJS_paths = { 'emulator.min.js': '/emulator/vendor/ejs-4.3/data/src/emulator.js', 'emulator.min.css': '/emulator/vendor/ejs-4.3/data/emulator.css' }` (4.3.0-pre ships no minified build; without this its loader logs a failed request first)
  - the loader script's `src` is `/emulator/vendor/ejs-4.3/data/loader.js` (every other core keeps `/emulator/vendor/data/loader.js`).
  `listenForMessages` isn't called (no modal). `keepDrawingBuffer()`, `EJS_onGameStart`, `EJS_defaultOptions` and the virtual-gamepad handling stay as for other cores; if a 4.3 API they rely on differs, the implementer asks before changing behaviour (Implement step 4).

## Risks
- **Prerelease code:** 4.3.0-pre is marked not for production upstream. It's confined to the 3DS tab; every other core keeps 4.2.3.
- **Build needs network:** the first vendoring (dev, CI, Docker build stage) downloads ~4.6 MB from codeload.github.com and cdn.emulatorjs.org. A changed upstream file fails the build loudly (SHA-256), never silently. GitHub's tarball bytes are stable per commit in practice; if the hash ever drifts, re-measure and update the pin (D3).
- **Image size:** +~4 MB compressed (azahar's wasm is ~18 MB unpacked in the browser).
- **Memory:** a multi-GiB dump is buffered whole; it may fail on smaller machines (documented, V3 shows an error instead of hanging).
- **Old releases** show Play even if encrypted (decision); they fail inside the emulator.
- **Security:** same CSP and isolation as the PSP/DOS pages; no new origins (`connect-src 'self'`).
