# Virtual Boy, Atari 5200 and Atari 7800

## Summary
Three new cartridge systems: Nintendo Virtual Boy, Atari 5200 and Atari 7800. Each stores its ROMs in the game ZIP, is identified against its libretro No-Intro DAT (with all four metadat kinds) and plays in the browser through EmulatorJS (`beetle_vb`, `a5200`, `prosystem`; none needs a BIOS). Atari 7800 reads the optional `.a78` header; the other two have no header.

## Out of scope
- BIOS files for browser play: `a5200` has AltirraOS built in, `prosystem` treats `7800 BIOS (U).rom` as optional, `beetle_vb` needs none. No BIOS folder, endpoint or `EJS_biosUrl`.
- Reading the Virtual Boy footer header (title/maker/game code at `size − 0x220`): it has no magic bytes, so junk files would show junk fields.
- Converting between headered `.a78` and headerless `.bin` 7800 dumps (the DAT lists both, each matches its own entry).
- Virtual Boy 3D/anaglyph options, 5200 keypad overlays or any per-core EmulatorJS settings beyond what the play page already sets.
- e2e Play checks for the new systems (no real ROMs can be committed).
- New README screenshots.

## Behaviour
- **B1** Three handlers, each its own family (`Family` = `Id`), `EmbedRomsInZip` true, `DatSource` Libretro, `DatFolder` No-Intro, all four metadat kinds (defaults), `FileSets` false:

  | | Virtual Boy | Atari 5200 | Atari 7800 |
  |---|---|---|---|
  | Project | `RnRomManager.Systems.VirtualBoy` (new) | `RnRomManager.Systems.Atari` | `RnRomManager.Systems.Atari` |
  | Class | `VirtualBoyHandler` | `Atari5200Handler` | `Atari7800Handler` |
  | `Id` / `Family` | `vb` | `a5200` | `a7800` |
  | `DisplayName` / `ShortName` | `Virtual Boy` / `VB` | `Atari 5200` / `5200` | `Atari 7800` / `7800` |
  | `RomExtensions` | `.vb` | `.a52` | `.a78`, `.bin` |
  | Size | 64 KiB – 4 MiB | 4 KiB – 64 KiB | 4 KiB – 1 MiB |
  | `DatName` | `Nintendo - Virtual Boy` | `Atari - 5200` | `Atari - 7800` |
  | `ReadHeader` | always null | always null | B2 |
  | `BrowserCore` (from step 4) | `beetle_vb` | `a5200` | `prosystem` |

  Extensions and sizes come from the libretro DATs (2026.10.07): VB 64 `.vb` entries, 256 KiB–4 MiB; 5200 150 `.a52` entries, 4–40 KiB; 7800 227 `.bin` (4–512 KiB) and 110 `.a78` (16 KiB+128 – 512 KiB+128) entries. Min sizes are left below the DAT minimum for homebrew/prototypes, as for Lynx.
- **B2** Atari 7800 `ReadHeader` (`A78Header.Read` in `RnRomManager.Systems.Atari`): a file of at least 128 bytes with ASCII `ATARI7800` at 0x01 returns a plausible header classified `a7800` with fields:
  - `version`: byte 0x00
  - `title`: 0x11, 32 bytes, Latin-1 up to the first NUL, trimmed, null if empty (same rules as Lynx)
  - `romSize`: u32 BE at 0x31
  - `cartType`: u16 BE at 0x35
  - `controller1`, `controller2`: bytes 0x37, 0x38
  - `tvType`: `ntsc` if bit 0 of 0x39 is 0, else `pal`

  Fields are added in that order; numbers are stored as read (unsigned). `RomHeader.Title` is `title`. Anything else (a headerless `.bin`, a shorter file) → null, so an unmatched file goes to Review as headerless, never `InvalidHeader`. No `NormalizeForHashing` (the DAT hashes headered `.a78` and headerless `.bin` separately). A `.bin` in `ingest/a7800/` is only eligible for 7800 (families are separate; Atari 2600's `.bin` is unaffected). The DAT lists most games twice under one game name (`.a78` and `.bin`); both dumps of a game become two releases of one game, and the existing tie-break (ordinal file name) makes the `.a78` primary. libretro's 7800 metadat files list only the `.bin` CRCs, so an `.a78` match gets no developer, publisher, genre or year (accepted; documented in `docs/features.md`).
- **B3** A file resolved in Review without a DAT entry is stored as `RomExtensions[0]` (`.vb`, `.a52`, `.a78` — even a headerless 7800 `.bin`), the existing convention; with a DAT entry it takes the entry's extension. Virtual Boy and 5200 releases have no Header button and `info.json` `header` null.
- **B4** Registration in `AppHost.AddSystemHandlers`: `VirtualBoyHandler` right after `SnesHandler`; `Atari5200Handler`, `Atari7800Handler` right after `Atari2600Handler` (before Lynx). `/api/systems` stays sorted by `DisplayName`, so the new ones land as `Atari 2600, Atari 5200, Atari 7800, Atari Jaguar, Atari Lynx…` and `…TurboGrafx-16, Virtual Boy, Wii…`.
- **B5** Badge colours (`systemColours.ts` + `app.css`, same in both themes, following `lynx`): `vb` `#f03e3e` with black text (5.5:1), `a5200` `#364fc7` with white text (6.8:1), `a7800` `#1098ad` with black text (6.1:1). `icons.ts` untouched (controller fallback).
- **B6** The play page accepts `beetle_vb`, `a5200` and `prosystem` (`params.js` core list, appended in that order). The three cores are vendored at 4.2.3 (`@emulatorjs/core-beetle_vb`, `@emulatorjs/core-a5200`, `@emulatorjs/core-prosystem`, exact versions; each ships `-wasm` and `-legacy-wasm` `.data` and `reports/<core>.json`, no `-thread-` variants are copied, as today) and listed in `licenses.json` (licence from each package's GitHub repo, since the npm packages name only a file): `@emulatorjs/core-beetle_vb`, `GPL-2.0`, `https://github.com/EmulatorJS/beetle-vb-libretro`; `@emulatorjs/core-a5200`, `GPL-2.0`, `https://github.com/EmulatorJS/a5200`; `@emulatorjs/core-prosystem`, `GPL-2.0`, `https://github.com/EmulatorJS/prosystem-libretro`. `play.js` sets `EJS_core` to the core name as today; no other play page change.
- **B7** README: the supported-systems table gains three rows, in `DisplayName` order as `SupportedSystemsTableTests` generates them (`Virtual Boy`/`vb`/`.vb`, `Atari 5200`/`a5200`/`.a52`, `Atari 7800`/`a7800`/`.a78`, `.bin`; In ZIP; No-Intro; Play `—` in step 3, the core name in step 4), the "Upgrading from…" sentence (step 3: `…SNES, Virtual Boy, Atari 2600, Atari 5200, Atari 7800, Atari Lynx…`), the Play feature bullet and the Attribution line (cores list gains [Beetle VB](https://github.com/EmulatorJS/beetle-vb-libretro) (GPL-2.0), [a5200](https://github.com/EmulatorJS/a5200) (GPL-2.0) and [ProSystem](https://github.com/EmulatorJS/prosystem-libretro) (GPL-2.0)).

## Risks
- **Play untested on real ROMs**: no e2e Play for these systems; a core may need input mapping (the 5200 keypad, VB's two d-pads) that EmulatorJS defaults cover only partly. Play is still offered; the PR says so.
- **Bundle size**: three more cores, ~10.7 MB unpacked, in the image.
- **Fixtures**: every fixture loading all systems' DATs must include the three, or `DatsMissing` fails ingestion tests (step 3 lists them).
- **7800 metadata**: `.a78` matches get no developer, publisher, genre or year (B2, accepted).
- **Colours**: 25 systems make near-duplicates unavoidable (VB vs Master System red); the colours differ in lightness and text colour.
