# UI polish and Activity report

## Summary
A batch of UI fixes across Library, Game detail, Collections, Reports, ROM Tools, About, footer, Global Search and Admin, plus a new Admin-only **Activity** report (recent added ROMs, sign-ins, browser plays, saves, edits, deletions, jobs, last backup). Browser plays become a new `GamePlayed` audit event so they can be reported. For every signed-in user; Activity and Admin pages for Admins only.

## Out of scope
- New storage for plays beyond the audit log (no migration; plays, saves, edits, deletions and sign-ins in Activity cover the 30-day audit retention only).
- Auditing release-note edits or ratings.
- Redesigning pages beyond the listed items; no new dependencies (Bootstrap 5.3 + Bootstrap Icons only).

  - `addedRoms`: `{ romId, gameId, gameTitle, fileName, systemId, sizeBytes, addedAt }`.
  - `signIns`, `plays`, `saves`, `edits`, `deletions`: audit rows `{ id, occurredAt, action, user, system, gameId, gameTitle, jobId, path, targetPath, details }` (the `/api/admin/audit` item, plus `gameTitle`), where `gameTitle` comes from `LEFT JOIN games` and is `null` when the game is gone. ### Browser plays
- **B22** `POST /api/games/{id}/roms/{romId}/played` (any signed-in user, antiforgery as all POSTs) records `GamePlayed` (system, game, actor, `details` = release name) and returns `204`; unknown game or a release not in it → `404` (`Problems.NotFound`, code `NotFound`, via the existing `roms.GetAsync(id, romId)` + game lookup pattern). No job lock; not `MaintenanceExempt`, so it is refused during a restore like other writes (the client ignores it). The SPA calls it fire-and-forget (errors ignored) from one place for the modal: `EmulatorModal` when it opens with the same guard as its player (`open && rom && core`, and a non-empty `gameId`), so every modal play counts (game page, Library and collection quick play, Global Search, play-with-save from `GameSaves`). Every PSP `target="_blank"` play link (game page release card and `GameResults`' `playAction`) records on `click` and middle-button `auxclick` through the same helper in `lib/emulator.ts`, and so does Global Search's PSP path (B27); "Open in new tab" from the context menu fires no event and isn't counted.

## Risks
- **Audit volume:** one `GamePlayed` row per play start; negligible next to ingest rows, purged at 30 days.
- **e2e selectors** break for B2, B3, B5, B9, B23, B26 and B30 (Changes); each is updated in the step that changes it.
- **DAT download path safety:** the name is only a lookup key into the checked manifest; no client path reaches the file system.
- **Discovery search vs "app never normalizes names":** `q` is a display filter on labels only; grouping and keys are untouched (Decisions).
- **Hidden Activity tab:** the route itself is guarded by `AdminOnly` (and the layout shows only `NotAllowed` there) and the API by `AuthSetup.AdminOnly`, so a Site user typing the URL sees "Not allowed".
