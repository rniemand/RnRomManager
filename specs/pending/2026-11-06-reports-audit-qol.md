# Reports, auditing and library QoL

## Summary
A batch for people curating a large library, especially during the first import. It fixes the "page stops scrolling" bug and adds small quality-of-life changes to the Review, Game, Library, Ingestion pages and the navbar. It also adds a **Reporting** page (Library Size treemap, Missing Images, Duplicates with merge/dismiss) for every signed-in user, and an **Admin → Auditing** tab that records every file action the app takes, kept for 30 days.

## Out of scope
- A Library Size tab under Admin. It lives only on Reporting (user decision).
- Duplicate detection by hash, by DAT game name or across systems. `roms.sha1` is unique, so the same bytes can never sit in two games; only the base-title rule (D1) is used.
- Auditing reads, sign-ins, user/role changes, settings changes, integrity checks (they never touch files) and the log purge.
- Undo from the audit log.
- Persisting the ingestion file selection across page loads.
- A JSON *editor*. The info.json view is read-only.
- Image search providers other than Google, and any automatic image fetching from the search.
- New third-party npm or NuGet dependencies. The treemap and JSON viewer are written here.

## Behaviour

### Global
- **G1 Scroll bug.** Cause: a Bootstrap `Modal` sets `body.modal-open`, inline `overflow: hidden` and `padding-right` on `<body>` and appends a `.modal-backdrop`. It only removes them at the end of `hide()`'s fade (`hidden.bs.modal`). `ConfirmModal` and `GlobalSearch` call `modal.dispose()` in `onDestroy`, and `dispose()` doesn't restore `<body>`. A modal unmounted while shown or still fading out therefore leaves the page unscrollable until refresh. That happens after merge, move, delete release and delete game on the game page (`GameAdminModal` closes and calls `ondone`, which runs `goto` or `reload++`; the page's load `$effect` sets `game = null`, unmounting every modal), after Dismiss/Delete on the review item page (`goto('/review')` right after closing), and when the root layout swaps the page out on a 401/403 redirect.
  Fix: a shared `releaseModal(element)` helper in `src/lib/modal.ts`, called by both components' `onDestroy` before `dispose()`. When `element.classList.contains('show') || document.querySelector('.modal-backdrop') || document.body.classList.contains('modal-open')`, and **no other** `.modal.show` element (other than `element`) remains in the document, it removes `modal-open` from `<body>`, clears `<body>`'s inline `overflow` and `padding-right`, and removes every `.modal-backdrop`. Another modal that is still open keeps its body state. Callers keep their current close-then-navigate flow.
- **G2 Ctrl K hint.** The `<kbd>Ctrl K</kbd>` in the navbar's Search button goes. The Ctrl+K shortcut itself still works.

### Library page
- **LP1 Size.** `GET /api/games` items get `primarySizeBytes` (`roms.size_bytes` of the game's `is_primary` release; with one release that is it). The grid card shows `<FileSize>` after `year · regions`; the list view gets a right-aligned **Size** column after Releases. A game with no primary release (shouldn't happen) shows nothing.

### Review list and review item
- **RV1 Shift+Delete.** On the review list's row delete button and on the item page's Delete button, a click with Shift held deletes the item at once (`DELETE /api/review/{id}`) with no modal, **unless the item came from an archive**. Deleting an archive item deletes the whole archive, so Shift+click on one still opens the modal and its warning. `GET /api/review` list items get `isArchive` (`archive_path` is not null; additive) so the list knows. Without Shift, the modal opens as today. The buttons' `title`/tooltip reads `Delete (Shift+click to skip confirmation)`. On success the list reloads the current page (or the previous one when the page became empty), and the item page navigates back to `/review` (keeping RV4's filter). A failure toasts the error (`JobRunning` uses `toasts.jobRunning`), and nothing else changes. The DELETE call moves from `ReviewDeleteModal` into `deleteReviewItem(id)` in `src/lib/review.ts`, used by the modal and both shortcuts.
- **RV2 Google It.** On the item page's Suggestions tab, below the DAT entry suggestions table (and its empty state), a `Google it` link-button (`btn btn-outline-secondary btn-sm`, search icon, `target="_blank" rel="noopener noreferrer"`) opens `https://www.google.com/search?q=<encoded query>`. The query comes from `reviewSearchQuery(item, systemName)` in `src/lib/googleSearch.ts`:
  1. Name = the header `title` when it's non-empty and has at least 3 alphanumeric characters, else the original file name.
  2. Clean it: drop the extension, drop every `(…)` and `[…]` group, replace `_` and `.` with spaces, collapse spaces, trim.
  3. Query = `"<name>" <system display name> rom`. When the cleaned name is empty, query = `<crc32> <system display name> rom`.
  Example: `Orbt_Blcks (U) [!].gb`, Game Boy → `"Orbt Blcks" Game Boy rom`.
- **RV3 Filter API.** `GET /api/review` accepts optional `system` (a system id), `reason` (`NoDatMatch` or `AmbiguousGroup`) and `q` (1–100 chars, case-insensitive substring of `original_file_name` or of the header `title`). Unknown `system`/`reason` values give `400` validation (`code: Validation`, field error on the parameter). The `total` and paging reflect the filter. Status and paging are unchanged.
- **RV4 Filter UI.** The review list gets a filter bar above the table: a search input (`Search file name or title`, debounced 300 ms), a System select (`All systems` + `/api/systems`), a Reason select (`All reasons`, `No DAT match`, `Ambiguous group`) and a `Clear` button (enabled when any filter is set). The filter is kept in the URL query (`q`, `system`, `reason`, `page`) and in `localStorage` key `review.filter` (wrapped in try/catch). Rules:
  - Loading `/review` with any of these params uses them and saves them.
  - Loading `/review` with none restores the saved filter (and page) by `replaceState`-ing the URL.
  - Changing a filter resets to page 1, updates the URL (`replaceState`) and saves.
  - `Clear` removes all four from the URL and `localStorage`.
  - The empty state reads `No review items match this filter.` when a filter is set, the current text otherwise.

### Game page
- **GP1 Tabs.** Below the header block, the Releases and Images sections become Bootstrap `nav-tabs` (`role="tablist"`, buttons with `role="tab"`, `aria-selected`, `aria-controls`) labelled `Releases (n)` and `Images (n)`. Releases is the default. `?tab=images` opens Images. Switching tabs updates `tab` with `replaceState` (Releases removes it). Both panels stay mounted and the inactive one is hidden with the `hidden` attribute, so `GameImages`' modals keep their DOM order (I3 from the previous spec) and nothing unmounts on a tab switch.
- **GP2 Google button.** Next to Download ZIP, a `Google` link-button (search icon, new tab, `noopener noreferrer`) opens `https://www.google.com/search?q=` + `gameSearchQuery(game)` = `"<display title>" <system display name>`. Visible to every signed-in user.
- **GP3 info.json endpoint.** `GET /api/games/{id}/info-json` (any signed-in user, like the downloads) returns the game ZIP's `info.json` entry as stored, `application/json`, reusing `LibraryFiles.OpenEntry` with `LibraryZip.InfoJsonEntry` and `InfoJsonReader.MaxBytes`. Unknown game → `404 NotFound`. A missing entry or an unreadable ZIP gets the same problem response the existing ROM download gives for those cases.
- **GP4 info.json modal.** A `View info.json` button (code icon, `btn-outline-secondary btn-sm`) next to the Google button opens a `ConfirmModal` (info mode, `size="lg"`, title `info.json`). The modal fetches GP3 when opened. It shows `Loading` while loading, `ErrorAlert` with Retry on failure, and a `CopyButton` for the raw text. A `JsonTree` component renders the parsed JSON:
  - Objects and arrays are `<details>`/`<summary>` elements. The summary shows the key and `{n}` or `[n]` when closed. Depth 0 and 1 start open; deeper ones start closed.
  - Expand all / Collapse all buttons.
  - Colours are Bootstrap text classes only: keys `text-primary-emphasis`, strings `text-success-emphasis`, numbers `text-warning-emphasis`, `true`/`false`/`null` `text-danger-emphasis`. All are monospace and readable in both themes (axe-checked).
  - Invalid JSON shows the raw text in a `<pre>` with a warning alert.
- **GP5 Merge suggestions.** When the Merge into… modal opens, it shows up to 5 **Suggested** games (same system, current game excluded) as a list of buttons above the typeahead. Clicking one selects it as the target, exactly as picking it in the typeahead does. Suggestions come from `GET /api/games?system=<system>&q=<term>&sort=relevance&pageSize=6`, filtered client-side to exclude the current game. `term` = the display title with `(…)`/`[…]` groups removed, trimmed, and cut to its first 8 words (`GameQuery.MaxWords`). If that returns no other game, one more try uses the first word of `term` with at least 3 characters. No suggestions → the list is omitted. A failed suggestion fetch is silent: the typeahead still works.

### Ingestion page
- **IN1 API.** `POST /api/jobs/ingest` accepts an optional JSON body `{ "files": [{ "system": "gb", "name": "x.zip" }, …] }`. No body, or `files` null → all pending files (today's behaviour). `files` present but empty, or any entry with a null/empty `system` or `name` → `400 Validation`. Unknown systems and repeated entries are ignored like an unknown file. A file in the list that isn't in the job's snapshot any more is ignored. Files in the snapshot but not in the list are left alone (not Skipped, not in `job_items`). The match is exact system id + top-level file name. 409 `JobRunning`/`DatsMissing` are unchanged. `IngestJob` gets an optional selection (set by the endpoint before `StartAsync`) that filters its snapshot.
- **IN2 UI.** Each pending-file row gets a checkbox (checked by default, `aria-label="Select <name>"`). Each system table's header gets a select-all checkbox for that system (checked, unchecked, or indeterminate when mixed). A `Select all` / `Clear selection` pair sits above the tables. The selection survives client-side paging and is rebuilt (all checked) after every reload of the pending list. Buttons: `Import all` (today's Start, no body) and `Import selected (n)` (sends IN1's body). The second is disabled when nothing is selected or everything is (then `Import all` does the same).

### Reporting
- **RP1 Page.** A new top-nav link `Reports` (after Library, visible to every signed-in user) opens `/reports`, which redirects to `/reports/library-size`. `src/routes/reports/+layout.svelte` renders `nav nav-tabs` like the Admin layout: `Library Size`, `Missing Images`, `Duplicates`. All report endpoints are under `/api/reports` and need a signed-in user unless stated.
- **RP2 Library Size API.**
  - `GET /api/reports/library-size` returns `{ totalBytes, gameCount, systems: [{ system, systemName, bytes, gameCount }] }`, sorted by `bytes` desc. Bytes are `SUM(games.zip_size_bytes)`, the on-disk ZIP sizes.
  - `GET /api/reports/library-size/{system}` returns `{ system, systemName, bytes, games: [{ id, displayTitle, bytes, romCount }] }`, every game in the system sorted by `bytes` desc. An unknown system gives `404 NotFound`.
- **RP3 Library Size UI.** The page has:
  - A total line: `<FileSize> in n games`.
  - A breadcrumb: `Library` › `<System>`.
  - A treemap: inline SVG, `role="img"` with an `aria-label` summary. Rectangles are laid out by a squarified algorithm (`src/lib/treemap.ts`, pure function `squarify(items, width, height)`) and sized by bytes. At the library level each system is one rectangle; at the system level each game is one. Colours come from a new exported map in `src/lib/systemColours.ts`, which `SystemBadge` also uses: per system, the Bootstrap colour name (`gb: 'success'`, …, `n64: 'danger'`, unchanged badges). A rectangle's `fill` is `var(--bs-<name>)`. Its label's `fill` is the foreground Bootstrap's `text-bg-<name>` uses for that colour (`#fff` or `#000`), stored next to the name in the map, so labels meet AA contrast like the badges. Rectangles get a 1 px `var(--bs-body-bg)` stroke so neighbours of the same system stay distinct. Each rectangle has a `<title>` tooltip `name — size` and a text label when it is at least 60×20 px. At the system level only the 300 largest games are drawn, plus one `n others` rectangle (not clickable).
  - A table under it, the accessible equivalent. At the library level: System, Games, Size, % of library. At the system level: Game (link), Releases, Size, % of system. Sorted by size desc.
  - Clicking a system rectangle or row drills into it (`?system=<id>`, so Back works). Clicking a game rectangle or row opens `/games/{id}`.
  - Empty library → `EmptyState`.
- **RP4 Missing Images API.** `GET /api/reports/missing-images?system=&page=&pageSize=` (pageSize default 50, max 200) returns `{ total, items: [{ id, displayTitle, system, systemName, reason }] }`, sorted by system then title. `reason` is `NoCover` (no image with `is_cover = 1`) or `Placeholder` (`has_default_boxart = 1`). A game is listed once; when both apply, `NoCover` wins.
- **RP5 Missing Images UI.** A System filter, then a table with Game (link to `/games/{id}?tab=images`), System (`SystemBadge`) and Reason (`No cover` / `Placeholder art`), with `Pagination`. Empty → `EmptyState` `Every game has a cover image.`
- **RP6 Duplicates rule (D1).** A duplicate group is two or more games in the same `system_id` that own releases with the same `roms.base_title` (the key ingestion groups releases by; compared with the column's collation). A game in several groups (because its releases have several base titles) appears in each. A group is hidden while a dismissal matches it (RP7).
- **RP7 Dismissals.** A new table `duplicate_dismissals(system_id VARCHAR(16), base_title VARCHAR(255) (same collation as `roms.base_title`), games_key CHAR(64), dismissed_by INT NULL (no FK, like AU1), dismissed_at DATETIME(6))`, PK `(system_id, base_title, games_key)`. `games_key` is the SHA-256 hex of the group's game ids sorted ordinally and joined with `,`. A dismissal hides only that exact membership: when a game joins or leaves the group, the group shows again. Rows whose group no longer exists are harmless and stay.
- **RP8 Duplicates API.**
  - `GET /api/reports/duplicates?system=&page=&pageSize=` (pageSize default 25, max 100) returns `{ total, items: [{ system, systemName, baseTitle, gamesKey, games: [{ id, displayTitle, romCount, zipSizeBytes, createdAt, boxArtUrl }] }] }`. Groups are sorted by system then base title. Games within a group are sorted by `romCount` desc, then `createdAt` asc, then id, so `games[0]` is the suggested target.
  - `POST /api/reports/duplicates/dismiss { system, baseTitle, gamesKey }` (rom-manager) stores the dismissal and returns `204`; repeating it is a no-op returning `204`. Missing/empty fields, an unknown system, a `gamesKey` that isn't 64 lower-case hex characters, or a `baseTitle` over 255 chars → `400 Validation`. A key that matches no current group is stored anyway (harmless; the group may have just changed).
  - `POST /api/reports/duplicates/merge { targetGameId, sourceGameIds }` (rom-manager) calls `LibraryEditor.MergeAsync(source, target)` for each source in order. That's the same logic, lock and errors as Merge into… (`409 JobRunning` etc.). Validation: a target is required, there must be 1–20 sources, the target can't be among the sources, and there can be no repeats (`400`). Success → `200 { targetGameId }`. On the first failure it stops and returns that failure's problem with an extra `merged` array of the source ids already merged (`Problems` gains an optional extensions argument for this). Each merge is atomic, so those stay merged.
- **RP9 Duplicates UI.** A System filter and paging. One card per group, headed `<SystemBadge> <baseTitle>`, listing its games as radio rows: title link, releases, `FileSize`, added date. The first game is pre-selected and labelled `Suggested target`. For rom-managers, the buttons are `Merge into selected` (danger, opens a `ConfirmModal` naming the target and the n games merged into it) and `Dismiss`. Others see the list without radios or buttons. After a merge or dismiss the list reloads. A merge failure toasts the problem, and when `merged` is non-empty it also says how many merged. Empty → `EmptyState` `No duplicate games found.`

### Auditing
- **AU1 Table.** A new migration adds `audit_events`:
  - Columns: `id BIGINT AUTO_INCREMENT PK`, `occurred_at DATETIME(6)`, `action VARCHAR(32)`, `system_id VARCHAR(16) NULL`, `game_id CHAR(36) NULL`, `user_id INT NULL`, `username VARCHAR(64) NULL`, `job_id CHAR(36) NULL`, `path VARCHAR(1024) NULL`, `target_path VARCHAR(1024) NULL`, `details VARCHAR(1024) NULL`.
  - Indexes: `(occurred_at)`, `(action, occurred_at)`, `(system_id, occurred_at)`, `(user_id, occurred_at)`.
  - No foreign keys, so deleting a user or game keeps its history. `username` is a snapshot taken when the row is written.
  - Paths are relative to the library or ingest root they belong to, prefixed `roms/` or `ingest/`, and never absolute. An archive entry (whose working copy sits under `cache/work/`) is recorded as `ingest/<archive path> › <entry>` from its `ArchivePath` + `ArchiveEntry`.
  - Text over its column length is truncated.
- **AU2 Writer.** `IAuditLog.Record(AuditEvent e)` in Core is **synchronous and non-blocking**: it stamps `occurred_at` from `TimeProvider` and enqueues the event on a bounded in-memory `Channel` (capacity 10,000; when full, the event is dropped with a `Warning` log). An `AuditWriter` hosted service in Api drains the channel and inserts the events through the Dapper `AuditRepository` with `CancellationToken.None`. So the synchronous pipeline helpers (`MoveToFailed`, `MoveToDuplicates`, `FailFile`, `IngestJob.ApplyFate`) can record without becoming async, and a cancelled request or job never loses a row that was recorded or throws after the file moved. A failed insert is logged at `Warning` and the event is dropped. `Record` never throws: its body is wrapped in try/catch that logs at `Warning`, so callers don't guard it. Events are recorded only after the file action succeeds. On shutdown the writer drains what is queued (up to 5 s). Events still queued at a crash are lost, which is accepted (best-effort log, files are the source of truth). Tests use `AuditWriter.FlushAsync()` (completes when the queue is empty) before asserting.
- **AU3 Who.** Every recorded event carries an `AuditActor(int? UserId, string? Username, Guid? JobId)`:
  - Endpoints build it once per request from the claims (`ClaimTypes.NameIdentifier`, `ClaimTypes.Name`), via `AuditActor.From(ClaimsPrincipal)` in Api.
  - `JobRunner` builds it once per job: job id, `requestedBy` and that user's username, loaded once through `IUserRepository`. It is passed as a new `JobContext.Actor`. Scheduled runs (`requestedBy` null) get `UserId`/`Username` null and show as `System`.
  - `LibraryEditor` methods, `ReviewResolver` methods, `GameMediaRetry.RetryAsync`, and the `IngestPipeline` methods that move or store files take an `AuditActor` parameter. `LibraryEditor.PatchAsync` takes `AuditActor?`: `PATCH …/rating` passes `null`, meaning "don't record", and `PATCH /api/games/{id}` passes the request actor. All callers are updated: endpoints pass the request actor; `IngestJob`, `MediaRetryJob` and `DatRefreshJob` pass `context.Actor`; `ReviewResolver` passes its caller's actor (job id null) instead of making up a job id.
- **AU4 Actions.** One row per file action, each with exactly one writer:

  | `action` | Written by | path / target_path / details |
  |---|---|---|
  | `Ingested` | `IngestPipeline` store (ingest and review resolve) | source / game ZIP / `release <file name>`; `review resolve (<action>)` when from Review |
  | `ZipRepaired` | `IngestPipeline` `Repaired` path (rewrites an existing library ZIP) | source / game ZIP / — |
  | `ExtensionRenamed` | `IngestPipeline.RenameToClassifiedExtension` | old path / new path / — |
  | `MovedToFailed` | `IngestPipeline.MoveToFailed` (ingest and review dismiss) | source / failed path / reason code; `review dismiss` when from Review |
  | `MovedToDuplicates` | `IngestPipeline.MoveToDuplicates` | source / duplicates path / — |
  | `ArchiveDeleted` | `IngestJob` archive delete | archive / — / — |
  | `ReviewDeleted` | `ReviewResolver.DeleteSourceAsync` | source (or archive) / — / — |
  | `GameUpdated` | `PatchAsync` for metadata edits (`PATCH /api/games/{id}`); **not** written for rating/favourite (`PATCH …/rating`) | old ZIP / new ZIP / changed field names |
  | `ReleaseDeleted` | `DeleteReleaseAsync` (not the last release) | ZIP / `_removed` copy / release file name |
  | `GameDeleted` | `DeleteGameAsync`, and `DeleteReleaseAsync` on the last release (it removes the game) | ZIP / `_removed` folder / — |
  | `ImageAdded` / `ImageDeleted` / `CoverSet` | image methods | ZIP / — / image file name |
  | `MediaFetched` | `GameMediaRetry.RetryAsync` only (called by `RetryMediaAsync` and `MediaRetryJob`), when it wrote the ZIP | ZIP / — / fetched image names |
  | `ReleaseMoved` | `MoveReleaseAsync` | source ZIP / target ZIP / release file name |
  | `GamesMerged` | `MergeAsync` | source ZIP / target ZIP / `n releases, m images` |
  | `DatsRefreshed` | `DatRefreshJob` (one row per run that swapped files) | — / — / DAT names |

  `MoveAside` (the private helper behind the two moves) records nothing itself. Review resolve/dismiss therefore write one row (`Ingested`/`MovedToFailed` with the user as actor), not two. `system_id` and `game_id` are filled whenever the action has them.
- **AU5 Retention.** Rows older than 30 days are deleted daily with the log purge (startup and 00:05 UTC), via `IAuditLog.PurgeAsync(olderThan)`. The 30 days is a constant (`AuditLog.Retention`), not a setting.
- **AU6 API.** `GET /api/admin/audit` (Admin) takes optional `action`, `system`, `user` (username, exact, case-insensitive), `scheduled=true` (only rows with `user_id` null; `400` together with `user`), `q` (substring of path, target_path or details, 1–200 chars), `from` (inclusive) and `to` (exclusive) as ISO 8601 instants with an offset (`400` when unparseable or `from >= to`), `page` and `pageSize` (default 100, max 500). It returns `{ total, items: [{ id, occurredAt, action, system, gameId, user, jobId, path, targetPath, details }] }`, newest first. `GET /api/admin/audit/actions` returns the AU4 action names for the filter.
- **AU7 UI.** An `Auditing` tab after Logs in the Admin layout:
  - Filter row: Action select, System select, User text with a `Scheduled only` checkbox (disables the text), Search text, From/To date inputs, and `Clear`. All are debounced 300 ms and kept in the URL query. The date inputs are local days: From sends local midnight of that day and To sends local midnight of the day after, both as ISO instants, so the rows match the local times shown.
  - Table: Time (local, `text-nowrap`), Action, System (`SystemBadge`), User (`System` in italics when null), Game (link when `gameId` exists), Path (truncated, `title`), Target, Details.
  - `Pagination` with 100 rows per page. Default load shows the last 100 actions.
  - Empty → `EmptyState`.

## Risks
- **G1 can't be reproduced reliably by hand.** The vitest test reproduces it deterministically: mount `ConfirmModal` open, unmount it mid-fade, and assert that `<body>` is clean. That test guards the fix. The helper never touches `<body>` while another modal is shown, so stacked modals (none exist today) are safe.
- **Audit volume.** One row per file means a 5,000-file import writes 5,000 rows. Each insert is small, and rows go one at a time after each file action, which is fine at this scale. Retention caps the table at 30 days. The indexes cover the default newest-first page and every filter column paired with time.
- **Audit and file consistency.** A failed insert, a full queue or a crash with events still queued leaves a file action without a row. That's accepted and logged (AU2). The file is the source of truth and the audit log is best-effort; in exchange, recording never slows down or breaks a file action.
- **Shift+Delete** can't destroy an archive's other ROMs: archive items always confirm (RV1).
- **Changing `LibraryEditor` signatures** touches every caller and test. Done in one step (19) with the compiler as the checklist.
- **Merging a whole duplicate group** takes the job lock once per merge, not once for the group. A job can start between two merges, and the next merge then returns `409` with `merged` filled in. That is acceptable and reported.
- **Base-title false positives.** Two genuinely different games with the same base title (e.g. a remake) will be suggested. Dismiss handles that, and the dismissal sticks until the membership changes.
- **Treemap size.** Thousands of games in one system are capped at 300 rectangles plus "others". The table lists all of them.
- **Google links** send the ROM's name to Google. They are only opened by an explicit click and never automatically.
