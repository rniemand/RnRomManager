# Nintendo 3DS support

## Summary
Admins can import Nintendo 3DS dumps (`.3ds`, `.cci`, `.cia`) into the library. They're identified by SHA1 against libretro's No-Intro `Nintendo - Nintendo 3DS` DAT and stored as files next to the game's ZIP, like Nintendo DS and Switch, since 3DS dumps reach 4 GiB. There is no browser play: EmulatorJS 4.2.3 ships no 3DS core.

## Out of scope
- **Browser play.** No EmulatorJS core exists for 3DS (checked 2026-11-17: the 4.2.3 system→core map, the `@emulatorjs/core-*` packages on npm, no Citra/Azahar/Lime3DS). `BrowserCore` stays null, so no Play button, no vendored core, no `params.js`/`licenses.json` change. A later spec can add it if a core appears.
- Serial (product-code) matching for unmatched dumps. Decrypted or trimmed dumps never hash-match the DAT's dumps and go to Review.
- Decrypting, encrypting, trimming or converting dumps (`.3ds` ↔ `.cia`), and `.cxi`, `.3dsx`, `.app`, `.bcmdl` (the DAT's one `.bcmdl` entry is filtered out by B1's extensions).
- Renaming `.cci` to `.3ds`: an external system keeps the source extension (see Decisions).
- Reading the title from the SMDH (it's inside the encrypted ExeFS), so `RomHeader.Title` is null.
- Release-year metadata: libretro has no `metadat/releaseyear/Nintendo - Nintendo 3DS.dat` (404 on 2026-11-17).
- Moving any existing data: `3ds` is a new system with no legacy games (`LegacyEmbeddedRoms` false).
- An icon mapping in `icons.ts` (the controller fallback is used).

## Behaviour
- **B1 Handler.** `Nintendo3DsHandler` in `RnRomManager.Systems.NintendoDs` (no new project, no Dockerfile or `.slnx` change): `Id` `3ds` (a public const `Nintendo3DsHeaderReader.Nintendo3DsId`, as DS does), `DisplayName` `Nintendo 3DS`, `ShortName` `3DS`, `Family` `3ds` (`=> Id`; its own, so DS files are never eligible and vice versa), `RomExtensions` `[".3ds", ".cci", ".cia"]` (in that order), `MinRomSizeBytes` 16,384 (16 KiB, room for small homebrew `.cia`), `MaxRomSizeBytes` 4,294,967,296 (4 GiB inclusive, the DAT's largest entry), `DatName` `Nintendo - Nintendo 3DS`, `DatSource` Libretro (default), `DatFolder` `no-intro` (default), `MetadatKinds` `[DatKind.Developer, DatKind.Publisher, DatKind.Genre]` (libretro has those three, covering 40 of the DAT's ~2,060 games; no `releaseyear`, so year is always empty), `EmbedRomsInZip` false, `FileSets` false, `LegacyEmbeddedRoms` false, `KeepsSourceExtension` false (default; external systems keep the source extension anyway, both on hash-matched ingest and in Review), `BrowserCore` null (default), `DefaultBoxArtPng` from `EmbeddedResources.Load("boxart.3ds.png")` (lazy, as DS), `ReadHeader` → `Nintendo3DsHeaderReader.Read`, `NormalizeForHashing` default (never called for an external system).
- **B2 Ingest.** Files come from `ingest/3ds/` (created at startup like every handler's). Matching is case-insensitive on the extension. A DAT match (by SHA1) is stored next to the ZIP under the DAT ROM name's stem with the source file's extension lower-cased (`IngestPipeline`, external naming in `zip-format.md`): a `.CCI` matching the DAT's `….3ds` entry is stored as `….cci`. The DAT's `.3ds` and `.cia` entries are both eligible (its `.bcmdl` entry is filtered by B1's extensions). Out-of-range sizes fail `TooSmall`/`TooLarge`; other extensions fail `UnsupportedType`. Input archives keep today's caps (`ArchiveExtractor`: 100 entries, 256 MiB extracted in total), so dumps over 256 MiB must be dropped loose; an over-cap archive fails `ArchiveUnsafe` as today. Review resolutions keep the source extension (`ReviewResolver` T9, external).
- **B3 Header** (`Nintendo3DsHeaderReader.Read(ReadOnlySpan<byte>)`, given at most the first MiB; never throws; every offset computed in `long` and bounds-checked before slicing). Layout from 3dbrew's [NCSD](https://www.3dbrew.org/wiki/NCSD), [NCCH](https://www.3dbrew.org/wiki/NCCH) and [CIA](https://www.3dbrew.org/wiki/CIA) pages (checked 2026-11-17). Rules, in this order:
  1. Span shorter than 0x200 bytes → null.
  2. First little-endian `u32` is `0x2020` (the CIA archive header size) → null. An unmatched `.cia` therefore goes to Review, never `InvalidHeader`.
  3. ASCII `NCSD` at 0x100 → `RomHeader("3ds", Title: null, IsPlausible: true, Fields)` with fields in this order: `format` `"NCSD"`; `mediaId` (u64 LE at 0x108, formatted `X16`: 16 upper-case hex digits); then, when partition 0's offset (u32 LE at 0x120, × 0x200, the media unit) plus 0x200 is ≤ the span length and ASCII `NCCH` is at that offset + 0x100: `productCode` (16 bytes at offset + 0x150, ASCII up to the first NUL, trailing spaces trimmed, null when empty), `makerCode` (2 bytes at offset + 0x110, kept whole) and `programId` (u64 LE at offset + 0x118, `X16`); otherwise those three are present with value null. Text fields keep bytes 0x20–0x7E and turn every other byte into `?`, like the DS reader.
  4. Anything else → `RomHeader("3ds", null, IsPlausible: false, { format: null })`, so an unmatched non-CIA file without `NCSD` is `InvalidHeader`; a DAT match still wins.
- **B4 Box art.** A drawn 512×512 `3ds.png` (with its `3ds.svg` source, made for this project, MIT) in the project's `Resources/boxart/`, loaded as `boxart.3ds.png` (the csproj already embeds `Resources/boxart/*.png`); `Resources/boxart/README.md` names both SVGs. libretro-thumbnails folder `Nintendo - Nintendo 3DS` is used as for any libretro system.
- **B5 UI.** The system appears everywhere handlers are enumerated (filters, `/api/systems` sorted by `DisplayName`, so between Mega Drive / Genesis and Nintendo 64; Systems tab). ## Risks
- **Large files.** 4 GiB dumps are hashed in one streamed read like Switch/DS (up to 64 GiB already supported); no new memory pressure since `ReadHeader` gets 1 MiB.
- **Most dumps may go to Review** if users have decrypted dumps (common from GodMode9 "decrypt" or Citra-era tooling). Accepted; B3's `productCode` and `mediaId` show in Review's Header card to help pick the DAT entry.
- **Sparse metadata.** Only 40 3DS games have developer/publisher/genre in libretro; the rest show none. Accepted.
- **Fixture churn.** Registering a handler breaks every test that enumerates systems/DATs until updated; step 2 does both in one commit.
- **Broken doc anchors.** Renaming the two external-storage headings breaks their in-doc links unless every link is updated in the same commit (B6 lists them).

## Decisions
- 2026-11-17 Browser play has no EmulatorJS 3DS core → import only, `BrowserCore` null, README Play column `—` (user).
- 2026-11-17 Formats → `.3ds`, `.cci` and `.cia` (user).
- 2026-11-17 Serial matching for decrypted/trimmed dumps → no; Review handles them (user).
- 2026-11-17 Storage → next to the ZIP (`EmbedRomsInZip` false), as requested (user).
- 2026-11-17 `.cci` is kept as `.cci`, not renamed to `.3ds`: every external system keeps the source extension (`IngestPipeline` and `ReviewResolver` T9), and renaming would need new ingest code for one alias (code).
- 2026-11-17 Lives in `RnRomManager.Systems.NintendoDs` as its own `3ds` family, reusing its box-art loader and test project (code; precedent GBA in `Systems.GameBoy`).
- 2026-11-17 Badge colour `#f783ac` with black text, not the 3DS red, which was too close to N64's `danger` red beside it in sorted lists (reviewer).
- 2026-11-17 Docs also cover `deployment.md`, `development.md` and the features ingest-folder list, as the Amiga change did (reviewer).
- 2026-11-17 Size range 16 KiB–4 GiB: the DAT's `.3ds` entries are 128 MiB–4 GiB and its `.cia` entries 126–237 MiB (code: libretro DAT version 2026.11.14).
- 2026-11-17 `MetadatKinds` → `[developer, publisher, genre]`, replacing the earlier `[]`: libretro has those three 3DS metadat files (40 games, all CRCs in the main DAT); only `releaseyear` 404s (user, review pass).
- 2026-11-17 Media unit fixed at 0x200 rather than read from NCSD flags[6]: 3dbrew documents 0x200 for the partition table and retail dumps use it; a non-standard value only loses the NCCH fields (reviewer).
- 2026-11-17 Fixtures use the default No-Intro fixture layout (it writes all four metadat files; the extra `releaseyear` is unused), as for C64, instead of a new `FixtureDatLayout` (reviewer).
- 2026-11-17 Renamed doc headings get every link updated in the same commit (reviewer).
