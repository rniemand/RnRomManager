# Arcade (FinalBurn Neo)

## Summary
Adds a second arcade system, `fbneo`, for Admins who keep FinalBurn Neo romsets (one `.zip` or `.7z` per set). It reuses the Arcade (MAME 2003-Plus) romset path end to end: ingest matches a set archive by its file name (the set name) plus the CRC32s of the files inside it, against the FBNeo arcade XML DAT, and stores the archive byte for byte (never repacked); clones join their parent's game; the release header keeps the set's parent/clone and BIOS links. The only new mechanics are a second romset DAT source, reading CRCs from a `.7z`, and board BIOS sets (`neogeo.zip`, `pgm.zip`, …) loaded from `Paths:Bios` instead of the library. Releases play in the browser with the EmulatorJS `fbneo` core, operator-supplied because FBNeo's licence forbids commercial use.

## Out of scope
- A shared "Arcade" library view, or moving sets between `mame2003` and `fbneo`. The same set name in both systems is two unrelated releases (decision 2026-11-24 of the MAME spec), except that a byte-identical archive is a `Duplicate` (I5).
- The FBNeo console DATs (Mega Drive, PC Engine, MSX, …): only the arcade-only DAT is used.
- Sets that need a CHD, and samples: ingest ignores both, and such games may play without sound effects or not at all.
- Merged sets (a parent ZIP that also holds its clones' ROMs is matched as the parent only), renaming or rebuilding sets, and matching a file whose name isn't a set name by its CRCs alone (all as for MAME).
- BIOS sets from the library at play time: a BIOS set dropped into `ingest/fbneo/` is stored like any set (G1), but play always reads BIOS sets from `Paths:Bios` (P3).
- FBNeo NVRAM, high scores and EmulatorJS save states in the library Saves tab (P4).
- A seeded FBNeo set or an e2e test: shared code is covered by the MAME e2e test; FBNeo gets integration tests and a minimal DAT fixture (decision 2026-11-24).

### Ingest (I)
- **I1** A `.zip` or `.7z` in `ingest/fbneo/` is one ROM file, not an archive to unpack (`ArchiveExtractor.IsArchiveFor` is false because the handler lists both extensions); it takes the external path like a MAME set.
- **I2** Entry list: `IngestPipeline` (the `IngestPipeline.cs:225` block) reads entries with `MameZip.ReadSevenZipEntries(Stream)` (new, same file) when `Path.GetExtension(file.Name)` is `.7z` or `.fbneo7z` (ignoring case), else with `MameZip.ReadEntries` as today. The new reader opens the stream with SharpCompress `SevenZipArchive.OpenArchive(stream, new ReaderOptions { LeaveStreamOpen = true })` (as `ArchiveExtractor` does) and enumerates `archive.Entries` into a list inside the same `try`, reading only headers (no entry is decompressed); it returns each non-directory entry's file name (after the last `/`) and its `Crc` as 8 lower-case hex digits. Errors, returned as today's `(Entries, Error)` tuple; only an `IOException` other than `EndOfStreamException` is thrown:
  - the exceptions `ArchiveExtractor.Guarded` treats as a bad archive, except that only `EndOfStreamException` counts among `IOException`s (any other `IOException` is rethrown and stays `Error IoError`, as for the ZIP reader) — `EndOfStreamException`, `InvalidOperationException`, `NotSupportedException`, `IndexOutOfRangeException`, `ArgumentException`, `SharpCompress.Common.CryptographicException` and any exception whose type's namespace starts with `SharpCompress` — → `not a readable 7z: <exception message>`;
  - any entry with `IsEncrypted` → `not a readable 7z: encrypted`;
  - more than `MameZip.MaxEntries` (4,096) entries → `more than 4096 files in the set 7z`.
  Each fails the file as `InvalidHeader`, as the ZIP reader's errors do. A truncated `.7z` is therefore `InvalidHeader`, not `IoError`.
- **I3** Match: unchanged MAME I3/I4 (`MameMatcher`, file stem = set name ignoring case, every required ROM CRC present). FBNeo's DAT lists a split clone's own ROMs and marks shared ones with `merge`, so a split clone matches alone, as in MAME.
- **I4** No set of that name, or `Incomplete`: Review `NoDatMatch` exactly as MAME I5 (the `missingRoms` header).
- **I5** Dedupe is by the archive's SHA1 across every system, unchanged: an FBNeo archive byte-identical to a release already in the library (e.g. the same `neogeo.zip` in `mame2003`) is `Duplicate`, moved to the duplicates folder, and may self-repair that release as today. It is not stored under `fbneo`, so FBNeo play lists it as `missing` when it is a parent (`/romset` looks only within the system). `docs/features.md` and the Risks say so.

### Identity and grouping (G)
- **G1** A matched set's release: logical `FileName` `<DAT set name><SourceExtension>` (`sf2.fbneoz`, `mslug.fbneo7z`), stored as `<ZipBase>.<set name>.fbneoz|.fbneo7z`. `MameRelease` gets the extension from `system.SourceExtension(file.Name)` instead of the literal `.mamez` (MAME keeps `.mamez`). Everything else is MAME G1: `Identification` `Dat`, `DatName` `FBNeo - Arcade Games`, `DatGameName` the description, a BIOS set (`isbios="yes"`, e.g. `neogeo`) flagged `BIOS`.
- **G2** Header, base title (parent's description), metadata (`<year>`, `<manufacturer>`), AmbiguousGroup and primary release (parents first): MAME G2–G5 and G7, unchanged, through D1's `IsRomset()`.
- **G6** Box art and snaps: libretro-thumbnails folder `FBNeo - Arcade Games` (`DatName`), keyed by the FBNeo description. A miss stores the placeholder; IGDB (S3) fills the gap.

### Romset endpoint (P2)
- **P2** `GET /api/games/{id:guid}/roms/{romId:long}/romset` serves any `IsRomset()` system (D1); other systems stay `404`. The response gains three fields, for both systems:
  - `fileName` (top level and on each `deps` item): the name the core sees, `<setName>.7z` when that release's `FileName` ends in `.fbneo7z` (ignoring case), else `<setName>.zip`. MAME releases are always `.zip`, so MAME play is unchanged.
  - `bios` (top level, `string[]`): for a `Fbneo` system, every set in the `romof` chain (MAME P2's chain, `MameRomset.MaxSteps` = 2) whose DAT set has `IsBios` is taken out of the library lookup and listed here, in chain order, by its DAT name (`neogeo`), never in `deps` or `missing`. For `Mame` it is always `[]` (MAME BIOS sets stay library deps, as today). `selfContained` doesn't empty `bios`.
  - `selfContained` (top level, bool): the release header's `selfContained`, false when absent (a Manual/Attach release). Play uses it for P3's BIOS rule.
  - Example, `kof97h` (clone of `kof97`, which is `romof` `neogeo`) with `kof97` in the library: `{ "setName": "kof97h", "fileName": "kof97h.zip", "deps": [{ "setName": "kof97", "fileName": "kof97.zip", "gameId": "…", "romId": 12 }], "missing": [], "bios": ["neogeo"], "selfContained": false }`.
  - With no loaded DAT: `deps`, `missing` and `bios` are `[]`.

## Risks
- **`DatsMissing` until Refresh DATs** after upgrading (README upgrade note).
- **DAT drift:** one bad row fails the whole FBNeo DAT and keeps the previous set (MAME D2's rules). Step 1 checks today's file.
- **Same-titled parents** share a game (MAME G3); the count for FBNeo isn't known and isn't measured. Move release splits one out.
- **DAT newer than the core:** the DAT is fetched from `master`; the pinned 4.2.3 core is older. A newer set may match but not run.
- **Paths:Bios name clash:** BIOS sets share the folder with other systems' BIOS files; `neogeo.zip` etc. are distinct names, so no clash today.
- **`.7z` headers:** SharpCompress parses a 7z's whole (possibly LZMA-compressed) header before the 4,096-entry check, so a crafted header can make it allocate memory beyond what the file's size suggests; only Admins put files in `ingest/`, and the same exposure exists today in `ArchiveExtractor`'s 7z path. Encrypted or truncated 7z fails `InvalidHeader`.
- **Cross-system duplicates (I5):** a set byte-identical to one in `mame2003` is a `Duplicate` and isn't stored under `fbneo`; documented.
- **Unverified upstream behaviour** (parent and BIOS files beside the game, `.7z` in the core): step 6's manual check with the user's sets; if it fails, stop and ask.
- **Licence:** the core isn't shipped; the operator supplies it, checked against pinned hashes.
