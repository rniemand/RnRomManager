# Play Atari 2600, ColecoVision, Game Gear and Master System

## Summary
Signed-in users get the **Play** button for Atari 2600, ColecoVision, Game Gear and Master System releases, using the EmulatorJS cores `stella2014`, `gearcoleco` and `smsplus` (Game Gear and Master System share it). ColecoVision needs the console's BIOS, which can't be shipped: an operator puts `colecovision.rom` in a new BIOS folder (`Paths:Bios`), and a signed-in endpoint serves it to the play page.

## Out of scope
- Uploading or managing BIOS files in the UI (the operator copies the file into the folder).
- Hiding Play when the BIOS is missing: the play page says what's missing instead.
- Checking a BIOS file's hash or size.
- Any other system or core; `genesis_plus_gx` (non-commercial licence).
- e2e Play checks for the new systems (no real ROMs or BIOS can be committed).

## Behaviour
- **B1** `Atari2600Handler.BrowserCore` is `stella2014`, `ColecoVisionHandler` `gearcoleco`, `GameGearHandler` and `MasterSystemHandler` `smsplus`. `GET /api/games/{id}` and `GET /api/games` report it as `browserCore`, so Play shows exactly as for the existing cores (embedded releases only; all four systems are embedded).
- **B2** `Paths:Bios` (env `Paths__Bios`, default `/app/bios`) is a new storage root, validated, created and probed for writability at startup and checked by `/health/ready` like the others (it's in `PathsOptions.All()`). Backups never include it (they write only database data to `Paths:Backups`); operators copy the folder themselves.
- **B3** `GET /api/emulator/bios/{name}` (any signed-in user; signed out → 401 like every `/api` route) returns the file `<Paths:Bios>/<name>` as `application/octet-stream` with `Cache-Control: no-store` (no range support). `name` must match `^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`. The file is opened with `ExternalRomPath.OpenRead(Paths:Bios, SafePath.Resolve(Paths:Bios, name))`, the repo's link-safe open, which matches the name ignoring case on every OS (`COLECOVISION.ROM` on disk serves `colecovision.rom`). A bad name, an `UnsafePathException`, `Missing`, `Unsafe` (a link or reparse point, a folder, or two files whose names differ only in case) and an empty (0-byte) file return 404 with code `BiosNotFound`, logging a warning for `Unsafe`. `Unreadable` (an IO or permission error) returns 500 `IoError` and logs the error, as `LibraryFiles.OpenExternal` does. Only GET is mapped (HEAD → 405; see Risks). Not audited (downloads never are).
- **B4** `params.js` accepts the cores `gambatte`, `mgba`, `handy`, `virtualjaguar`, `stella2014`, `gearcoleco`, `smsplus`, and exports `biosFor(core)` (`colecovision.rom` for `gearcoleco`, otherwise null) and `biosError(name, status)`, the B5 message for a failed BIOS response (null for a 2xx status).
- **B5** When `biosFor(core)` isn't null, `play.js` fetches `/api/emulator/bios/<name>` (same-origin credentials) before the ROM, as a check; the response body is discarded. Messages (`biosError`): 401 → `Your session has expired. Sign in again.`; 404 → `This system needs its BIOS: ask an Admin to put <name> in the BIOS folder (Paths:Bios).`; another status → `Couldn't load the BIOS (HTTP <status>).`; a network error → `Couldn't load the BIOS.`. On success it sets `EJS_biosUrl` to that URL and goes on as today. EmulatorJS then downloads it again from the server (`no-store`), after the ROM, and writes it next to the ROM under the URL's last segment (`emulator.js:716-717` in 4.2.3), which is the name Gearcoleco looks for (`colecovision.rom` appears in the core's wasm). Cores without a BIOS behave exactly as now.
- **B6** The README supported-systems table's "Play in browser" column shows the new cores for `a2600`, `coleco`, `gg` and `sms` (`SupportedSystemsTableTests` enforces it).
- **B7** A Game Gear release stored as `.sms` (the handler accepts it) may run in `smsplus`'s Master System mode: with its default `auto` hardware setting the core can identify Game Gear games by the `.gg` extension, and a real Game Gear game run as Master System shows the wrong screen size and palette. Not verified without a real ROM. Known limitation, stated in `docs/features.md`.

## Risks
- **BIOS loading in EmulatorJS (verified in 4.2.3 source):** `downloadGameFile` (`emulator.js:702-756`) writes an uncompressed BIOS as `<ROM folder>/<URL's last segment>` (717), and the ROM is downloaded first (925-926). Before the GET it sends a HEAD (724); the endpoint answers 405, `downloadFile` returns -1, and that result is never read because `EJS_disableDatabases` makes the cache lookup return nothing (`emulator.js:282-287`, `storage.js:110-112`), so the GET follows. **`EJS_disableDatabases` must stay `true`**, or the HEAD result is read. A wrong-size BIOS is refused by Gearcoleco itself ("Incorrect BIOS size"). A real-BIOS check is manual (no BIOS in the repo).
- **Licences:** `stella2014` is GPL-2.0 (the repo's `stella/license.txt`), `gearcoleco` GPL-3.0 (its `LICENSE`), `smsplus` GPL-2.0 (`docs/license`), though its readme says its Z80 and YM2413 code come from MAME under the MAME licence (historically non-commercial). Fine for this personal, non-commercial app; the attribution says so.
- **Serving files:** B3 only serves regular files directly inside `Paths:Bios` with a strict name pattern, opened with `ExternalRomPath.OpenRead` (link-safe; 404 rules in B3), to signed-in users.
- **Image size:** three more cores (`-wasm` and `-legacy-wasm` `.data` each, a few MB) in the image.

## Decisions
- 2026-11-13 Game Gear core → `smsplus` (GPL-2.0) rather than EmulatorJS's default `genesis_plus_gx` (non-commercial licence) (user)
- 2026-11-13 ColecoVision BIOS → operator drops `colecovision.rom` into a new `Paths:Bios` folder, served by a signed-in endpoint; play page explains when it's missing (user)
- 2026-11-13 Master System gets Play too, through the same `smsplus` core (user)
- 2026-11-13 Atari 2600 core → `stella2014`, the only 2600 core EmulatorJS ships (code)
- 2026-11-13 A Game Gear release stored as `.sms` plays in Master System mode (wrong screen size/palette for a real GG game) → accepted limitation, noted in `docs/features.md` (reviewer R8, code)
- 2026-11-13 BIOS pre-check fetch + EmulatorJS's own download (double fetch of an ~8 KiB file) → accepted; a blob URL would lose the file name Gearcoleco needs (reviewer R5, code)
- 2026-11-13 BIOS file opened with `ExternalRomPath.OpenRead` (link-safe); empty file → 404 (reviewer R2/R3, code)
- 2026-11-13 BIOS names → matched ignoring case, as `ExternalRomPath` does everywhere (the earlier "case-sensitive on Linux" was wrong) (review, code)
- 2026-11-13 BIOS IO/permission error → 500 `IoError` with an error log, matching `LibraryFiles.OpenExternal`, not 404 (review, code)
- 2026-11-13 EmulatorJS's HEAD before the BIOS GET → leave the 405: harmless while `EJS_disableDatabases` is true; mapping HEAD would add a role-matrix row for nothing (review, code)
- 2026-11-13 BIOS-naming check in step 3 → dropped; verified now against the 4.2.3 source (Risks) (review, code)
- 2026-11-13 smsplus's MAME-derived Z80/YM2413 code (MAME licence) → keep smsplus, list it as GPL-2.0 and note the MAME parts in the attribution (user)
- 2026-11-13 BIOS name map lives in `params.js` (`biosFor`), not in `ISystemHandler`: only the play page needs it, and the endpoint serves any validly named file in the folder (code)
