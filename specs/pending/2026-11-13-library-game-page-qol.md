# Library, Game page and Deleted ROMs quality of life

## Summary
A batch of quality-of-life changes for everyday curation. The Library filter is redesigned as a toolbar of matching dropdowns (system badges, readable names, right-aligned formatted counts), remembered in localStorage with a Reset button, and game cards gain an updates badge and a quick Play button. The Game page's Releases, Images and Zip Contents tabs are tidied. The Review queue gets multi-select delete. A new admin **Deleted ROMs** page lists the ROMs that library edits moved to `ingest/<system>/_removed/`, with permanent delete and restore. Global search gets a bigger modal with richer rows, and three navigation shortcuts are added (plus one for Deleted ROMs).

## Out of scope
- Server-side storage of the Library filter (per-browser localStorage only) and saving several named filters.
- Changing which filters exist (no new filter dimensions), the facets API or its counting rules.
- Showing `_duplicates/` on the Deleted ROMs page; restoring into a specific game (restore goes through ingestion).
- Choosing which release Quick play starts (always the primary release; the Game page's Play buttons stay for others).
- A batch API for review *dismiss* or *resolve*.
- Search ranking or new search sources; search keeps calling the same endpoints.
- Bulk restore of Review items or any undo for permanent deletes.

## Behaviour

### Library filter
- **L1 Toolbar.** The Library filter row becomes one toolbar: search input, then **System**, **Region**, **Letter** and **Sort** dropdowns, the sort-direction button, the Favourites toggle and the Grid/List group (Select mode and "Add to collection…" keep their place after it). Each of System/Region/Letter/Sort is a new `FilterDropdown` component built on a Bootstrap dropdown (`#lib/bootstrap.js`), not a native `<select>`: a `btn btn-outline-secondary btn-sm dropdown-toggle` whose label is the field name plus, when a value is chosen, that value (e.g. `System: Game Boy`); the toggle is `btn-secondary` (filled) while a value is active. All four look the same (same button classes, menu width `min-width: 16rem`, max-height `20rem` with `overflow-y: auto`).
- **L2 Menu rows.** Each menu item is a `button.dropdown-item` with `d-flex justify-content-between align-items-center gap-3`: the option label on the left and its count on the right (`ms-auto text-body-secondary font-monospace`, so counts line up). The "All …" row is first; for System and Letter it shows the sum of that facet's counts, for Region it shows no count (a game counts once per region, so the sum overstates it). While facets are loading or after a failed facets call (counts null) no row shows a count, as `optionLabel` does today. The active option has `active` and `aria-current="true"`. Options with a count of 0 stay listed and clickable (today's behaviour), their row `text-body-secondary`. Sort has no counts.
- **L3 System menu.** Rows show `<SystemBadge system name={shortName} />` then the system's `displayName` (from `/api/systems`, e.g. `Sega 32X` instead of `32x`), sorted by `displayName` as `/api/systems` already returns them. The menu has a filter input at its top (`input.form-control form-control-sm`, placeholder `Filter systems…`, case-insensitive substring on `displayName`, `id`, `shortName`; focus moves into it when the menu opens; Escape closes the menu). `/api/systems` gains `shortName` (`handler.ShortName`, as the game list already returns).
- **L4 Keyboard and a11y.** Bootstrap's dropdown keyboard support (arrow keys, Escape) applies; the toggle has `aria-label="<Field>: <value or All>"`; choosing an option closes the menu and returns focus to the toggle. Axe must pass in both themes.
- **L5 Count format.** Every count shown in these menus and in the active-filter chips is formatted by a new `formatCount(n)` in `src/lib/format.ts`: `n.toLocaleString('en-US')` (`1250` → `1,250`), matching the existing `en-US` uses in `CollectionModal` and `ReleaseNoteModal`. `optionLabel` in `libraryQuery.ts` is removed once nothing uses it (its test cases move to the new component's tests).
- **L6 Active filters.** Below the toolbar, when any of system/region/letter/search/favourite is set, a row of chips (`badge` pills with a `btn-close`-style × button, `aria-label="Remove <field> filter"`) shows each active filter; × clears just that one. At its right end a **Reset filters** button (`btn btn-link btn-sm`) clears every filter, sort and direction back to defaults, page 1, and deletes the saved filter (L7). The row (and so Reset) is hidden when no filter is active and sort/direction/page are at their defaults; a non-default sort alone shows the row with Reset but no chips.
- **L7 Persistence.** New `src/lib/libraryFilter.ts` (same pattern as `reviewFilter.ts`): `saveLibraryFilter(search)` / `readSavedLibraryFilter()` / `clearLibraryFilter()` under key `rnrm.library.filter`, storing the query string produced by `toSearch` (system, letter, region, q, sort, dir, favourite, page), every storage call in try/catch. The Library page saves after every URL change it makes. Save and restore apply only to the root Library page (unscoped), never to collection pages that reuse the query helpers. When the page loads with none of system/letter/region/q/sort/dir/favourite/page in its URL (other parameters don't count; bare `/`: navbar link, `← Library`, `nav.library` hotkey, browser address), it restores the saved query with `goto('?…', { replace: true, reset: false })`; an explicit URL query wins and is then saved. A saved value that `parseFilters` rejects (unknown system, bad page) is dropped silently (the existing parse rules apply). The `libraryView` key is unchanged.

### Game cards
- **C1 Updates badge.** `GET /api/games` items gain `updateCount` (number of the game's roms whose `flags` contains `"Update"`; `JSON_CONTAINS(flags, '"Update"')`, the same test the game-updates migration used). When `updateCount > 0`, the grid card shows a badge at the **bottom left** of the box-art area (`position-absolute bottom-0 start-0 m-1`, `badge text-bg-info`) with `<Icon name="update" />` and the count (`formatCount`), `title`/tooltip and visually hidden text `<n> update(s)`. List view shows the same badge after the title. `romCount` keeps counting every rom (B12 of game-updates is unchanged).
- **C2 Quick play.** `GET /api/games` items gain `playRomId`: the id of the game's primary release (`is_primary = 1`) when the game's system handler has a `BrowserCore` and that release isn't external (`external_file_name IS NULL`), else `null`; `playRomFileName` (that release's `fileName`, else `null`) and `browserCore` (the handler's core or `null`). When `playRomId` is set, the grid card shows a round `btn btn-sm btn-primary` Play button over the box art (bottom right, above the stretched link via `position-relative z-1`), `aria-label="Play <displayTitle>"`, and list view shows a Play icon button in its actions. Clicking opens the existing `EmulatorModal` (one instance on the page): its `rom` prop is narrowed from `RomDetail` to `Pick<RomDetail, 'id' | 'fileName'>` (all it reads, through `playUrl` in `src/lib/emulator.ts`), so the card passes `{ id: playRomId, fileName: playRomFileName }` with `core = browserCore`; no extra fetch. The button is hidden in Select mode. Collections' game grid (`collections/[id]`, which reuses `GameResults`) gets the same badge and button for free.

### Game page — Releases tab
- **R1 Collapsed header.** The release card header keeps only: chevron, file name, Primary/Version/Disc/External badges, region badges, and the Note, Play, Download and Delete buttons. The `Original: …` line, the **Header** button and the **Move** button move into the body.
- **R2 Body layout.** The expanded body is a definition grid: `dl.row.mb-0` with `dt.col-sm-3.col-lg-2.text-body-secondary` / `dd.col-sm-9.col-lg-4` pairs, two pairs per row from `lg` (so labels and values align in columns), one per row below. Rows, in order, each shown only when it has a value: Original file name (`text-break`, with `CopyButton`), Size (`FileSize`), SHA1 / CRC32 / MD5 (monospace, `CopyButton`), Revision, Languages, Flags, Identified by, DAT, Date added, plus existing fields the body shows today (the step keeps every field it shows now; none is dropped). Below the grid, a `d-flex flex-wrap gap-2` action row with `btn btn-sm btn-outline-secondary` buttons: **Header details** (only when `rom.header`; opens the header modal) and, for library editors, **Move release** (opens today's move dialog), both with icon + text.
- **R3 Header modal.** Today's `ConfirmModal` (size `lg`) shows its key/value table as two pairs per row: four columns `Field | Value | Field | Value` (`<th scope="row">` + `<td>` twice per `<tr>`; an odd last pair leaves an empty `<td colspan="2">`). The table keeps the T1–T4 classes (no `<thead>`).
- **R4 Note indicator.** When `rom.hasNote`, the note button is `btn-warning` (filled) with the `note-filled` icon and tooltip `View note`; without a note it stays the outline style with `note` and tooltip `Add note`. The aria-labels stay `Note for …` / `Add note for …`.

### Game page — Images tab
- **I1** The tab's `<h2>Images</h2>` heading is removed; the **Upload image** button stays right-aligned on its own row. A visually hidden `h2` keeps the heading outline (as the Releases tab does).
- **I2 Upload modal.** Source radios become a `btn-group` of two `btn-check` toggles, **URL** (default, selected on every open) then **File**. Type `<select>` becomes a `btn-group` of `btn-check` radios **Box art** / **Screenshot** (default Box art, as today). The URL input or the file input + drop zone sits below, then the type group. Labels, validation messages and the confirm button behave as today.
- **I3 Drag and drop.** The whole modal body is a drop target. Dragging a file over it shows a dashed `border-primary` overlay reading `Drop image to upload`; dropping one file selects **File** as the source and uses that file (as if picked; the existing file checks apply, e.g. type/size errors show as today). Dropping several files uses the first and shows `Only one image can be uploaded at a time; using <name>.` as a form text. Dropping non-files (text, links) does nothing. `dragover`/`drop` call `preventDefault()` only for drags carrying `Files`, so the browser never navigates to the dropped file.

### Game page — Zip Contents tab
- **Z1 Tree.** On load every folder is expanded (the seed set is filled with every folder path after `load()`), and selecting a folder no longer expands anything: only the chevron toggles expansion (so the chevron reflects only what the user toggled). The selected folder's row gets `bg-primary-subtle rounded` plus today's `fw-semibold` and `aria-current="true"`.
- **Z2 Table.** The folder table keeps its columns (Name, Size, Compressed, Modified, Download) and T1–T4 classes; Size and Compressed render as `<span class="badge text-bg-light border"><FileSize …/></span>` (the Library card's size badge style), right-aligned, `text-nowrap`; folder rows show `—` in those cells instead of an empty colspan; Name keeps `text-truncate` with `title`; the download button is a right-aligned `btn-sm` icon button with its aria-label as today.

### Review queue
- **Q1** The page title reads `Review Queue` (the navbar label `Review` is unchanged).
- **Q2 Selection.** The table gains a leading checkbox column (header "select all on this page" with indeterminate state, as `IngestFileTable`). Selection is a `SvelteSet` of item ids, kept across pages of the current filter and cleared when the filter changes or after a delete. A toolbar above the table shows `n selected`, **Clear selection** and **Delete selected (n)** (`btn btn-sm btn-danger`, disabled at 0).
- **Q3 Bulk confirm.** **Delete selected** opens a `ConfirmModal`: `Delete <n> review file(s)?` listing up to 10 file names (`… and <m> more`), and, when any selected item is an archive member, `Archive entries delete their whole archive, including its other pending items.` Shift+click on **Delete selected** skips the modal only when no selected item is an archive member (same rule as the row delete, `review/+page.svelte` `askDelete`); like every Shift+click skip it applies only when the button is enabled (n ≥ 1), and a plain click or Enter always confirms.
- **Q4 Batch endpoint.** `POST /api/review/delete` (Admin), body `{ ids: number[] }`, 1–500 distinct positive ids (else `400 ValidationFailed`, field `ids`). Under **one** job-lock acquisition (`409 JobRunning` when busy, nothing deleted) it runs today's per-item delete (`ReviewResolver` delete path, audit `ReviewDeleted` per file) for each id in order; an id that is no longer `Pending` (e.g. removed with its archive earlier in the batch) counts as `skipped`, not failed. Response `200 { deleted, skipped, failed: [{ id, code }] }` (`code` e.g. `DeleteFailed`). The SPA sends batches of 500 and toasts `Deleted <n> file(s).` plus `<k> couldn't be deleted.` when any failed, then reloads the list and the navbar count. The single-item `DELETE /api/review/{id}` stays.

### Deleted ROMs
- **D1 What it is.** "Deleted ROMs" are the files library edits moved to `ingest/<system>/_removed/` (game/release delete, see `LibraryEditor`): flat files per system, names made unique with ` (2)`… Everything here is Admin only.
- **D2 List API.** `GET /api/ingest/removed` (Admin): per registered system with at least one file, in registry order, `{ system, files: [{ name, sizeBytes, modifiedAt }] }`, top-level regular files only, ordered by name, ignoring dot-files/junk as the other scans do. It reuses the `_failed/` scan (generalised to take the folder; the external-system checked scan included), without the `.error.txt` handling.
- **D3 Page.** `/deleted` (`routes/deleted/+page.svelte`, inside `AdminOnly`), title `Deleted ROMs`. One card per system (header: `SystemBadge` with the system's display name and `formatCount(n) file(s)`), each with an `IngestFileTable`-style table: checkbox, Name (`text-truncate` + `title`), Size (`FileSize`), Removed (`modifiedAt`, `formatDateTime`), and row actions **Restore** (`btn-sm btn-outline-primary` icon button) and **Delete** (`btn-sm btn-outline-danger` icon button). A page toolbar: `n selected`, **Select all**, **Clear selection**, **Restore selected (n)**, **Delete selected (n)**. Selection is keyed `system/name` (`fileKey`). Empty state: `EmptyState` "No deleted ROMs".
- **D4 Permanent delete.** Uses the existing `POST /api/ingest/delete` with a new folder value `removed` (`IngestDeleteRef.Folder`: `pending` | `failed` | `removed`; validation, the ≤500 limit, the job lock and the audit row `IngestFileDeleted` with `Details: "removed"` work as for `failed`; no review rows are touched). Row Delete and Delete selected open a `ConfirmModal` (`Permanently delete <n> file(s)? This can't be undone.`, listing up to 10 names); **Shift+click** on either skips the modal (the Ingestion page's pattern; only when enabled, n ≥ 1). Toast and reload as the Ingestion page (`deleteIngestFiles` reused).
- **D5 Restore.** `POST /api/ingest/restore` (Admin), body `{ files: [{ system, name }] }` (1–500, validated by reusing `IngestFileDeleter.Validate` with each entry mapped to `Folder = removed`; duplicate entries are ignored, as the deleter does; `400 ValidationFailed`, field `files`). Under the job lock (`409 JobRunning`, nothing moved) each file moves from `ingest/<system>/_removed/<name>` to `ingest/<system>/<free name>` (`FileNameRules.FirstFreeIn`, so an existing pending file is never replaced; never overwrite), through `ExternalRomMove` for external systems and `File.Move(…, overwrite: false)` otherwise; a missing source or a failed move is listed in `failed`. Each move records a new audit action `RemovedRestored` (path `ingest/<system>/_removed/<name>`, target path the new pending path). After releasing the lock the endpoint starts an ingest job for exactly the restored files (`IngestJob.Selection`, as `POST /api/jobs/ingest` with `files`). Response `200 { restored, failed: [{ system, name }], jobId }` where `jobId` is null when nothing was restored or the job couldn't start (`DatsMissing` or the lock was taken in between); the files then stay pending and show on the Ingestion page. SPA: Restore / Restore selected (no confirmation), toast `Restored <n> file(s); importing.` with a link to `/jobs/<jobId>` (or `Restored <n> file(s) to Ingestion; import them there.` when `jobId` is null), then reload. After every delete or restore the page calls the layout's count refresh (D6). A bin/cue set must be restored together to ingest as a set; the confirm-free restore doesn't check this (a lone `.bin` goes to Review/Failed as any lone file would).
- **D6 Navbar.** A **Deleted ROMs** link (`/deleted`, icon `delete`, admin only) after Review. When the count is > 0 it shows a `rounded-pill text-bg-secondary` badge with `formatCount(total)` and visually hidden ` deleted`. The layout loads the count from `GET /api/ingest/removed` (sum of files) alongside the review count, on the same triggers (every pathname change, admins with a changed password only), reset on logout. A small store, `src/lib/stores/navCounts.svelte.ts` (the review count moves into it too), exposes `refreshCounts()`, which the Review page (after Q4) and the Deleted ROMs page (after D4/D5) call, since their pathname doesn't change.

### Global search
- **S1 Size.** The search modal's dialog becomes `modal-xl modal-dialog-scrollable` (the M1 options and `releaseModal` rule unchanged).
- **S2 Results.** Collections render first as a horizontal wrap of compact chips (`btn btn-sm btn-outline-secondary`: cover thumb or icon, name, `· <n>` games). Games render as rows: a 48×48 cover thumbnail (`boxArtUrl`, `object-fit: contain`, placeholder `Icon system-<id>`), title (with the matched-on label as today), `SystemBadge` (short name), year, regions, primary size (`FileSize`) and read-only `RatingControl`, laid out as a grid row (`d-grid`, `grid-template-columns: 48px 1fr auto auto auto`) collapsing to title + badge on narrow screens. Games request `pageSize=20` (was 10). Keyboard (arrows, Enter), `listbox`/`option` roles and the "collections then games" option order stay as today.

### Keyboard shortcuts
- **K1** New actions in `Core/Users/Hotkeys.cs` and `src/lib/hotkeys.ts` (same order, appended after `review.next`): `nav.reports` "Go to Reports" `Alt+Shift+R` (role null — Reports is open to every signed-in user, as its navbar link), `nav.integrity` "Go to Integrity" `Alt+Shift+T` (Admin), `nav.admin` "Go to Admin" `Alt+Shift+A` (Admin, goes to `/admin/users` as the navbar link), `nav.deleted` "Go to Deleted ROMs" `Alt+Shift+D` (Admin). A user whose saved overrides already use one of these keys keeps their binding; the table-order duplicate rule already decides which fires, and the shortcuts modal shows the conflict as it does today. Users with stored overrides get the new actions at their defaults (stored JSON holds overrides only; unset actions fall back to defaults). None of the new defaults is in `Hotkeys.Reserved`.

## Risks
- **Permanent delete** is irreversible: confirmation by default, Shift+click opt-out only, Admin only, audit row per file.
- **Restore + ingest** races another job: moves happen under the lock; if the ingest job can't start the files simply wait in pending (D5), so no data is lost.
- **Bulk review delete with archives**: one archive delete removes other selected items; they report as `skipped`, and the modal warns (Q3).
- **Custom dropdowns** replace native selects: keyboard/axe coverage is required in their tests and the e2e axe scans (both themes).
- **List query cost**: two more correlated subqueries per page row (≤100 rows), on indexed `roms.game_id`; acceptable.
- **Navbar count cost**: the deleted count scans every system's `_removed/` (top level only) on each admin route change, next to the review count query; the folders are small and flat, so this is accepted. A count-only endpoint is the upgrade if it shows up in logs.
- **Hotkey collisions** with user overrides: handled by the existing duplicate rule (K1).
