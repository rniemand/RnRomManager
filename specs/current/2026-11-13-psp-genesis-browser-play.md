# PSP, Genesis and Master System browser play

## Summary

Signed-in library users can launch PlayStation Portable UMD images with PPSSPP and Sega Genesis (Mega Drive) cartridges with operator-supplied Genesis Plus GX. Sega Master System already plays through SMS Plus GX. Cover that path with a real browser regression test.

## Out of scope

- New ingestion formats, ROM storage changes, firmware management, and browser support for Sega CD or 32X.
- Automatic downloads or redistribution of Genesis Plus GX by the project.
- An EmulatorJS version upgrade, new save features, or changes to PSX disc packaging.

## Behaviour

- **B1. Discovery.** Existing PSP and Genesis games receive their core from the system handler. Quick Play uses the primary release in both card and table views and stays hidden during bulk selection. Game details offer Play per release. Use the existing JSON fields. Allow external PSP releases in the same list/detail eligibility checks that allow PSX. Genesis Play is visible on installations without the optional core and leads to the setup message in B4. SMS keeps its existing Play actions and modal.
- **B2. PSP content.** Extend authenticated `GET /api/games/{id}/roms/{romId}/play-disc` to stream a standalone external PSP `.iso` byte-for-byte using the measured-length disc response with 200 `application/octet-stream`, `Content-Length`, `Cache-Control: no-store`, and `Accept-Ranges: none`, including when the request sends `Range`. Abort if the file truncates after streaming starts. Apply the existing game/release association, matching system, exact stored name, sole ownership and checked file-open rules. Return 404 for missing, unsafe or disputed files, unrelated IDs, and releases without an external file. Unreadable files return 500 `IoError`. Preserve global 401 and 403 `PasswordChangeRequired` responses. Nonportable or mismatched metadata names, sets, other extensions and empty files return 409 `InvalidPlayDisc`. Bound the opened ISO length at 2 GiB inclusive, covering standard UMD sizes, and return 409 `PlayDiscTooLarge` above it. Keep PSX's 1 GiB cap, statuses, firmware and ZIP behavior. Ordinary downloads keep their current eligibility and limits.
- **B3. PSP player.** Both Play actions open `/emulator/play-psp.html` in a new tab via a `target="_blank"` link with `rel="noopener"` and an accessible name that identifies the game or release and announces the new tab. Serve the dedicated top-level document with COOP `same-origin`, COEP `require-corp`, and the emulator CSP with `frame-ancestors 'none'`. Use the shared player script and styles and leave the SPA and modal headers in place. Require the matching PSP core on the dedicated page and reject PSP on the modal page. Before fetching the ISO, report a clear error for insecure contexts or unavailable cross-origin isolation, SharedArrayBuffer, or WebGL2. Use HTTPS or a browser-trusted loopback origin. Fetch via B2 with same-origin credentials, name the EmulatorJS File from the release name in the validated link using the existing filename sanitization, and show PSP-specific size and invalid-disc errors, the existing expired-session message, or a disc-loading failure. No BIOS request. Set `EJS_threads = true`, force the threaded variant even if saved `ejs_threads` is disabled, and load the PPSSPP build report, `ppsspp-thread-wasm.data` and `ppsspp-assets.zip` from the same origin. Keep the EmulatorJS Start Game action. Core and asset requests follow that click. Handle PSP asset request failure and rejected ISO body or File-to-ArrayBuffer reads with a visible startup error. The pinned loader can leave startup promises pending on these failures. Scope these failure-handling changes to PPSSPP. Closing the tab stops playback.
- **B4. Genesis delivery.** Add optional `Emulator:GenesisCorePath` (`Emulator__GenesisCorePath` in Docker), a fully qualified directory supplied by the deployment operator. Include it in the existing Admin-only effective settings, startup log and diagnostic settings snapshot. Blank means disabled. A relative configured path fails startup validation. A missing absolute mount behaves as unavailable without failing startup. The read-only mount contains the EmulatorJS 4.2.3 files `genesis_plus_gx-wasm.data`, `genesis_plus_gx-legacy-wasm.data` and `genesis_plus_gx.json` at its root. Match URL names ordinally and serve just these names via authenticated `GET /api/emulator/genesis/{name}` using the checked read pattern from the BIOS endpoint. Serve `.data` as `application/octet-stream` and the report as `application/json`. Missing, empty, unsafe and unlisted files return 404, and unexpected read errors return 500 `IoError`. The server pins each file's exact length and SHA-256 (the 4.2.3 values below) in one manifest that tests can replace. GET checks the opened file's length first, reads exactly that many bytes into memory, verifies the hash, and serves those verified bytes, so a file swapped after the check is never served. A wrong length or hash returns 409 `GenesisCoreMismatch`. Support an authenticated `HEAD /api/emulator/genesis` availability check that opens, verifies and disposes all three regular files. It returns 204 when all three are safe, non-empty and match, 404 when disabled or incomplete, 409 when any present file mismatches, and 500 for an unexpected read error. Log which file mismatched. Check this before fetching a ROM or starting the loader. Report missing setup with the configuration name, report a mismatch as files that don't match EmulatorJS 4.2.3 and need replacing, map 401 to session expiry, and show a core-loading error for other failures. The checked resolver for both handlers rejects ambiguous on-disk case variants. GET returns the entire file even when the request sends `Range`. Both handlers set no-store, including availability failures. HEAD is bodyless and only checks that the set is available and matches. Both routes inherit 401 and 403 from the API auth policy. The operator supplies a trusted, matching 4.2.3 set from the upstream release. The `@emulatorjs/core-genesis_plus_gx@4.2.3` npm package has the two payloads at its root and the report under `reports/`, so the operator copies the report to the mount root. The pinned values are `genesis_plus_gx-wasm.data` (1,203,661 bytes, SHA-256 `190297a6f86757405090f1a2266f67dfe1a570a528c583434ed3641a5664f768`), `genesis_plus_gx-legacy-wasm.data` (1,204,803 bytes, `2a1edeb68d7ec882149ed3cd5d3aa95a6ac231ebabaf82cdb56175a8b62967cc`) and `genesis_plus_gx.json` (129 bytes, `5936a8ce8d7f010d5bfdd8c3bba2b2414f103b3a703121e56f2724b24dbe7ff3`). EmulatorJS runs JavaScript embedded in the payload with the app origin. Keep the mount outside the web root and unavailable to application uploads. The hash check rejects corrupt, other-version or altered files before any byte reaches the browser.
- **B5. Genesis player.** Route `.md`, `.gen` and `.bin` through the existing authenticated cartridge download and modal. Allow the explicit `genesis_plus_gx` core in the play link. Pin it in the guarded vendoring edit and hide the core chooser so a saved alternate core cannot replace it. Set the `segaMD` control scheme explicitly because upstream resolves the core's first group to `segaMS`. In 4.2.3 that scheme gives the Mega Drive virtual gamepad (A, B, C, X, Y, Z, Mode and Start). The Controls menu has no `segaMD` labels and lists the generic RetroPad buttons, and the default keyboard mapping does not change. Leave `EJS_disableCue` unset, because the pinned loader already skips automatic cue generation for `genesis_plus_gx`. Map the three asset basenames to the B4 same-origin URLs through `EJS_paths`. Keep WebGL2/legacy selection and force nonthreaded Genesis variants even if an isolated context has a saved thread setting. Show a local core-loading error if the selected payload cannot be fetched after HEAD. A failed report fetch stays non-fatal, as upstream: the 4.2.3 Genesis report has empty `options`, so the selected variant is the same without it. Skip the upstream remote payload fallback for Genesis and keep the existing same-origin CSP. Preserve the current database and save settings. Neither the image nor the npm lockfile contains the operator's core.
- **B6. Master System.** A stored `.sms` release plays with the bundled `smsplus` and the Master System controls. The saved core preference cannot switch it to Genesis Plus GX. Verify this both with Genesis assets absent and with the pinning regression test. Game Gear continues to use the existing filename-based control scheme.

## Risks

- PPSSPP requires WebGL2, a secure isolated top-level page and enough memory to load the ISO. Confirm an actual boot with the 4.2.3 build and a redistributable or locally supplied lawful bootable ISO before opening the PR. The synthetic Playwright ISO proves request handling and startup wiring only. While `EJS_gameUrl` still references the fetched Blob, the pinned loader briefly holds three full copies of the image: the File's ArrayBuffer, its own `Uint8Array` copy and the Emscripten filesystem file. A 1.8 GB dual-layer image can therefore need about 5–6 GB in the tab. The 2 GiB server limit bounds the transfer. Successful playback depends on browser memory and the core. Record the browser, platform and ISO size for the known-good boot. Record a representative dual-layer-size boot if available, or mark that size unverified. If 4.2.3 fails to boot the known-good sample, raise a scope or version decision before enabling PSP. In the same check, record whether PPSSPP in-game saves survive closing and reopening the tab, and document what you observe.
- PPSSPP assets have their own provenance and notices. The exact 4.2.3 npm tarball contains only the threaded payload (4.6 MB), build report (`defaultWebGL2` and `requireThreads` both true) and asset ZIP (10.9 MB). It has no licence file, so the payload's own `license.txt` is the core notice. The asset ZIP has 166 entries (about 19.6 MB unpacked) and no top-level notice. It contains `flash0/font/*.pgf` fonts, a bundled web debugger with its own `LICENSE.txt`, `gamecontrollerdb.txt`, shaders, translations and VFPU tables. Trace each to PPSSPP's `assets/` at the core's source revision. Review the payload and asset ZIP license texts and source revisions before bundling. [EmulatorJS 4.2.3 core artifacts](https://cdn.emulatorjs.org/4.2.3/data/cores/)
- Genesis depends on the operator supplying compatible files and following their upstream terms. Verify an actual boot with privately provisioned 4.2.3 assets before opening the PR. Automated tests use synthetic assets with a replaced manifest for delivery/wiring and avoid publishing the restricted binary. The pinned hashes come from the npm package; whether the CDN copies are byte-identical is unverified, so the docs name the npm package as the source. [EmulatorJS Mega Drive cores](https://emulatorjs.org/docs/systems/sega-mega-drive/) · [Libretro core licenses](https://docs.libretro.com/development/licenses/)
- Scope isolation headers to the dedicated PSP document, so cross-origin isolation does not affect the SPA or its existing modal flows. [Cross-origin isolation requirements](https://developer.mozilla.org/en-US/docs/Web/API/Window/crossOriginIsolated)

## Decisions

- 2026-11-13 Master System core → retain the existing SMS Plus GX integration and add real browser coverage (code).
- 2026-11-13 Genesis core delivery → operator-supplied Genesis Plus GX (user).
- 2026-11-13 PSP launch → isolated top-level tab with the authenticated disc path and a 2 GiB ISO limit (design).

- 2026-11-13 Browser verification → observe real core requests after Start Game and distinguish PSP boot sizes from the server transfer limit (pinned player behavior).
- 2026-11-13 Genesis deployment → use the existing effective settings projection and a bodyless HEAD check of the operator's 4.2.3 files (code and design; hash verification added below).

- 2026-11-13 Genesis report and cue → a failed report fetch stays non-fatal, and the loader's built-in cue skip is used without `EJS_disableCue` (pinned 4.2.3 loader and report).
- 2026-11-13 Genesis asset source → document the npm package layout and its file lengths and SHA-256 values (pinned package).
- 2026-11-13 Genesis asset integrity → the server verifies each file's pinned length and SHA-256 before serving it, and answers 409 `GenesisCoreMismatch` (bodyless 409 on HEAD) for a mismatch (user).
- 2026-11-13 PSP steps → split library linking from player startup to keep each step within the step-size rule (spec rules).
- 2026-11-14 Step 2 test locations → the options registration and effective settings tests live in `RnRomManager.Api.Tests`, not `RnRomManager.Core.Tests`; the step names the real files (code).
- 2026-11-14 PPSSPP asset ZIP → bundle the upstream ppsspp-assets.zip unchanged, although its flash0/font/*.pgf files are Sony PSP firmware fonts with no published licence; ppsspp-NOTICE.txt records their provenance and the trace of the archive to EmulatorJS/ppsspp 47efdd0 (user).
- 2026-11-13 Game Gear coverage → add a real-player e2e start, because the shared pinned-core edit changes and no Game Gear player test exists (code).
