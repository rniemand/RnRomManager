# Play NES and PlayStation in the browser

## Summary
Signed-in users can launch NES and PlayStation releases from the library grid, library list or game detail. Use EmulatorJS 4.2.3 with its default cores for these systems. PlayStation launches one stored disc at a time, including the cue sheet and all tracks when present.

## Out of scope

- Nintendo 64 browser play is deferred pending a redistributable build and browser verification.

- New import formats, disc conversion, and in-session swapping between releases of a multi-disc game.
- BIOS uploads, bundled firmware, alternative cores, and emulator version upgrades.

## Behaviour

- **B1** Map `nes` to `fceumm` and `psx` to `pcsx_rearmed`. NES uses the stored headered `.nes` through the current release download path and requires no BIOS. The game detail offers Play per eligible release. Quick Play uses the current primary release only, including an external primary for PSX. NES requires embedded releases. External releases of other systems remain ineligible. The existing list/detail fields and query parameters carry the launch.
- **B2** Add authenticated `GET /api/games/{id}/roms/{romId}/play-disc` for PSX. Verify the release belongs to the specified game and the handler is PSX. A standalone external `.bin` or `.iso` streams unchanged. The shipped JS core manifest omits ISO, but EmulatorJS 4.2.3 falls back to the sole filename and the native core advertises ISO and detects MODE1/2048 cooked sectors. [Pinned native extensions](https://github.com/EmulatorJS/pcsx_rearmed/blob/f29871d/frontend/libretro.c#L1053-L1062) [Pinned sector detection](https://github.com/EmulatorJS/pcsx_rearmed/blob/f29871d/libpcsxcore/cdriso.c#L1486-L1508). For a set, stream an uncompressed ZIP containing one cue and all its BIN tracks at archive root, including the release's main track. Before opening files, require portable case-insensitively unique archive leaf names and validate shape: one cue, 1–99 BINs including the main file. After opening the cue, require one-to-one coverage of all stored tracks by its distinct FILE names, within the selected release. Reuse the ingestion cue grammar, UTF-8/BOM and Latin-1 decoding, 64 KiB bound and portable leaf-name checks. Build playback-only ZIP names using the stored cue basename with a lowercase .cue extension and short ASCII track names track-01.bin through track-99.bin, assigned in original FILE order. Map case-insensitive source names to those aliases and emit canonical quoted FILE lines with BINARY. Keep a release-specific cue basename so different releases do not share a fixed-name save. Emit UTF-8 without BOM and LF line endings. Emit only FILE, TRACK, INDEX and PREGAP, which the pinned parser reads. Normalize their keywords and mode tokens to uppercase and separate tokens with ASCII spaces, preserving track order, modes, index positions and pregap values. Omit other metadata. Reject non-BINARY FILE types and repeated case-insensitive FILE blocks. Require at least one TRACK per FILE and an INDEX 01 per TRACK; accept INDEX 00 and PREGAP without reordering them. Require consecutive track numbers 01–99, valid MM:SS:FF positions (seconds 00–59, frames 00–74), and raw BIN track modes (AUDIO, MODE1/2352 and MODE2/2352). The parser computes each cue FILE length assuming 2352-byte sectors. Cooked MODE1/2048 remains supported through standalone ISO. Reject malformed playback commands and any emitted line longer than 254 bytes excluding LF. Support multiple TRACKs under one FILE. [Pinned PCSX cue parser](https://github.com/EmulatorJS/pcsx_rearmed/blob/f29871d/libpcsxcore/cdriso.c#L342-L505). Keep original cue and track files byte-for-byte on disk. Resolve the selected release through the game-scoped ROM lookup. Use ListFilesByGameAsync filtered by RomId and load external claims once. For same-game collisions count claims for the case-insensitive external leaf name; its selected row must be the sole matching claim, including for main ROMs whose claim lacks a FileId. Require each FileSets member name to equal its external filename as in info.json, and reject duplicate claims from other releases of the same game as well as conflicting games in the same folder. Reuse LibraryFiles.OpenExternal for checked opens. Open and validate every member before starting the response. Own every pre-opened handle through result execution and dispose it on validation failure, cancellation, write failure, or if the result never executes. Copy at most each measured member length, abort the response if a member shrinks or streaming otherwise fails after headers, and propagate request cancellation through the copy. Return application/zip for a set and application/octet-stream for a standalone image. Range requests receive the full payload. Set `Cache-Control: no-store` on success and endpoint errors; no persistent archive or audit event. Use .NET 10 asynchronous ZIP create, entry open, copy and finalization with UTF-8 entry names and no compression. Stream to Kestrel without buffering disk images on the server or enabling synchronous response IO.
- **B3** The disc endpoint returns 404 `NotFound` for wrong game, release, system, missing, unsafe or conflicting member, 500 `IoError` for an unreadable member before headers, 409 `InvalidPlayDisc` for malformed or inconsistent disc metadata or cue contents, and 409 `PlayDiscTooLarge` if the combined opened lengths exceed 1 GiB. Reject empty members as invalid. Use the authenticated API group's existing anonymous and password-change responses. The limit covers a standard single CD while bounding browser memory. The list and detail buttons use library metadata and the endpoint checks current files on launch.
- **B4** For `pcsx_rearmed`, the play page fetches `play-disc` and uses the endpoint's bytes with a File named from the selected release (the existing filename sanitization applies to the File wrapper only). Keep the release name as `EJS_gameName`. For a standalone BIN named scph5501.bin, ignoring case, use a virtual name scoped to the game ID and original filename so the BIOS write cannot overwrite the image. The archived BIN aliases likewise reserve the BIOS leaf. In 4.2.3, compressed content is unpacked into the runtime filesystem and a supplied cue takes priority for a cue-plus-BIN archive. Display the existing session-expiry message for 401, a specific disc-too-large or invalid-disc message for the corresponding problem code, and a disc-loading message for other HTTP/network failures. Do not start the loader on any such failure. PlayStation optionally uses operator-supplied scph5501.bin through the existing authenticated BIOS endpoint. A 404 uses HLE. A 401 uses the session-expiry message. Other HTTP failures or a network or body-read failure show the BIOS load error and stop before fetching content. Use one same-origin GET and read its body with a 512 KiB bound. Cancel on excess and reject a short or oversized file before fetching the disc. Display a message that names the expected 512 KiB scph5501.bin. Pass the validated ArrayBuffer as EJS_externalFiles["/scph5501.bin"]. The pinned GameManager writes a direct file key before loading content, and RetroArch finds it in the root content directory. A disposable probe of the pinned JavaScript passed an ArrayBuffer to the direct file key and verified the exact bytes and path. This avoids a second BIOS request and the pinned BIOS downloader's archive detection. In a disposable probe, both pinned PCSX WASM variants with the app RetroArch config selected a synthetic 512 KiB placeholder at this path and selected HLE without it. The placeholder verified lookup only. Confirm real firmware boot in Auto and a separate real HLE boot. Preserve the saved explicit HLE option. [Pinned directory lookup](https://github.com/EmulatorJS/RetroArch/blob/6dd4353/runloop.c#L1939-L1972). ColecoVision retains its required BIOS. Firmware is never bundled. [PCSX ReARMed BIOS and HLE](https://docs.libretro.com/library/pcsx_rearmed/).

## Risks

- EmulatorJS reads and unpacks the disc in browser memory before boot. The 1 GiB cap bounds input, and enough free memory is still needed for multiple runtime copies. Document this for mobile and large discs.
- The pinned PCSX parser is case-sensitive, splits on ASCII spaces and reads 256-byte lines. Test the playback normalization against case differences, tabs, CR-only input, long UTF-8 names and names with spaces and #. Verify that a disc with audio tracks boots through the cue, check audio, and confirm that two releases keep distinct browser saves across reopen.
- Browser graphics support and BIOS compatibility depend on the actual pinned WASM builds. Record playback and firmware lookup results. Use legally redistributable playable fixtures or operator-supplied dumps separate from repository fixtures. If Step 1 cannot verify source provenance or component terms, report the specific missing evidence before committing vendored packages.

- **NES and PSX source evidence.** The pinned FCEUmm core source and PCSX readme and libretro header explicitly allow GPLv2 or later. Check their linked component terms separately. The PCSX binary probe identifies P.E.Op.S. as the selected renderer, and its source also permits later versions. Audit the actual Emscripten build inputs and notices, including any linked disc library and dependencies, before declaring the combined binaries cleared. [FCEUmm source](https://github.com/EmulatorJS/libretro-fceumm/blob/d9d7e141274d07186b6a871ca2919b6f13cfb2f9/src/fceu.c) [PCSX readme](https://github.com/EmulatorJS/pcsx_rearmed/blob/f29871dde1742cafb0ab56ba33636a8600bbbd80/readme.txt#L450) [P.E.Op.S. source](https://github.com/EmulatorJS/pcsx_rearmed/blob/f29871dde1742cafb0ab56ba33636a8600bbbd80/plugins/dfxvideo/gpu.c).

## Decisions

- 2026-11-13 Use the two default cores documented by [EmulatorJS](https://emulatorjs.org/docs4devs/cores/), pinned like the existing integrations.
- 2026-11-13 A PSX release represents one disc; send its full set and present each disc as a separate launch, following the current library model.
- 2026-11-13 Use optional operator-supplied `scph5501.bin` with the core's built-in HLE fallback, keeping the current BIOS directory and permissions.

- 2026-11-13 Review of the pinned PCSX source → canonicalize the playback-only cue and alias its BIN members, keeping stored data and cue save identity. Reserve the firmware leaf for both packaged sets and standalone launches. Keep native standalone ISO playback, and verify cooked ISO separately.
- 2026-11-13 Review of npm payloads → retain the embedded licences and verify component terms and exact corresponding source before distribution.

- 2026-11-13 Review of the pinned runtime → record WebGL2 and legacy variant selection separately from game output, preserve the app's production CSP, and confirm firmware mode through the core log.

- 2026-11-13 Runtime review selected a single BIOS fetch and the pinned direct-file handoff. Both PCSX variants locate firmware at the content root using the existing RetroArch config.

- 2026-11-13 User deferred Nintendo 64 from this release. Mupen64Plus-Next has an unresolved GLideN64 compatibility question, and the stock ParaLLEl build includes glN64 with an unverified original grant. A Glide64-only ParaLLEl rebuild is a candidate for separate review. [GLideN64 notice](https://github.com/EmulatorJS/mupen64plus-libretro-nx/blob/c35e55e87cbaa4cfc8355d8f91ceaa2beb212e9d/GLideN64/LICENSE) [ParaLLEl build rules](https://github.com/EmulatorJS/parallel-n64/blob/56f4daf8ec9b00d51d7db88e3c34c381294dbde0/Makefile#L471-L492) [glN64 licensing audit](https://www.emutalk.net/threads/licensing-for-gln64.45564/).

- 2026-11-13 Step 1 audit → FCEUmm's compiled `src/boards/emu2413.c` (Okazaki's 2001-2002 YM2413, modified 2004) has no in-file grant; record it under the author's MIT licence (Copyright (c) 2001-2019 Mitsutaka Okazaki, digital-sound-antiques/emu2413). Both cores and RetroArch link Emscripten's zlib port (`-s USE_ZLIB=1`), now noted in COMMON-BUILD.txt. Header-less project files are taken under each project's GPL-2.0-or-later.
- 2026-11-13 Step 2 → the pinned parser lets every INDEX overwrite the track start and applies PREGAP to the next INDEX, so the playback cue accepts per TRACK only an optional INDEX 00, then one INDEX 01, and at most one PREGAP before INDEX 01; INDEX 02+ and other orders are malformed (409). TRACK, INDEX and MM:SS:FF fields take one or two digits and are written with two; the first TRACK must be 01.
- 2026-11-13 Step 3 → .NET 10's async ZIP entry dispose still writes the data descriptor synchronously on an unseekable stream, which fails with synchronous response IO disabled. `AsyncOnlyWriteStream` holds such synchronous writes (bounded at 1 MiB) and sends them ahead of the next asynchronous write or flush, so the response only sees async IO and nothing is buffered beyond descriptors and the central directory. A FileSets name that differs from its external name is `409 InvalidPlayDisc` (inconsistent metadata); ambiguous claims are `404`. Shrinkage, growth and cancellation are unit-tested through `PlayDisc.CopyMeasuredAsync`, since an open handle can't be truncated in an integration test on Windows.
- 2026-11-13 Step 4 → the real-content PSX boot probe moves to Step 5 (user's choice): the repo has no bootable PlayStation content, firmware can't be downloaded, and Step 5 needs the same user-supplied disc and BIOS for its raw BIN, ISO and cue-set boots. Step 4 is verified by the play-page unit tests.
