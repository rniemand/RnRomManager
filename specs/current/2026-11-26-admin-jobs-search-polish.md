# Admin, Jobs and search polish

## Summary
A batch of Admin-facing fixes and polish: a tidier ROM Zip Config table (size column, one Storage column with an inline switch, clickable level badges), IGDB actions that skip games already handled (with opt-in flags for the old behaviour), a Running time column and button-style links on Jobs, a Jobs link in the user menu, a resume button that loads save *states* only, IGDB link and rating in Global search, an always-visible modal footer, and a Lookup Info shortcut on the game page.

## Out of scope
- A running time on the Running table or the job detail page (the Recent jobs list only).
- Backfilling `actions.coverImageChecked` or the new state-save counts for existing games (they fill on each game's next write; see B-rules for the fallbacks).
- Any change to which IGDB data is pulled, or to the Saves tab's own load flow.

### Actions tab (`/admin/actions`)
- **AC1** `info.json` gets `actions.coverImageChecked` (string?, same format and validation as `coverImagePulled`: round-trip UTC, whole seconds, via `InfoJsonActions.Format`/`Parse`; validator message `actions.coverImageChecked must be an ISO-8601 time`). It is optional and written inside `actions`, so it needs no schema version (as `coverImagePulled`). `actions` is dropped on write when both values are null (`InfoJsonSerializer.Serialize`'s check becomes `{ CoverImagePulled: null, CoverImageChecked: null }`); otherwise both keys are written, an unset one as `null`, because the serializer writes nulls (`JsonIgnoreCondition.Never`). Older apps ignore the unknown key on read and drop it on their next write. Changing or clearing `igdbId` already drops `actions` (`LibraryEditSupport`), which clears it too.
- **AC2** Migration `0030_game_cover_checked.sql` (new) adds `game_actions.cover_image_checked_at DATETIME(6) NULL`. `LibraryMirror` replaces its per-game `cover_image_pulled_at` statement with one that handles both: when either value is set, `INSERT INTO game_actions (game_id, cover_image_pulled_at, cover_image_checked_at) … ON DUPLICATE KEY UPDATE` both columns; when neither is, `UPDATE game_actions SET cover_image_pulled_at = NULL, cover_image_checked_at = NULL WHERE game_id = @Id`. The IGDB columns stay untouched. Existing rows start NULL.
- **AC3** Integrity's action check (A5, `ZipIntegrityCheck.CheckActionsAsync`) compares both times: `IGameRepository.ListCoverPulledAsync` is replaced by `ListCoverActionsAsync` (new) returning `IReadOnlyDictionary<Guid, (DateTime? Pulled, DateTime? Checked)>` (UTC) with one entry per `game_actions` row that has either value (the existing `ListCoverPulledAsync` assertions in `IntegrityJobTests.Cache` move to it); `ZipIntegrityCheck.Pulled` is renamed `CoverActions` with that type, and both `IntegrityJob` call sites set it; a mismatch in either (whole seconds) re-mirrors the game and records `DbRowUpdated`, as today.
- **AC4** **Pull Cover Images** default run processes IGDB-linked games with neither `cover_image_pulled_at` nor `cover_image_checked_at`. With **Try Missing Images** it processes linked games without `cover_image_pulled_at` (today's logic, checked games included). `PullCoversJob` gets `public bool RetryMissing { get; set; }` (set by the endpoint on the transient job), and `IGameRepository.ListPullCoverCandidatesAsync(bool includeChecked, CancellationToken)` (new parameter).
- **AC5** When a pull fails on the IGDB side, the job still writes the ZIP with `actions.coverImageChecked = now` (plus `metadata.updatedAt`/`appVersion`, through `LibraryZipWriter` exactly as a pull writes, then mirrors). IGDB-side failures: `NoCover`, `ImageLimit`, `Error`/`ImageUnreadable`, and `Error`/`DownloadFailed` **only when `IgdbCoverDownload.Status` is 200 (image over the size limit) or 4xx** (a null status, i.e. network error or timeout, or a 5xx counts towards the breaker and is not recorded, so an outage never marks games). Not recorded: `Skipped` games, ZIP open errors, and write/DB errors of the pull itself. The job item keeps the original outcome; if the checked write itself fails, a warning is logged and the outcome is unchanged (the game is simply tried again next run). The checked write records no audit event (nothing was fetched). A `RetryMissing` run that fails again rewrites `coverImageChecked` with the new time. A default (not `RetryMissing`) run that finds `coverImageChecked` already in the ZIP but not in the database re-mirrors and returns `Skipped` (`The cover was already checked.`), as the pulled case does. A successful pull leaves any `coverImageChecked` as it is.
- **AC6** **Refresh IGDB Ratings** default run processes linked games whose `game_actions.igdb_rating` is NULL (no row, or no rating stored, including games IGDB has no rating for). With **Repull ALL Ratings** it processes every linked game (today's logic). `IgdbSyncJob` gets `public bool All { get; set; }`; `IGameRepository.ListIgdbLinkedAsync(bool missingRatingOnly, CancellationToken)` (new parameter).
- **AC7** API: `POST /api/jobs/pull-covers?retryMissing=true` and `POST /api/jobs/igdb-sync?all=true` (Admin, as today). Both bind as `bool?` route parameters (`bool? retryMissing`, `bool? all`; null means false), as `AuditEndpoints` binds `scheduled`; a non-boolean value is the framework's 400. All other responses (202, 409 `JobRunning`, 409 `IgdbNotConfigured`) are unchanged.
- **AC8** `GET /api/admin/actions` returns `{igdbConfigured, igdbLinked, coversPending, coversMissing, ratingsMissing, lastIgdbSyncAt}`: `coversPending` now counts linked games a default pull would process (neither time), `coversMissing` (new) those without a pulled time, `ratingsMissing` (new) linked games with no stored rating. `GameActionsSummary` becomes `(int IgdbLinked, int CoversPending, int CoversMissing, int RatingsMissing, DateTime? LastIgdbSyncAt)` (only `GameRepository` constructs it).
- **AC9** UI, Pull Cover Images card: text `Downloads the IGDB cover of every linked game that hasn't been tried yet and makes it the game's cover, replacing the current cover.`; under the count a `Checkbox` (`id="pull-retry-missing"`, label `Try Missing Images`, disabled like the button) followed by `<div class="form-text">Also retries games whose IGDB cover couldn't be pulled before.</div>`. The count line and the confirmation modal's `count` use `coversMissing` while ticked, else `coversPending`. Starting posts with `?retryMissing=true` only when ticked. The box keeps its value after a start.
- **AC10** UI, Refresh IGDB Ratings card: text `Fetches the IGDB rating and vote count of every linked game without a rating.`; count line `{n} game(s) to process · last refreshed …`, or `· never refreshed` when `lastIgdbSyncAt` is null, as today (`plural(n, 'game to process', 'games to process')`, n = `igdbLinked` while ticked, else `ratingsMissing`); a `Checkbox` (`id="ratings-all"`, label `Repull ALL Ratings`, disabled like the button) and `<div class="form-text">Refreshes every linked game, including ones that already have a rating.</div>`. Starting posts with `?all=true` only when ticked.

## Risks
- **Extra ZIP writes:** AC5 rewrites a game's ZIP on an IGDB-side failure: once for default runs (they then skip it), and again on each **Try Missing Images** run that fails for it. Same writer, verification and atomic replace as a pull.
- **Outage marking games:** avoided by recording `DownloadFailed` only on a 200 (oversize) or 4xx answer (AC5).
- **ROM Zip Config load cost:** RZ2 runs `ListSystemSizesAsync` (per-game subqueries over the whole library) on each page load and job end, as the Library size report already does; acceptable at library scale, no caching added.
- **Stale counts after upgrade:** `state_count` is NULL until a game's next write, so SV2 falls back to today's behaviour for those rows; `coversPending` starts equal to `coversMissing` until runs record checks.
- **Every modal now scrolls its body:** a body that fits shows no scrollbar; the body gains one extra tab stop (the WCAG fix for a scroll region). The emulator modal already fits the viewport.
