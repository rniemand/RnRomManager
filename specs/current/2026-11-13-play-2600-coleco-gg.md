# Play Atari 2600, ColecoVision, Game Gear and Master System

## Summary
Signed-in users get the **Play** button for Atari 2600, ColecoVision, Game Gear and Master System releases, using the EmulatorJS cores `stella2014`, `gearcoleco` and `smsplus` (Game Gear and Master System share it). ColecoVision needs the console's BIOS, which can't be shipped: an operator puts `colecovision.rom` in a new BIOS folder (`Paths:Bios`), and a signed-in endpoint serves it to the play page.

## Out of scope
- Uploading or managing BIOS files in the UI (the operator copies the file into the folder).
- Hiding Play when the BIOS is missing: the play page says what's missing instead.
- Checking a BIOS file's hash or size.
- Any other system or core; `genesis_plus_gx` (non-commercial licence).
- New Playwright Play checks for these systems. Use synthetic fixtures for API and play-page tests and operator-supplied files for manual playback.

## Behaviour
- **B1** `Atari2600Handler.BrowserCore` is `stella2014`, `ColecoVisionHandler` is `gearcoleco`, and `GameGearHandler` and `MasterSystemHandler` are `smsplus`. `GET /api/games/{id}` and `GET /api/games` report the handler's `browserCore`. The game detail offers Play for embedded releases. Library quick Play still requires an embedded primary release and uses the existing `playRomId` and `playRomFileName` fields. All four handlers use embedded storage.
- **B2** `Paths:Bios` (env `Paths__Bios`, default `/app/bios`) joins `PathsOptions.All()`. It must be absolute, distinct and non-nested like the other roots. Startup creates it and probes it for writability. `/health/ready` checks that it exists. The effective configuration logged at startup and returned by Admin `GET /api/admin/settings` includes `paths.bios`. The app's database backups exclude this folder. Operators back it up separately.
- **B3** `GET /api/emulator/bios/{name}` serves an ordinary signed-in user. A signed-out request matching the GET route gets 401 `Unauthorized`. The existing forced-password-change gate returns 403 `PasswordChangeRequired` for a flagged session before either GET or HEAD. HEAD is unmapped and otherwise hits `FallbackEndpoints` (404, empty body). The GET handler sets `Cache-Control: no-store` on every response it produces. Match the whole leaf name with `\A[A-Za-z0-9][A-Za-z0-9_.-]{0,63}\z` and reject trailing dots so Windows cannot normalize a different leaf. Resolve it with `SafePath.Resolve(Paths:Bios, name)` and read it with `ExternalRomPath.OpenRead`. On Windows and Linux this matches disk spelling ignoring case and rejects links, reparse points, non-regular entries and case collisions below the configured root. Invalid names, `UnsafePathException`, `Missing`, `Unsafe` and empty files get `Problems.NotFound` (404 `NotFound`). Log a warning for `Unsafe`. `Unreadable` gets 500 `IoError` with a BIOS-specific message and an error log, following the convention in `LibraryFiles.OpenExternal`. Dispose the open stream on the empty-file path. On success, hand the checked stream to `Results.Stream` as `application/octet-stream` with range processing disabled. The response owns the stream. The download has no audit event.
- **B4** `params.js` accepts the existing `gambatte`, `mgba`, `handy`, `virtualjaguar`, `beetle_vb`, `a5200` and `prosystem` plus `stella2014`, `gearcoleco` and `smsplus`. It exports `biosFor(core)` (`colecovision.rom` for `gearcoleco`, otherwise null), `biosError(name, status)` (the B5 HTTP messages, null for 2xx) and `controlSchemeFor(core, name)` (B8: `segaGG` for `smsplus` when `name` ends in `.gg`, ignoring case, otherwise null).
- **B5** If `biosFor(core)` returns a name, `play.js` checks `/api/emulator/bios/<name>` with a same-origin credentialed GET before requesting the ROM. Cancel the unused response body. A cancellation failure does not change the HTTP status message or success path. Abort before requesting the ROM or adding the loader on a failed check. Messages (`biosError`): 401 → `Your session has expired. Sign in again.`; 404 → `This system needs its BIOS: ask an Admin to put <name> in the BIOS folder (Paths:Bios).`; another status → `Couldn't load the BIOS (HTTP <status>).`; a network error → `Couldn't load the BIOS.`. Handle BIOS fetch rejection separately from the existing ROM error. On success, set `EJS_biosUrl` to the original endpoint URL before adding the loader. EmulatorJS downloads it again and writes it next to the ROM using the URL's last segment (see Risks). Cores without a BIOS skip the check.
- **B6** The README supported-systems table's "Play in browser" column shows the new cores for `a2600`, `coleco`, `gg` and `sms` (`SupportedSystemsTableTests` enforces it).
- **B7** SMS Plus GX stays in `auto` hardware mode for Game Gear and Master System. The packaged core's source defaults to Master System II, checks for a Game Gear region in the `TMR SEGA` header at `0x7ff0`, and then applies built-in CRC overrides. Either `.gg` or `.sms` may run as Master System if those checks fail to identify a Game Gear ROM. Document the limitation in `docs/features.md`.
- **B8** Both Sega systems stay on `smsplus`. Hide only the EmulatorJS core selector (`retroarch_core`) for `smsplus` launches. Ignore a previously saved alternative core while preserving the other emulator settings and SMS Plus GX's hardware options. EmulatorJS 4.2.3 takes the control scheme from the core's group (`getControlScheme()` → `getCore(true)`), which is `segaMS` for `smsplus`: no Start on the touch gamepad or in the controls menu. `play.js` sets `EJS_controlScheme` to `controlSchemeFor(core, name)` when it isn't null, so a `.gg` release gets the `segaGG` controls with Start. Any other name keeps the default; a Game Gear release stored as `.sms` gets Master System controls (document it with B7).

## Risks
- **BIOS loading in EmulatorJS 4.2.3:** `downloadFiles` downloads the ROM then BIOS (`emulator.js:925-926`). `downloadGameFile` writes an uncompressed BIOS beside the ROM as the URL's last segment (`717`). It tries HEAD first (`727`), gets `-1` for the 404, and goes on to GET because `EJS_disableDatabases = true` selects dummy storage and short-circuits the cache hit at `729`. Keep that setting enabled. Both packaged Gearcoleco variants contain `colecovision.rom` and `Incorrect BIOS size`. Both npm WASM variants were run with the app's virtual RetroArch config path, a synthetic cartridge and an 8 KiB placeholder. They fell back to the content directory and opened `//colecovision.rom` there. Check actual browser playback by hand when a real BIOS and ROM are available.
- **Licences and distribution:** the npm manifests point to [Stella 2014](https://github.com/EmulatorJS/stella2014-libretro), [Gearcoleco](https://github.com/EmulatorJS/Gearcoleco) and [SMS Plus GX](https://github.com/EmulatorJS/smsplus-gx). The fork sources identify Stella 2014 as GPL v2 (`stella/license.txt`), Gearcoleco as GPL-3.0-or-later (`LICENSE` and the Libretro source header), and SMS Plus GX as GPL-2.0-or-later (README and `docs/license`). SMS Plus GX's build includes the MAME-derived BSD-3-Clause Z80 and the CrabEmu GPL-2.0-or-later YM2413. The two Gearcoleco `.data` variants include GPL v3 text internally. The Stella 2014 and SMS Plus GX variants lack licence texts. The npm reports omit source revisions. Packaged WASM build identifiers point to [Stella 2014 `1f578c3`](https://github.com/EmulatorJS/stella2014-libretro/commit/1f578c36382bb5a86a0fe245973fa557f369738b), [Gearcoleco `f80af5d`](https://github.com/EmulatorJS/Gearcoleco/commit/f80af5d6f0f78b0228e060e158e7f2500e0caa6d), [SMS Plus GX `c642bbd`](https://github.com/EmulatorJS/smsplus-gx/commit/c642bbd0680b5959180a420036108893d0aec961) and [RetroArch `6dd4353`](https://github.com/EmulatorJS/RetroArch/commit/6dd4353937ef48b6ec0bfbdbb15d1c5992d86927) for Gearcoleco. The packages identify build tooling as 2.0.2. Step 6 must establish the remaining build inputs for the distributed binaries.
- **Serving files:** operators control `Paths:Bios` and its ancestors, which the checked open trusts. Keep only BIOS files in this dedicated writable folder because a signed-in user can request any valid direct filename. Checked opens use Windows/Linux implementations and require procfs on Linux.
- **SMS Plus GX auto detection:** the packaged legacy WASM produced Master System dimensions for a synthetic cartridge without a matching header and Game Gear dimensions for the same fixture with a Game Gear header. Changing the extension between `.gg` and `.sms` did not change either result.
- **Image size:** the six additional non-threaded `.data` files total 5,598,268 bytes (about 5.34 MiB before image compression).
