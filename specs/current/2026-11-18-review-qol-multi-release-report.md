# Review QoL and Multiple Releases report

## Summary
Cuts clicks for an Admin curating the library: Next missing image lands on the Images tab with the upload dialog open and focused, the Upload Image dialog submits on Enter, toasts with a link close themselves like every other toast, the review item page gets a styled back button and **Use and Next**, and the Images tab gets a Google Images button. Adds a new **Multiple Releases** report (every signed-in user) listing games with N or more releases, with sortable columns, total size and update count.

## Out of scope
- A user setting for the toast timeout (fixed 5 s).
- **Use and Next** on the Search tab's results (Suggestions only).
- A system filter on the Multiple Releases report.
- Sortable columns on any other table.
- Changing the Review-next hotkey's own behaviour.

## Behaviour

### Toasts
- **B1** Every toast closes itself `toastDurationMs` (5 s) after it appears, including toasts with a link (today those stay until closed). The close button still works.
- **B2** While the pointer is over a toast or focus is inside it (its link or close button), its timer pauses; when the pointer leaves and focus leaves, it gets a fresh 5 s. Hover and focus are tracked separately per toast: `mouseleave` while focus is still inside doesn't resume, nor does `focusout` while hovered or whose `relatedTarget` is inside the same toast (link → close button). Dismissing a toast clears its timer. Pausing one toast doesn't affect others. Clicking the link dismisses it at once (unchanged).

### Next missing image and the Upload Image dialog
- **B3** The Next missing image shortcut opens `/games/<id>?tab=images&upload=1` instead of `/games/<id>`, for every user (a Site user lands on the Images tab without the dialog, B4). The toasts for "only one left", "none left" and lookup failure are unchanged.
- **B4** On the game page, `upload=1` with an Admin opens the Upload Image dialog once the game has loaded. In the same step the page replaces the URL with `?tab=images` (`goto(…, { replace: true, reset: false })`: `upload` removed, `tab` forced to `images` whatever it was, since the dialog lives in the Images panel and a hidden ancestor would hide it), so a reload or Back doesn't reopen it. The dialog opens only after that navigation has made the Images panel visible. A Site user ignores it (the parameter is still removed, `tab` left as it was). A game that fails to load or isn't found ignores it and leaves the parameter in the URL (as `?play=`, whose effect returns early without a game). As `?play=` does, it acts only once the loaded game's id is the route's id, so a Next missing image press on another game's page doesn't open the dialog for the previous game. The dialog opens through `openUpload()`, so it starts reset as a button click does. Any `upload` value other than `1` is removed without opening the dialog.
- **B5** The trigger button and the dialog title read **Upload Image** (capital I). The confirm button stays **Upload**.
- **B6** Each time the dialog finishes opening (Bootstrap's `shown.bs.modal`), focus moves to the **Image URL** input (the dialog always opens on URL, as today). Switching to File and back doesn't refocus.
- **B7** Pressing Enter in the Image URL input submits the dialog exactly as **Upload** does (`preventDefault`, ignored while `busy`). Enter elsewhere in the dialog keeps its default behaviour (radio buttons, file input, buttons).

### Game page Images tab
- **B8** For Admins, a **Google Images** button (`btn btn-outline-secondary btn-sm`, Google icon, text "Google Images" so it can't be confused with the header's "Google" link) sits immediately before **Upload Image**; `ms-auto` moves from Upload Image to it, so the pair stays right-aligned. It is a link opening, in a new tab (`target="_blank" rel="noopener noreferrer"`), Google Images for the header's query: `https://www.google.com/search?udm=2&q=<encodeURIComponent(gameSearchQuery(game))>`. Site users don't see it.

### Review item page
- **B9** The `← Review queue` link becomes `<a class="btn btn-sm btn-outline-primary">` with the `back` icon and text **Review queue**, the same style as the game page's **Back to Library**. It still links to `/review`.
- **B10** Each Suggestions row gets **Use and Next** (`btn btn-sm btn-outline-primary ms-1`) right after **Use**, in the same cell. It resolves exactly as **Use** does (same request, same update checkbox, same done toast text).
- **B11** "Next" is the first Pending item, in the queue's default order, that isn't the current item, within the saved Review filter (`parseReviewFilter(new URLSearchParams(readSavedReviewFilter()))`, since the saved value is a query string; `q`, `system`, `reason` apply, `page` is ignored). It's looked up with `GET /api/review` built by `reviewApiUrl({...filter, page: 1}, 2)` and the first item whose id differs from the current one is taken.
- **B12** When the page loads an item (and again after each item change), it does that lookup. A lookup still running when the item changes is aborted and its answer ignored (as the item load's `AbortController`). While it's running, or when it finds no other item, or it fails, **Use and Next** is disabled (as are all actions while `disabled` is true, unchanged). A disabled button has a tooltip-free `title` "No more items in the review queue." only when the lookup found none.
- **B13** When a **Use and Next** resolution ends successfully while the user is still on that item's page, `reviewJobs` repeats the B11 lookup (the queue may have changed) and navigates to that item, showing the usual success toast; if none is left, or the lookup fails, it opens the game, as **Use** does. `running` stays set until that lookup has settled, so the page's actions stay disabled meanwhile. After the lookup, `here` is checked again: if the user has left the item page in the meantime, nothing navigates and the existing off-page success toast (with **Open game**) is shown instead. A failure behaves exactly as **Use** (error shown on the page, no navigation). If the user left the page before the job ended, the existing off-page toast behaviour applies unchanged.
- **B21** When the item page moves to another item in place (Use and Next, the Review-next hotkey, any `/review/<id>` link), every per-item value starts as on a fresh load: `updateChoice` (so the update checkbox follows the new file's `[UPD]` marker), `chosenTab`, `searchText`/`searchResults`, the Attach target, flag, disc and their errors, the Manual form and its errors, `actionError`, and the Dismiss/Delete confirmations closed. A DAT search still running for the previous item has its answer ignored (`searching` cleared), as B12's lookup.

### Multiple Releases report
- **B14** A new Reports tab **Multiple Releases** (`/reports/multiple-releases`, icon name `report-multiple-releases` → `bi bi-layers`, unused elsewhere), after Duplicates and before Activity, for every signed-in user.
- **B15** A game's **releases** are its `roms` rows whose `flags` don't contain `"Update"` (DLC counts as a release). **Updates** are the rows that do. **Size** is the Library Size report's game bytes: `games.zip_size_bytes` plus the recorded `size_bytes` of its external ROMs and their set files (all external rows, updates included).
- **B16** `GET /api/reports/multiple-releases?min=&sort=&dir=&page=&pageSize=` (any signed-in user) returns `{maxReleases, items, page, pageSize, total}`. `min` defaults to 2 and must be 2–10000; `sort` is `name|system|releases|updates|size` (default `releases`); `dir` is `asc|desc` (default per sort key: `asc` for `name` and `system`, `desc` for the others); paging as the other reports (page ≥ 1, pageSize 1–200, default 50). `min`, `page` and `pageSize` bind as `int?` like the other reports, so a non-number is minimal-API binding's plain `400`; a well-formed number out of range, or an unknown `sort`/`dir` value (case-insensitive match), is `400 ValidationFailed` naming the field, with house-style messages: `min` "Must be 2–10000.", `sort` "Must be name, system, releases, updates or size.", `dir` "Must be asc or desc.", `page`/`pageSize` from `Paging.Validate`. Items are `{id, displayTitle, system, systemName, releaseCount, updateCount, bytes}` for games with `releaseCount >= min`. `maxReleases` is the highest release count of any game in the library (0 when empty), independent of `min`.
- **B17** Ordering: only the primary key follows `dir`; tie-breakers are always ascending. `releases`/`updates`/`size`: key, then `display_title`, then `id`. `name`: `display_title`, then `system_id`, then `id`. `system`: `system_id`, then `display_title`, then `id`.
- **B18** The page shows a **Minimum releases** `<select>` at the top, laid out as Missing Images' System filter (`row g-2 align-items-end mb-3` > `col-12 col-sm-6 col-md-4`, `<label class="form-label" for="multiple-releases-min">Minimum releases</label>`, `<select id="multiple-releases-min" class="form-select">`), with options 2…`max(maxReleases, 2)` (each option's text and value is the number), default 2. Until the first response arrives it is disabled and shows only the current `min`; later loads keep the last `maxReleases`, so it stays enabled (and keeps focus) while they run. A URL `min` within 2–10000 but above `max(maxReleases, 2)` is kept and added as one extra option (the table then shows B20's empty state). Changing it resets to page 1. State lives in the URL (`?min=&sort=&dir=&page=`) written with `goto(…, { replace: true, reset: false })`; a value equal to its default is omitted (`min` 2, `sort` releases, `page` 1, `dir` the sort key's default from B16). Bad URL values (non-numbers, out of range, unknown sort/dir; `sort`/`dir` match exactly, lowercase, as `libraryQuery.ts`) fall back to those defaults. The page always sends `sort` and `dir` explicitly, and a fixed `pageSize=50` (no rows-per-page selector, as on Missing Images).
- **B19** The table (T1–T4 table rules) has columns **Game** (link to `/games/<id>`), **System** (`SystemBadge` with `name={item.systemName}`, as Missing Images), **Releases**, **Updates**, **Size** (`<FileSize>`); numbers and size right-aligned `text-nowrap`. Every header is a sort button (`<button type="button" class="btn btn-link p-0 text-reset text-decoration-none fw-semibold">`, the label then the icon) inside its `<th scope="col">`, the Releases, Updates and Size headers `text-end`; the active one carries `aria-sort="ascending|descending"` and the `sort-asc` / `sort-desc` icon (existing `icons.ts` names); inactive headers have no icon and no `aria-sort`. Clicking the active header flips the direction; clicking another sorts by it in its default direction (B16) and resets to page 1. `Pagination` below, as on Missing Images. Loading/ErrorAlert as the other reports.
- **B20** `total === 0`: `EmptyState` "No games have <min> or more releases.". A `page` past the last page (`items` empty, `total > 0`) replaces the URL with the last page and reloads instead.

## Risks
- **Size query cost:** the report computes per-game subqueries over all games (as Library Size already does). Acceptable at current scale; `maxReleases` is a second scan. No index added.
- **SQL injection:** sort column and direction come only from the enum/bool mapping, never from the query string.
- **Accessibility:** auto-dismissing link toasts would fail WCAG 2.2.1; B2's pause on hover/focus covers it. Auto-focus happens only after an explicit open (button or shortcut).
- **Use and Next race:** the queue can change between the load lookup and job end; B13 re-checks at the end.
- **e2e names:** the case change breaks `getByRole("button", { name: "Upload image" })` and the dialog name checks; updated in step 4. The review e2e's `getByRole("button", { name: "Use" }).first()` still hits **Use** (it precedes **Use and Next** in the row).
