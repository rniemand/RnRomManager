# Neo Geo Pocket and Neo Geo Pocket Color

## Summary
Two new systems, Neo Geo Pocket (`ngp`, mono) and Neo Geo Pocket Color (`ngpc`), in a new `RnRomManager.Systems.NeoGeoPocket` project, for the Admin who ingests ROMs and everyone who browses and plays the library. They split like Game Boy / Game Boy Color: one family, a shared base class and header reader, the header's mode byte (0x23) decides colour vs mono for unmatched files, and each has its own libretro No-Intro DAT. Both play in the browser with EmulatorJS's `mednafen_ngp` core (Beetle NeoPop), which isn't vendored yet: this spec vendors `@emulatorjs/core-mednafen_ngp` `4.2.3` the way Beetle PCE was. No BIOS (the core uses its built-in HLE BIOS).

## Out of scope
- A system icon (`icons.ts`): like `gb`/`gbc`, both use the controller fallback.
- Converting or detecting bad dumps; NeoPop's three catalog hacks (`rom_hack()` in the core) aren't copied: classification reads the raw byte.
- A `getCore()` pin, a core-chooser hide or a control scheme: EmulatorJS 4.2.3's `ngp` group holds only `mednafen_ngp` (as `pce` holds only `mednafen_pce`).
- An automatic DAT refresh after upgrading (documented manual step).

## Behaviour
- **G1 Contract values.** Base `NeoGeoPocketHandlerBase` (new, abstract, as `GameBoyHandlerBase`): `Family` = `neogeopocket` (`FamilyId` const), `MinRomSizeBytes` = `NeoGeoPocketHeaderReader.HeaderEnd` (`0x40`, the header's size), `MaxRomSizeBytes` = `4 * 1024 * 1024` (the DATs' largest entry, 4,194,304, is also the cartridge maximum of 32 Mbit), `EmbedRomsInZip` = true, `BrowserCore` = `mednafen_ngp` (from step 4; null before), `DefaultBoxArtPng` loads `boxart.{Id}.png`, `ReadHeader` = `NeoGeoPocketHeaderReader.Read(rom)`. Defaults kept for every other member (`DatSource.Libretro`, `DatKind.NoIntro`, all four metadat kinds, no `NormalizeForHashing`).

  Facts (libretro-database `master`, DAT version `2026.11.14`, checked 2026-11-24): both systems have all five files (`no-intro`, `releaseyear`, `developer`, `publisher`, `genre`) and a `libretro-thumbnails` repository (`SNK_-_Neo_Geo_Pocket`, `SNK_-_Neo_Geo_Pocket_Color`). The mono DAT lists 9 `.ngp` entries (512 KiB–2 MiB); the colour DAT 106 `.ngc` entries (512 KiB–4 MiB). Neither lists another extension, so `.ngpc`/`.npc` are ingest aliases only: a DAT hit is stored under the DAT's `.ngc` name, and a Review resolution under `RomExtensions[0]` (`.ngc`).
- **G2 Header.** `NeoGeoPocketHeaderReader` (new, static class) with `public const int HeaderEnd = 0x40;` (as `GameBoyHeaderReader.HeaderEnd`) and `Read(ReadOnlySpan<byte> rom)` (never throws). Returns null when `rom.Length < HeaderEnd`. Otherwise a header (layout from Beetle NeoPop's `RomHeader` in `mednafen/ngp/rom.h`):
  - `IsPlausible`: bytes 0x00–0x1B equal, byte for byte, either `COPYRIGHT BY SNK CORPORATION` or ` LICENSED BY SNK CORPORATION` (ASCII, 28 bytes each, the second with a leading space; the console's BIOS checks this string to boot).
  - `ClassifiedSystemId`: `ngpc` when byte 0x23 is exactly `0x10`, else `ngp` (`0x00` and any other value), whether plausible or not.
  - `Title`: the `title` field below.
  - `Fields`, in this order: `title` (bytes 0x24–0x2F up to the first NUL, each byte outside 0x20–0x7E replaced by `?`, trailing spaces trimmed; null when empty), `licence` (the matched string trimmed, `COPYRIGHT BY SNK CORPORATION` or `LICENSED BY SNK CORPORATION`; null when neither matched), `catalog` (int, little-endian uint16 at 0x20), `subCatalog` (int, byte 0x22), `mode` (`"0x"` + two upper-case hex digits of byte 0x23, e.g. `"0x10"`), `colour` (bool, mode == 0x10), `startPc` (`"0x"` + eight upper-case hex digits of the little-endian uint32 at 0x1C, e.g. `"0x00200040"`).
- **G3 Ingestion.** The existing family pipeline, as for GB/GBC:
  - A file in `ingest/ngp/` or `ingest/ngpc/` with any of the four extensions is checked against both DATs; a DAT hit decides the system (a colour-header ROM listed in the mono DAT is stored as `ngp`).
  - Unmatched: an implausible header → `InvalidHeader` ("no DAT match, and the header isn't valid for this system"); a plausible one → Review (`NoDatMatch`) under the classified system, the file first renamed to that system's `RomExtensions[0]` when its extension isn't one of the classified system's (`RenameToClassifiedExtension`): a colour `.ngp` becomes `.ngc`, a mono `.ngc`/`.ngpc`/`.npc` becomes `.ngp`.
  - Under 64 bytes → `TooSmall`; over 4 MiB → `TooLarge`. Another family's file (e.g. `.gb`) in `ingest/ngp/` → `UnsupportedType`; a `.ngp` in `ingest/gb/` → `UnsupportedType`.
  - Releases have the Header button; `info.json` `header` holds G2's fields.

## Risks
- **Two new systems break every full-registry DAT manifest** (`DatsMissing`) and the count/order assertions: all fixed in step 2's single commit.
- **Licence notice accuracy.** G8's facts were read from the payload and the source at `10f91c1`. Step 4 re-checks the pinned hashes; if they differ, G7/G8 no longer apply: stop and ask.
- **Header check misfires.** A homebrew file without either SNK string fails `InvalidHeader` when unmatched (the BIOS wouldn't boot it either). A mono game with a stray `0x10` mode byte (NeoPop patches `Dokodemo Mahjong`) classifies as colour when unmatched; DAT hits are unaffected.
- **Image size.** About 1.7 MB more vendored output.
