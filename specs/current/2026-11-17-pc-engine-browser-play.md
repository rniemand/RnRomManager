# PC Engine browser play

## Summary
PC Engine HuCards already import as the `tg16` system: `.pce`, stored in the game ZIP, matched against libretro's `NEC - PC Engine - TurboGrafx 16` No-Intro DAT, which lists both Japanese PC Engine and US TurboGrafx-16 releases. This spec adds in-browser play through EmulatorJS's `mednafen_pce` core (Beetle PCE, GPL-2.0-or-later plus component licences; see P4). The core is vendored the same way PUAE was, so it needs no operator setup. The system's display name also changes to `TurboGrafx-16 / PC Engine` so users can find it under either name.

## Out of scope
- A separate `pce` system. Both systems would match the same DAT, so one game could be ingested twice.
- PC Engine CD / TurboGrafx-CD (disc, needs a System Card BIOS) and SuperGrafx (its own DAT, and `.sgx` isn't in the core's `core.json`).
- Changes to ingestion, storage, the DAT, the `tg16` id, folders or colours. Existing data is untouched.
- A `getCore()` pin, a core-chooser hide or a custom control scheme. EmulatorJS 4.2.3's `pce` group holds only `mednafen_pce`, so no other saved core can be chosen, and the `pce` controls apply as upstream (the same as `puae`).

## Behaviour
- **P1 Display name.** `TurboGrafx16Handler.DisplayName` = `TurboGrafx-16 / PC Engine`. `Id`, `ShortName` (`TG16`), `Family`, extensions, sizes and DAT are unchanged. `/api/systems` order is unchanged: the new name still sorts after `Super Nintendo Entertainment System` and before `Virtual Boy` (`OrdinalIgnoreCase`). Every place that shows the name from the API (System filter, badges, Admin views) shows the new name. Nothing in the SPA hard-codes it.
- **P2 Browser core.** `TurboGrafx16Handler.BrowserCore` = `mednafen_pce`. Game list and detail responses advertise it for `tg16`. Play follows the existing embedded-release rules: the card's Quick Play targets the primary release, the detail Play targets the selected release, and the play page fetches `GET /api/games/{id}/roms/{romId}/download` (the stored `.pce`, header already stripped at ingest). No BIOS request is made. `EJS_disableCue` stays unset, which upstream already treats as disabled for `mednafen_pce`. Battery and state saves use the existing generic save flow (`core.json` `save: "srm"`).
- **P3 Vendored core.** `@emulatorjs/core-mednafen_pce` `4.2.3` becomes an exact-version dependency. `vendor-emulatorjs.mjs` copies its two non-threaded payloads and its report into `static/emulator/vendor/data/cores/`, like the other vendored cores, and never copies the `-thread` variants. `params.js` adds `mednafen_pce` to the allowed play-page cores. It is not added to `hidesCoreChooser`, the `getCore()` pin, the threaded-payload guard or `biosFor` (like `puae`: `play.html` isn't cross-origin isolated, so EmulatorJS never picks a `-thread` payload there). ## Risks
- **Licence notice accuracy.** The source commit, build flags and bundled components in P4 were read from the binaries and the source at that commit. Step 1 re-checks the pinned hashes. If they differ, the P4 facts no longer apply: stop and ask.
- **Report quirk.** The upstream `reports/mednafen_pce.json` and `core.json` carry a `Beetle PSX HW` options block (an upstream copy-paste). It names a setting Beetle PCE doesn't read, so it's harmless. The files are copied unchanged and pinned by hash.
- **Rename.** External scripts that matched the `TurboGrafx-16` display name text break. The id is the stable key and is unchanged.
- **Image size.** About 2 MB more in the vendored output.

## Decisions
- 2026-11-17 Separate `pce` system or the existing `tg16` → `tg16` gets browser play. The shared DAT would ingest the same game twice (user).
- 2026-11-17 Display name → `TurboGrafx-16 / PC Engine`, id unchanged (user).
- 2026-11-17 Vendored or operator-supplied core → vendored. Beetle PCE is GPL (exact expression per P4) and ships `license.txt`, like PUAE (code and package).
- 2026-11-17 Pin or hide the core chooser → neither. `pce` is a single-core group in EmulatorJS 4.2.3, as with `puae` (code).
- 2026-11-17 Build provenance → matches COMMON-BUILD.txt (2025-06-14 build, build.json 2.0.2, RetroArch `6dd4353`). Emscripten 4.0.8 was confirmed in the second review (see below) (code, reviewer).
- 2026-11-17 Doc rename → only the user-facing system lists. History, handler-pattern and seed mentions keep `TurboGrafx-16` (reviewer).
- 2026-11-17 Beetle PCE source commit, build flags and components → `EmulatorJS/beetle-pce-libretro` `e1ac90d5a97ad328c51b8b01e68da8af5faa1579` (binary version string `v1.29.0 e1ac90d`), components per P4 from the Makefile defaults at that commit (upstream, reviewer).
- 2026-11-17 Licence expression → `GPL-2.0-or-later AND LGPL-2.1-or-later AND BSD-3-Clause AND Zlib AND MIT`, plus the public-domain LZMA SDK and dr_flac. Every GPL header under `mednafen/` allows later versions (upstream, reviewer).
- 2026-11-17 Emscripten 4.0.8 → confirmed now. Both `.wasm` producers sections name LLVM `23e3cbb`, as COMMON-BUILD.txt states, so step 1 no longer has a stop-and-ask check (upstream, reviewer).
- 2026-11-17 Component licence files → `libchdr`, `lzma` and `tremor` get `mednafen_pce-<component>-LICENSE.txt`. zlib, Blip_Buffer, dr_flac and libretro-common ship no file, so the NOTICE quotes their terms (upstream, reviewer).
- 2026-11-17 Step 3 "Done when" → a type check, not a Playwright run. The spec skill runs Playwright only in Finish (repo rule, reviewer).
- 2026-11-17 Which upgrade note P5 renames, and whether `deployment.md` gets a new one → only README line 126. There's no deployment note, since the upgrade needs no DAT refresh, folder or operator file (code, reviewer).
- 2026-11-17 PC Engine CD and SuperGrafx → out of scope. The request covers files stored in the ZIP (user request, `core.json`).
