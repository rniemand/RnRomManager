# Play progress, Emulators button, report search and system filters

## Summary
Polish for every signed-in user: the browser player always shows a progress bar while it downloads a ROM or disc (the server now says how big the download is), the game page gets an **Emulators** button for its system (and the modal title becomes "… Emulators"), Global Search also finds reports, and six reports use the Games page's System dropdown instead of a plain `<select>`. For Admins, the review queue's Attach tab can also attach a file to an existing game as a new **Release** (tagged from its file name, marked Unverified).

## Out of scope
- Progress for the BIOS and library-save downloads in the player, and for EmulatorJS's own core download.
- Per-system counts in the report System dropdowns (the Games page shows counts; reports don't).
- Library Size and Activity reports (they have no System select).
- Changing the "No games match" text in Global Search.
- Exact `Content-Length` for the on-the-fly cue/bin ZIP (an estimate header is sent instead, P2).
- Attach as **Disc** on systems without file sets: it stays a disc-system option, as today (review B16).
- Changing the `AmbiguousGroup` attach (`flag: "None"`).

## Behaviour

### Player download progress (P)
- **P1** `GET /api/games/{id}/roms/{romId}/download` for a ROM stored inside the library ZIP (`LibraryDownload.OpenReleaseAsync`'s `OpenEntry` branch, `ranges: false`) sends `Content-Length: <rom.SizeBytes>`. Implemented once in `LibraryDownload.Send`: when `!attachment.Ranges`, set `ctx.Response.ContentLength = attachment.Length` before returning `Results.Stream(...)`. This also gives the save download (`SaveEndpoints.cs:134`, `save.SizeBytes`) a `Content-Length`. `Send`'s callers are `LibraryEndpoints.cs:179` (release, changes), `:187` (set file, ranges, unchanged) and `SaveEndpoints.cs:134` (changes); the bundle ticket stream (`BundleDownloadEndpoints.FileAsync`) calls `OpenReleaseAsync` but writes through its own `TicketStreamResult`, not `Send`, so it is unchanged. Range-enabled attachments (external files, set files) are unchanged: `Results.Stream` already sends their length. If the entry turns out shorter than the recorded size, Kestrel aborts the response (today it ends as a truncated `200`); the player then shows its existing "Couldn't load the ROM." error.
- **P2** `GET /api/games/{id}/roms/{romId}/play-disc` for a cue set (the ZIP built on the fly in `PlayDisc.DiscResult`) adds the header `X-Content-Bytes: <cue.Length + Σ entries[i].Length>` (the sum of the cue's and tracks' lengths, in bytes, invariant culture) before the first write. It still sends no `Content-Length`. A standalone image keeps its `Content-Length` and gets no `X-Content-Bytes`.
- **P3** In `static/emulator/play.js`, `readContent(response)` uses `Content-Length` as the total if it is usable (`Content-Encoding` absent or `identity`, and a safe positive integer, as today); otherwise `X-Content-Bytes` if it is a safe positive integer (whatever the encoding); otherwise there is no total. With a total: the bar shows with `max = total`, `value = min(bytes, total)`, and the label `#downloaded` shows the percent `floor(min(bytes, total) * 100 / total)` (so it never passes 100%). Without a total: the bar still shows, **indeterminate** (`progress.removeAttribute('value')`), and the label shows the byte count as today. `show()` hides both again, as today. Applies to ROM downloads and disc downloads (`loadDisc`, which already calls `readContent`).

### Emulators button on the game page (E)
- **E1** `SystemEmulatorsModal`'s title becomes `{system.displayName} Emulators` (capital E). The body texts don't change.
- **E2** The game page (`routes/games/[id]/+page.svelte`) action row gets `<button type="button" class="btn btn-sm btn-outline-secondary"><Icon name="emulators" /> Emulators</button>` right after the **Collections** button (before **Next missing metadata** and **Manage**), for every signed-in user and every system. ### Reports in Global Search (S)
- **S1** The report tab list moves out of `routes/reports/+layout.svelte` into `src/lib/reports.ts` (new): `export function reportTabs(isAdmin: boolean): ReportTab[]` with `ReportTab = { href: string; label: string; icon: string }`, the same entries, order, labels, icons and `resolve(...)` hrefs as today (Missing Metadata and Activity only when `isAdmin`). - **S2** A report matches when its label, lower-cased, contains every whitespace-separated word of the trimmed, lower-cased query. It uses the same 2-character minimum and runs in `search()` (so report results appear together with the API results, after the 250 ms debounce). All matching reports show (at most 8 exist). Site users never get Missing Metadata or Activity. The report matches are state cleared wherever `collections` and `games` are cleared today (`oninput`, `choose`, `reset`), with `active` reset to 0, so no stale chip shows while the next query loads or below 2 characters.
- **S3** Matches show as a **Reports** group, **first** in the list (Reports → Collections → Games), with a header row `Reports` like the Collections one (`<li role="presentation">`), then one `<li class="list-group-item d-flex flex-wrap gap-2" role="group" aria-label="Reports">` holding chips like the collection chips (`btn btn-sm btn-outline-secondary d-inline-flex align-items-center gap-1`, `class:active`, `aria-selected`, `onmousemove` setting `active`; `<Icon name={tab.icon} />` then `<span>{tab.label}</span>`, no count), each an `option` of the same listbox. The `Entry` union gains `{ kind: 'report'; item: ReportTab }`. Up/Down walk Reports, then Collections, then Games; option ids stay `global-search-results-<index>` over the combined list: `results` prepends the reports, a report chip's index is its position `r`, a collection chip's (today the bare `i`, line ~300) becomes `reports.length + i`, and a game row's (today `collections.length + g`, line ~332) becomes `reports.length + collections.length + g`, so `id`, `class:active`, `aria-selected`, `onmousemove` and `aria-activedescendant` (line 263) agree.
- **S4** Enter or a click on a report chip closes the search (as `choose` does) and navigates to the report's `href`. Shift+Enter on a report does nothing.
- **S5** The input's `visually-hidden` label (`for="global-search-input"`) and its placeholder become `Search games, collections and reports`. "No games match" shows only when all three groups are empty (no text change). When both API calls fail, the error shows and report matches still show.

### Attach as a new release (A)
- **A1** `POST /api/review/{id}/resolve` (Admin, unchanged access) accepts `action: "Attach"` with `flag: "Release"` (new) and a `targetGameId`. `ReviewEndpoints.Validate`'s flag check becomes `"Hack" or "Translated" or "None" or "Disc" or "Release"`, with the message `Must be Hack, Translated, None, Disc or Release.` A `disc` with `Release` stays `400` (`A disc number needs Manual or Attach as a disc.`), as for Hack/Translated today.
- **A2** In `ReviewResolver`, `Release` goes through the existing `Attach` branch (target lookup, same-system check, `OpenTarget`, title = the game's title), with these differences from Hack/Translated: the regions, languages, revision and flags come from `NoIntroName.Parse(<name stem>)` (as the `None` branch parses a name), where `<name stem>` is the original file name without extension, or, for a set item (`set` from `ReviewSets.FindAsync` is not null), the stem of the set member whose `IngestFile.Name` ends in `.cue` (case-insensitive), whichever member was opened. Parsed flags matching `^(Disc|Track) \d+$` (case-insensitive) are dropped; another disc is Attach as Disc's job. Then the flag `Unverified` is appended (as the Dat action's manual pick does, `ReviewResolver.cs` ~468 for the flag, ~471–472 for the file name), so `PrimaryReleaseRanker` keeps DAT-verified releases primary; it is not added twice when the parsed flags already have it. The file name is the sanitized original stem plus ` (Unverified)` (not added twice when the stem already contains `(Unverified)`), plus the same extension rule (`external || system.KeepsSourceExtension ? originalExtension : system.RomExtensions[0]`); a set keeps its members' source names as today (B14). Everything after (name checks, an embedded release's clashing file name getting ` (2)`… before the extension (`IngestPipeline` §6.1 `FileNameRules.FirstFree`), `NameTaken` for a disc set's clash, `Duplicate` 409s, unmatched sets, external storage, primary release recompute) is the shared code path, unchanged. The release is identified as Manual, as other Attach releases are today.
- **A3** The Attach tab (`routes/review/[id]/+page.svelte`) lists `Release`, `Hack`, `Translated` (plus `Disc` on a disc system), in that order, with **Release** preselected for every item (`attachFlag`'s type at line 70 gains `'Release'`; its default and the per-item reset at line ~148 become `'Release'`; `attachFlags` at line 74 lists `'Release'` first). The radio label is `Release`. The radios' `<legend>` changes from `Flag` to `Attach as` (no test queries it). The hint text becomes `Attach to a game as a new release, a hack or a translation.` and, on a disc system, `Attach to a game as a new release, a hack, a translation or another disc.` The success toast stays `Attached to <title>.`

## Risks
- **Content-Length mismatch (P1):** a DB size that doesn't match the ZIP entry now aborts the response instead of sending a short `200`. That's an Integrity problem already; failing loudly is better than a truncated ROM. Saves gain the same check.
- **`Results.Stream` and a preset `ContentLength`:** the result must not clear the header for a non-seekable stream. Step 1's tests prove the header on the ASP.NET pipeline (`ApiFactory` is a `WebApplicationFactory`, so TestServer, not Kestrel); Kestrel's abort on a short body isn't unit-tested, and the e2e **Download ROM** check (`mvp.spec.ts` ~618–628) exercises the real `Content-Length` on Kestrel.
- **Tests that pin today's behaviour** (listed in each step) change: the modal title in three places, the game page's action-row order test, the report `<select>` tests, the `'game'` queries in Global Search's play tests, the player's "unknown length hides the bar" test, and `ReviewRequestValidationTests`' flag message.
- **Data:** nothing stored changes. A2 only adds releases; P1 can turn a silently truncated download into an aborted one (above).
