# Ingest file delete, release header colour and Atari 2600

## Summary
Three changes for the Admin who runs ingestion and browses the library. (1) The Ingestion page can permanently delete files: pending files, and the files in each system's `_failed/` folder, which get their own new list with the failure reason. (2) Each release card on a game's Releases tab gets a stripe in the system's colour and a tinted header, so a new release is easy to spot when scanning. (3) Atari 2600 (`a2600`) joins as the seventh system, in a new `RnRomManager.Systems.Atari` project.

## Out of scope
- Other Atari systems (5200, 7800, Lynx, Jaguar): separate specs.
- Atari 2600 header parsing, bank-switching detection, Supercharger `.wav` tapes (the DAT's one `.wav` entry is dropped by the existing extension filter), a dedicated `a2600` icon (the controller fallback is used) and an automatic DAT refresh after upgrading (documented manual step).
- Deleting files in `_duplicates/` or `_removed/`, and orphan `.error.txt` files whose ROM is already gone (not listed).
- Undo or a recycle bin: delete is a hard delete, as the request asks.

## Behaviour

### Ingest file delete (Admin only)
- **D1 Failed list.** `GET /api/ingest/failed`: like `GET /api/ingest/pending`, one entry per registered system in registry order, `{ system, files: [{ name, sizeBytes, modifiedAt, reason }] }`. `files` are the top-level files of `ingest/<id>/_failed/` (missing folder → `[]`), ordered by name (ordinal), without names `IngestFileScanner.IsIgnored` rejects and without names ending `.error.txt` (case-insensitive). `reason` is the rest of the first line in `<name>.error.txt` that starts with `reason: `, trimmed (the format `IngestPipeline.MoveToFailed` writes), or null when that file is missing, unreadable or has no such line. Implemented as `IngestFileScanner.ScanFailed()` next to `Scan()`.
- **D2 Delete endpoint.** `POST /api/ingest/delete`, body `{ files: [{ system, folder, name }] }`, `folder` = `pending` (`ingest/<system>/`) or `failed` (`ingest/<system>/_failed/`).
  - **Validation → 400** (ProblemDetails `errors.files`, nothing deleted; body read by hand and errors via `Problems.Validation`, as `POST /api/jobs/ingest` does): body missing or not JSON; `files` missing, empty or over 500 entries; any entry with an unregistered `system`, a `folder` other than the two values, or a `name` that is empty, contains `/` or `\`, is `.` or `..`, is rejected by `IsIgnored`, or (for `failed`) ends `.error.txt`. The path is built as `Path.Combine(paths.Ingest, system, [_failed,] name)` and checked with `SafePath.Resolve` as `ReviewResolver.DeleteSourceAsync` does.
  - **Job lock:** taken with `TryAcquire` for the whole request; busy → `409 JobRunning`, nothing deleted.
  - **Repeats:** an entry equal to an earlier one (same `system`, `folder`, `name`) is skipped and not counted.
  - **Per file**, in request order: `existed = File.Exists(path)`; `File.Delete(path)` (a missing file or folder counts as deleted). For `failed`, `<path>.error.txt` is deleted too (missing is fine; an IO error on the sidecar only logs a warning). For `pending`, only after the file delete succeeded (or the file was already gone), every `Pending` review row of that source goes (`DeletePendingBySourceAsync(path, null)` for a loose file, `DeletePendingBySourceAsync(path, path)` when `ArchiveExtractor.IsArchive(name)`); resolved and dismissed rows stay. `path` is the same full-path form the scanner gives `IngestFile.FullPath`, so it matches the stored `source_path` / `archive_path`. An `IOException` / `UnauthorizedAccessException` on the file itself puts the entry in `failed` (its review rows and sidecar stay), logs a warning and continues with the next file.
  - **Audit:** a new action `IngestFileDeleted` (added to `AuditActions` and `All`), recorded only when the file existed, with the system and `Path` = `auditPaths.Of(path)` (injected `AuditPaths`, as in `ReviewResolver`) (`ingest/<system>/…`), `Details` = the folder (`pending` / `failed`). One info log line per request (user, counts).
  - **Response 200** `{ deleted: <count of entries not in failed>, failed: [{ system, folder, name }] }`.
- **D3 Pending table.** Each row gets a right-aligned `btn-sm btn-outline-danger` delete icon button (`aria-label="Delete <name>"`) and the tooltip `Delete (Shift+click to skip confirmation)` (`use:tooltip`, as on the Review page) in a new last column (`<th scope="col"><span class="visually-hidden">Actions</span></th>`). The toolbar gets **Delete selected (n)** (`btn-sm btn-outline-danger`, after **Clear selection**), counting the same checkboxes Import selected uses (all checked after each reload, so n starts at every pending file; D5's always-confirm modal with count and names is the safeguard), disabled at 0.
- **D4 Failed section.** A new section "Failed files" between Pending files and Last runs, one table per system with failed files (a `card` with `EmptyState` "No failed imports." when none): checkbox, Name, Reason (`reason` in `<code>`, or `—`), Size (`FileSize`), Modified, row delete button as D3; header checkbox per system, **Select all** / **Clear selection** / **Delete selected (n)** toolbar; 20 rows per page per system (`Pagination`, as pending). Its selection is separate from the pending one and starts empty after every load.
- **D5 Confirmation.** Every delete opens a `ConfirmModal` titled `Delete <name>` (one file) or `Delete <n> files`, listing up to 10 entries as `<system>/<name>` (then "and <n> more"; the one-file title stays the bare name), stating that the files are permanently deleted from the ingest folder and can't be undone, and, for pending files, that their pending Review items go too; confirm button **Delete** (`btn-danger`). **Shift+click** on a *row* delete button skips the modal (as on the Review page), except for an archive (`.zip`/`.7z`, the same extensions as `ArchiveExtractor.IsArchive`, mirrored in the SPA), which always confirms. **Delete selected** always confirms, Shift or not.
- **D6 After a delete.** More than 500 entries are sent as consecutive requests of at most 500 (D2's cap), stopping at the first error response, with `deleted` summed and `failed` concatenated over the batches that succeeded. From the response(s): when `deleted > 0`, a success toast `Deleted <name>.` (one entry requested and deleted) or `Deleted <deleted> files.` (otherwise); when `failed` is not empty, a danger toast `Couldn't delete: <system>/<name>, …` (both toasts can show). `409 JobRunning` → `toasts.jobRunning`; other errors → danger toast with the ProblemDetails title. The page then reloads its lists (`load()`, which now fetches `GET /api/ingest/failed` alongside pending, so a finished job refreshes the Failed section too). All delete buttons are disabled while a job runs (`jobs.current`) or a delete is in flight. The request and toasts live in `src/lib/ingestDelete.ts`, shared by both sections and both paths (modal and Shift+click).

### Release header
- **R1.** Each release `<article class="card">` on the Releases tab gets `border-left: 6px solid var(--bs-<name>)`, `<name>` = `systemColour(game.system).name` (unknown systems → `secondary`). Its `card-header` changes from `bg-body` to `bg-body-tertiary release-header`.
- **R2 Contrast.** `app.css` sets, for `.release-header` in both themes, `btn-outline-secondary` / `-primary` / `-danger` `--bs-btn-color` and `--bs-btn-border-color` to the matching `--bs-*-text-emphasis` (the dark theme already does this globally), because the default outline colours fall under 4.5:1 on `bg-body-tertiary` in the light theme. The e2e axe scans (both themes) must stay clean on the Releases tab.

### Atari 2600
- **A1 Registration.** `Atari2600Handler`, in a new `src/RnRomManager.Systems.Atari` project (room for later Atari systems), is registered after SNES. Systems order: `gb`, `gbc`, `gba`, `n64`, `nes`, `snes`, `a2600`.
- **A2 Contract values.** `Id` = `a2600`, `DisplayName` = `Atari 2600`, `Family` = `a2600`, `RomExtensions` = `[".a26", ".bin"]`, `MinRomSizeBytes` = `2048`, `MaxRomSizeBytes` = `65536`, `DatName` = `Atari - 2600`. `ReadHeader` returns null (2600 cartridges have no header); `NormalizeForHashing` is the default. Facts (libretro DAT 2026.10.07, checked 2026-11-09): all five DAT files and the `Atari - 2600` thumbnails folder exist; the DAT has 876 `.a26`, 13 `.bin` and 1 `.wav` entries; `.a26`/`.bin` sizes range 2048–65536.
- **A3 Ingestion.** The existing pipeline. A matched dump is stored as `roms/a2600/<bucket>/<title>.zip` with the DAT's ROM name (`.a26` or `.bin`, as the DAT says). An unmatched file always goes to Review (`NoDatMatch`, suggestions from the file name; no header, so never `InvalidHeader`); resolving it stores it with `RomExtensions[0]` (`.a26`), the existing `ReviewResolver` rule for every system (a resolved `.bin` becomes `….a26`). Under 2048 bytes → `TooSmall`, over 65536 → `TooLarge`. A `.a26`/`.bin` in another family's folder, or another family's file in `ingest/a2600/` → `UnsupportedType`. Releases have no Header button (header null).
- **A4 Badge colour.** Woodgrain brown, same in both themes: `app.css` `--bs-a2600: #7a4b2a` on `:root` and `.text-bg-a2600 { color: #fff !important; background-color: var(--bs-a2600) !important; }` next to the SNES rules; `systemColours` gets `a2600: { name: 'a2600', foreground: '#fff' }` (the `name` union gains `'a2600'`). Used by `SystemBadge`, the Library Size treemap and R1's stripe.
- **A5 Default box art.** `a2600.svg` (drawn for this project, MIT) and its 512×512 `a2600.png` render, embedded and loaded like SNES's.
- **A6 Upgrade.** Ingestion refuses with `DatsMissing` until an Admin runs **Admin → DATs → Refresh DATs** (documented).

## Risks
- **Irreversible delete.** Gated by the modal (D5); Shift+click skips it only for one file at a time; bulk delete always confirms; Admin only; audited (D2).
- **Path tricks.** Names are plain file names (D2 validation) and the path is re-checked with `SafePath`, so a request can't reach outside `ingest/<system>/` or `_failed/`.
- **Deleting a file mid-ingest.** Prevented by the job lock (409).
- **Ingestion blocked after upgrade** (A6) until DATs are refreshed. Documented.
- **A 7th system breaks existing tests** (`DatsMissing`, counts). Fixed in the registration step (6).
- **No 2600 header check:** any 2–64 KiB `.bin` dropped in `ingest/a2600/` reaches Review rather than `InvalidHeader`. Accepted: Review is recoverable and the new delete clears junk.
