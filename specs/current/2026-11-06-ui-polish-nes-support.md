# Game page polish, image URLs and NES support

## Summary
A round of SPA polish plus a fifth system. The game page gets consistent buttons (a Google logo on the Google buttons), a key/value info table, release cards instead of a horizontally scrolling table, an info.json modal with a bordered, self-scrolling JSON pane, and the Upload image button at the top of the Images tab. Library editors can add an image by pasting a URL: the server downloads it (public internet only) and stores it like an upload, or says why it couldn't. The Library card shows the size as a badge, and the navbar is reordered. Nintendo Entertainment System (`nes`) joins through the `ISystemHandler` plug-in, accepting headered `.nes` dumps.

## Out of scope
- Headerless NES dumps (`.unh`), UNIF (`.unf`), Famicom Disk System (`.fds`), NSF, and repairing non-canonical iNES headers (a dump whose header differs from No-Intro's goes to Review).
- Any change to `ISystemHandler`, `RomHeader`, the DB schema or the hotkeys table.
- Image URLs that need cookies, auth or a proxy; images other than PNG/JPEG; a client-side (browser) download.
- A dedicated NES icon (the controller fallback is used) and an auto DAT refresh after upgrading (documented manual step, as for N64).
- Redesigning other pages' buttons.

### Image from URL
- **U1 Endpoint.** `POST /api/games/{id}/images/from-url`, JSON `{ "url": string, "type": "BoxArt" | "Snap" }`, `LibraryEditor` policy and the antiforgery header like the other image routes. Returns the game detail (200) like the upload.
- **U2 Validation** (`400 ValidationFailed`, before any network access): `url` required, ≤ 1024 characters (the `images.source_url` column is `VARCHAR(1024)`), an absolute `http` or `https` URL without user info (`Enter an http or https image URL.`); `type` as the upload (`Choose BoxArt or Snap.`).
- **U3 Public addresses only.** The download uses its own named HTTP client (`imageUrls`): `SocketsHttpHandler` with `UseProxy = false`, `AllowAutoRedirect = true`, `MaxAutomaticRedirections = 3`, and a `ConnectCallback` that resolves the host, rejects the connection unless **every** resolved address is public, and connects to the vetted address (so DNS rebinding and redirects to internal hosts are caught on every hop). Not public (`PublicAddress.IsPublic`, IPv4-mapped IPv6 checked as IPv4): `0.0.0.0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16`, `172.16/12`, `192.0.0/24`, `192.0.2/24`, `192.88.99/24`, `192.168/16`, `198.18/15`, `198.51.100/24`, `203.0.113/24`, `224/4`, `240/4`; `::/96` (IPv4-compatible, including `::` and `::1`), `64:ff9b:1::/48` (local-use NAT64), `100::/64` (discard), `fc00::/7`, `fe80::/10`, `fec0::/10` (deprecated site-local), `ff00::/8`, `2001:db8::/32`, Teredo `2001::/32`, and 6to4 `2002::/16` (all blocked outright); `64:ff9b::/96` is checked as its embedded IPv4. A literal-IP host goes through the same callback (no DNS). The callback throws `BlockedAddressException`; `ImageUrlDownloader` maps an `HttpRequestException` whose inner exception is a `BlockedAddressException` to `400 ImageUrlBlocked`, title `The URL points to a private or local network address.`, and every other one to `ImageDownloadFailed` (U4).
- **U3a Problems.** Both new codes are built in the endpoint with the existing `Problems.Create(ctx, status, code, title)`; the cause is the problem `title` (the SPA's `ApiError` reads `title`, not `detail`), so no change to `Problems.cs` or `errors.ts`.
- **U3b Order.** The endpoint validates (U2), then checks the game exists (`IGameRepository.GetAsync` → `404 NotFound` without downloading), then downloads (U4), then calls `AddImageAsync`.
- **U3c Client registration.** `imageUrls` is registered in `HttpClients.cs` **without** the shared `Configure()` (no resilience handler: no retries, no 20 s Polly timeout) but with `RequestLoggingHandler` (Debug line per request, as for the other clients) and the shared `UserAgent`; its `HttpClient.Timeout` is `Timeout.InfiniteTimeSpan` because U4's token is the only timeout. The `HttpClients` class comment is updated to say the retry/20 s policy applies to the DAT and thumbnail clients only.
- **U4 Download.** `User-Agent: RnRomManager/<version>`, `Accept: image/png, image/jpeg`, a 15 s overall timeout (injectable so tests can shorten it), no retries. The timeout is one `CancellationTokenSource` (`CancelAfter(15 s)`) linked with `ctx.RequestAborted` and passed to both `SendAsync` and every body `ReadAsync`, so it covers the headers **and** the body (a server that trickles the body is cut off at 15 s). An `OperationCanceledException` is `timed out` only when the timeout source fired; when `RequestAborted` fired (client went away) it is rethrown, not mapped to a 502. An `IOException` (including `HttpIOException`) or `HttpRequestException` while reading the body (connection reset mid-download) maps to `couldn't connect.`. The request uses `HttpCompletionOption.ResponseHeadersRead` and the body stream is read with a bounded loop of at most `ImageFormats.MaxBytes + 1` bytes, whatever `Content-Length` says (never `GetByteArrayAsync` or a buffered read). Content type headers are ignored (the bytes decide). The endpoint checks the bytes itself, with these messages, before calling `AddImageAsync`. Outcomes, in this order:
  | Case | Response |
  |---|---|
  | DNS failure, connection or TLS error, or the connection dropping mid-body | `502 ImageDownloadFailed`, title `Couldn't download the image: couldn't connect.` |
  | Timeout (15 s from send to the last body byte) | `502 ImageDownloadFailed`, title `Couldn't download the image: timed out.` |
  | Final response is 3xx (more than 3 redirects, or an https→http hop the handler won't follow) | `502 ImageDownloadFailed`, title `Couldn't download the image: too many redirects.` |
  | Other non-2xx status | `502 ImageDownloadFailed`, title `Couldn't download the image: HTTP <code>.` |
  | Empty body | `400 ValidationFailed`, `url`: `The URL didn't return a PNG or JPEG image.` |
  | More than 8 MiB | `400 ValidationFailed`, `url`: `The image must be at most 8 MiB.` |
  | Not a PNG/JPEG (`ImageFormats.Detect`), or unreadable dimensions (`ImageFormats.Read`) | `400 ValidationFailed`, `url`: `The URL didn't return a PNG or JPEG image.` |
  | Downloaded fine | `LibraryEditor.AddImageAsync` as for an upload, so `DuplicateImage`, `TooManyImages`, `JobRunning` and the placeholder rule (I3) behave the same |
- **U5 Stored image.** Identical to an upload (`source: "upload"`) except `sourceUrl` is the URL as submitted. The `ImageAdded` audit row's details are `<fileName> from <url>` (truncated to the column as usual). The download runs before the job lock is taken, so a slow host never holds the lock.
- **U6 Upload modal.** A `File` / `URL` radio button group (`btn-check` + `btn btn-outline-secondary btn-sm`, `File` selected on open) above the fields. `File` shows today's file input; `URL` shows a `type="url"` input labelled `Image URL` with help `The server downloads the image. PNG or JPEG, at most 8 MiB.` The Type select is shared. `Upload` with an empty URL shows `Enter an http or https image URL.` without a request. While downloading the confirm button is busy. Success: toast `Image added from <hostname>.` (`new URL(url).hostname`, no port), modal closes. Failure: the URL field shows, as `invalid-feedback`, the problem `title` for `ImageDownloadFailed` / `ImageUrlBlocked` or `errors.url[0]` for validation, followed by `Download the image and upload the file instead.` and an `Upload a file instead` link-button that switches to `File` mode (keeping the Type); the modal stays open. Other failures toast as uploads do today. Every open (after success or cancel) resets everything: mode `File`, file and URL cleared, Type `Box art`, no errors.

### Nintendo Entertainment System
- **N1 Registration.** `NesHandler`, in a new `src/RnRomManager.Systems.Nes` project, is registered after N64. Systems list order: `gb`, `gbc`, `gba`, `n64`, `nes`.
- **N2 Contract values.** `Id` = `nes`, `DisplayName` = `Nintendo Entertainment System`, `Family` = `nes`, `RomExtensions` = `[".nes"]`, `MinRomSizeBytes` = `16 + 4096` (4112, the smallest `.nes` in the DAT; a standard iNES header can't describe less than 16 KiB of PRG, so this entry is an NES 2.0 / odd-sized dump — step 10 re-confirms it against the downloaded DAT and uses the real smallest `.nes` size if it differs), `MaxRomSizeBytes` = `16 + 512 + 64 MiB` (header, trainer, the largest multicart), `DatName` = `Nintendo - Nintendo Entertainment System` (the five libretro files and the thumbnails folder exist; checked 2026-11-06). `NormalizeForHashing` is the default (bytes as-is, header included), so dumps match the DAT's headered `.nes` entries, whose CRCs the metadat files key on (checked 2026-11-06).
- **N3 DAT extension filter.** `DatStore` takes the handler's `RomExtensions` (`DatCache.LoadSystem` passes them; an optional constructor argument, null = keep everything, for existing tests). DAT ROMs whose file extension (case-insensitive) isn't in the list are left out of the SHA1 index, `Roms` (review DAT search, suggestions) and `BaseTitles`; metadata still merges by the remaining ROMs' CRCs. Effect: NES ignores `.unh` and `.bin`; N64 ignores its 12 `.bin`/`.cmd`/`.sm` entries; GB, GBC and GBA are unchanged (every entry has their extension; checked 2026-11-06). The `Loaded DATs` log line reports the kept count.
- **N4 Header reader** (`NesHeaderReader.Read`). Never throws. Returns `null` under 16 bytes. Otherwise `ClassifiedSystemId` = `nes`, `Title` = null (iNES has none; suggestions use the file name), `IsPlausible` = `headerValid`. `Fields`:
  | Field | Source |
  |---|---|
  | `headerValid` | bytes 0–3 are `4E 45 53 1A` (`NES` + EOF) |
  | `format` | `NES 2.0` when `(byte7 & 0x0C) == 0x08`, else `iNES`; null when not `headerValid` |
  | `mapper` | `(byte6 >> 4) \| (byte7 & 0xF0)`, plus `(byte8 & 0x0F) << 8` for NES 2.0 |
  | `prgRomSizeBytes` | `byte4 × 16384`; NES 2.0: `((byte9 & 0x0F) << 8 \| byte4) × 16384`, null when `(byte9 & 0x0F) == 0x0F` (exponent form) |
  | `chrRomSizeBytes` | `byte5 × 8192`; NES 2.0: `((byte9 >> 4) << 8 \| byte5) × 8192`, null when `(byte9 >> 4) == 0x0F` |
  | `mirroring` | `Four-screen` when byte6 bit 3, else `Vertical` (bit 0 set) or `Horizontal` |
  | `battery` | byte6 bit 1 |
  | `trainer` | byte6 bit 2 |
  | `tvSystem` | NES 2.0: byte12 `& 3` → `NTSC`, `PAL`, `Multi-region`, `Dendy`; iNES: byte9 bit 0 → `PAL` or `NTSC` |
  | `romSizeBytes` | the length |
  When `headerValid` is false only `headerValid` and `romSizeBytes` are set (the rest null).
- **N5 Ingestion.** The existing pipeline. A matched dump is stored like any other system: a game ZIP `roms/nes/<bucket>/<sanitized title>.zip` whose ROM entry is the DAT ROM name (`….nes`). Unmatched + valid header → Review (suggestions from the file name). Unmatched + no `NES\x1A` → `InvalidHeader`. Under 4112 bytes → `TooSmall`. A `.nes` file in another family's folder, or another family's file in `ingest/nes/` → `UnsupportedType`.
- **N6 Badge colour.** `systemColours` gets `nes: { name: 'warning', foreground: '#000' }` (the `name` union gains `'warning'`), used by `SystemBadge` and the treemap.
- **N7 Default box art.** `nes.svg` (drawn for this project, MIT) and its 512×512 `nes.png` render, embedded like the N64 ones.
- **N8 Upgrade.** Ingestion refuses with `DatsMissing` until an Admin runs **Admin → DATs → Refresh DATs** (documented).

## Risks
- **SSRF.** A library editor can make the server fetch URLs. Mitigated by U3: public addresses only, checked at connect time for every hop, no proxy, 15 s, 8 MiB, bytes validated as PNG/JPEG. Deployments behind a mandatory egress proxy can't use the feature (documented); file upload still works.
- **Ingestion blocked after upgrade** (N8) until DATs are refreshed. Documented in README and `deployment.md`.
- **N3 changes DAT search/suggestions for N64** (drops 12 `.bin`/`.cmd`/`.sm` entries). Those could only ever have been stored with a foreign extension, so dropping them is a fix; covered by a DatStore test.
- **Non-canonical NES headers** (old iNES dumps with junk in bytes 7–15) don't match the DAT and go to Review. Accepted (out of scope).
- **A 5th system breaks existing tests** (`DatsMissing`, counts). Fixed in the same step as the registration.
- **Release cards change selectors** in vitest and e2e (rows → cards). Updated in the same step.
- No real ROMs or images from the internet in tests: synthetic ROMs, and a local stub server for the URL tests (allowed only through a test-only `PublicAddress` override, see step 6).
