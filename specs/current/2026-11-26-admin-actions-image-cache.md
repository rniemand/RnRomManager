# Admin actions, cover image cache and IGDB ratings

## Summary
Admins get an **Actions** tab with two one-click jobs: **Pull Cover Images** (the IGDB cover becomes each linked game's cover, recorded in `info.json` → `actions.coverImagePulled` and in a new `game_actions` table) and **Refresh IGDB Ratings** (IGDB's `total_rating` and vote count, stored in the database and shown on the game page). Library cards load covers from a new resized WebP **image cache** on its own path. Everyone sees in the footer when the job lock is held, Edit Metadata shows a progress bar while it saves, and a game card gets a green **Pick up where you left off** button that plays the user's newest save.

## Out of scope
- Importing library ZIPs (the table and `info.json` mirror only make it possible later).
- Real percentage progress for library edits (the save keeps its requests: the PATCH, plus the cover requests of **Use this match and save**; the bar is indeterminate and spans all of them).
- Caching anything but the cover (Images tab, snaps and the game page keep reading the ZIP).
- IGDB ratings in `info.json` (database only, by decision), schedules for either action, an audit row for a ratings refresh (the job row is the record), and a per-game "refresh from IGDB" button.
- A schema version bump: `actions` is optional and left out when empty, as `chosenPrimarySha1` is.

## Behaviour

### `info.json` actions and the `game_actions` table
- **A1** `info.json` gains an optional top-level object `actions`, written after `images` only when it has a value: `{"coverImagePulled": "<ISO-8601 UTC>"}`, written with the round-trip format `"O"` from a UTC `DateTimeOffset` truncated to whole seconds (e.g. `2026-11-26T10:15:30.0000000+00:00`), so the value survives `DATETIME(6)` unchanged. `coverImagePulled` is the time Pull Cover Images last made the IGDB cover this game's cover. In C#: `InfoJsonGame.Actions` (`InfoJsonActions?`, declared after `Images` and before `Metadata`, `[JsonIgnore(Condition = WhenWritingNull)]` as `ChosenPrimarySha1` has), with `InfoJsonActions.CoverImagePulled` a `string?` (so a bad value reaches the validator, not the deserializer). `{coverImagePulled: null}` is normalised to `Actions = null` before writing, so it is left out. `schemaVersion` stays `8` (no upgrader; older apps ignore and drop it, as for `chosenPrimarySha1`). Every writer that builds a game with `with` keeps `Actions`; the two `new InfoJsonGame` sites (`IngestPipeline`, `LibraryEditor.NewGameForAsync`) start a new game without it, which is correct.
- **A2** Validation: `actions` absent, `null` or an object; `actions.coverImagePulled` absent, `null` or a string `DateTimeOffset.TryParse` (invariant culture, round-trip styles) accepts. A bad time is `InfoJsonInvalid` with the rule text "actions.coverImagePulled must be an ISO-8601 time" (`InfoJsonValidator`). A non-object `actions` is "actions must be an object": `InfoJsonReader` checks the parsed `JsonObject`'s `actions` node after the upgraders and before `Deserialize` and returns `InfoJsonReadResult.Invalid("actions must be an object", fileVersion)` when it is neither an object nor null (tested in `InfoJsonTests`). Unknown keys inside `actions` are ignored on read and dropped on write.
- **A3** New table `game_actions` (migration `0029_game_actions.sql`, `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci` as `0025` uses), one row per game that has any value: `game_id CHAR(36) NOT NULL PRIMARY KEY` (same type as `games.id`; **no** foreign key), `cover_image_pulled_at DATETIME(6) NULL` (UTC), `last_igdb_sync_at DATETIME(6) NULL` (UTC), `igdb_rating DOUBLE NULL`, `igdb_rating_count INT NULL`. Existing installs start with an empty table; v8 ZIPs have no actions, so that is already correct.
- **A4** Mirror: every `LibraryMirror.ApplyAsync` replace upserts `game_actions.cover_image_pulled_at` from the game's `actions.coverImagePulled` (inserting the row only when the value is non-null, or updating an existing row to the value, null included) in the same transaction and never touches the IGDB columns. There is no FK because the mirror deletes and re-inserts `games` rows on every write, which would cascade away the database-only IGDB columns. An id in the `delete` list that isn't re-inserted (a deleted game, a merged-away source game) has its `game_actions` row deleted in the same transaction. A game the mirror removes only through the `zip_path` clash delete is left to the A5 sweep.
- **A5** Integrity: the database-repair step (`DbSync`) mirrors `actions` like every other field, so a ZIP whose size or mtime changed (an imported or hand-edited ZIP) updates `cover_image_pulled_at`. A **Deep** or **Game** run also compares, for every ZIP it opens, `cover_image_pulled_at` (from `IGameRepository.ListCoverPulledAsync`, new: `game_id` → time for every row with a value) with `actions.coverImagePulled`, both as UTC truncated to whole seconds (a hand-edited value may carry sub-microsecond digits the column can't hold), and fixes a mismatch through `ILibraryMirror.ReplaceAsync`, recorded as an `AutoRepaired` `DbRowUpdated` issue like other repairs. Each Quick or Deep run (not Game mode) deletes `game_actions` rows whose `game_id` has no `games` row (`IGameRepository.DeleteOrphanActionsAsync`, new).
- **A6** Changing or clearing a game's IGDB link (Edit Metadata, **Not on IGDB**, the lookup's **Use this match**, any `PATCH /api/games/{id}` that changes `igdbId`, or a merge whose target takes the source's `igdbId`) removes `actions.coverImagePulled` in the same ZIP write and clears the row's `igdb_rating`, `igdb_rating_count` and `last_igdb_sync_at`, so both actions pick the game up again. The clearing is a new `IGameRepository.ClearIgdbSyncAsync(gameId, ct)` (sets the three columns null). The ZIP side lives in the two shared builders in `LibraryEditor.cs`, `Patched` (edits) and `MergedInto` (merges), which drop `Actions` when the result's `IgdbId` differs from the target's. `ClearIgdbSyncAsync` is called right after the mirror succeeds, only when `igdbId` changed, by all four callers of those builders: `PatchAsync` and `MergeAsync` (`LibraryEditor.cs`), and `PatchExternalAsync` and `MergeExternalAsync` (`LibraryEditor.External.cs`, external-ROM systems). A failure there is logged as a warning and the edit still succeeds.

### Pull Cover Images (job `PullCovers`)
- **P1** `POST /api/jobs/pull-covers` (Admin, antiforgery), mapped beside `POST /api/jobs/media-retry` in `LibraryEndpoints.cs` → `202 {jobId}`; `409 JobRunning` (`DatEndpoints.JobRunning`) when the lock is busy; `409 IgdbNotConfigured` ("Pulling covers needs Sources:IgdbClientId and Sources:IgdbClientSecret.") when `SourcesOptions.IgdbConfigured` is false, checked by the endpoint before `JobRunner.StartAsync`, as `GET /api/games/{id}/image-suggestions` does. Not cancellable mid-ZIP, but cancellable between games (`Cancellable` true, the default).
- **P2** Candidates: games with `igdb_id > 0` and no `game_actions.cover_image_pulled_at`, ordered by `g.title, g.id` as `ListMediaRetryCandidatesAsync` orders (`IGameRepository.ListPullCoverCandidatesAsync`, new, returning `GameRow`s). Games of a system whose storage migration is pending are not filtered here: `RomStorage.IsPending` needs the ZIP's `info.json`, so P4 skips them.
- **P3** IGDB is queried in batches of up to 500 ids: `fields cover.image_id,total_rating,total_rating_count; where id = (<ids comma-separated>); limit 500;` (`IgdbClient.GetGamesAsync(IReadOnlyList<int> ids, ct)`, new, shared with R2, returning `IgdbGameRating(int Id, string? CoverImageId, double? TotalRating, int? TotalRatingCount)` records, new; a failure throws an exception whose message is one of the existing titles `IgdbClient.Unreachable`, `Refused`, `Busy`, `Unreadable`, or `ThrowOnStatus`'s "IGDB returned HTTP <n>." for another non-2xx status, mapped as `GamePageUrlAsync` maps them: a connection error or timeout is `Unreachable`; cancellation propagates). The cover downloaded is `https://images.igdb.com/igdb/image/upload/t_1080p/<image_id>.jpg` (`IgdbClient.ImageBaseUrl` + `t_1080p`, the size **Use this match** stores) via `IgdbClient.DownloadCoverAsync(imageId, ct)` (new) on the IGDB `HttpClient` (`ImageUrlDownloader` lives in the Api project, so a Core job can't use it), reading at most `ImageFormats.MaxBytes` + 1 bytes. It returns `IgdbCoverDownload(byte[]? Bytes, int? Status, string? Error)` (new): `Bytes` on a 200 within the limit; `Status` for any other response, or a body over the limit (`Error` "The image is larger than 8 MiB."); `Status` null with `Error` the exception message for a connection error or timeout. The bytes must pass `ImageFormats.Read` (a PNG/JPEG within 8 MiB whose size can be read).
- **P4** Per game, under the job lock the job already holds. The job never calls `LibraryEditor` (every editor method takes the lock itself); it reads and writes the ZIP itself exactly as `GameMediaRetry.RetryAsync` does: `LibraryTarget.OpenForWrite`, the ZIP's own `info.json`, a `LibraryZipWriter` at the system's compression (`IRomStorageSettings.Compression`), `WriteCheckedAsync` when `LibraryTarget.NeedsCheck`, else `WriteAsync`, then `ILibraryMirror.ReplaceAsync(new MirrorEntry(...))`, with `Metadata` `UpdatedAt` now and `AppVersion` `AppInfo.Version`. Cases, first match wins:
  - The ZIP can't be opened (`LibraryTarget` code) → outcome `Error` with that code; the job continues.
  - The system's storage migration is pending (`RomStorage.IsPending(handler, game)`) → `Skipped`; nothing written.
  - The ZIP already has `actions.coverImagePulled` (the database lost it) → the game is re-mirrored and the outcome is `Skipped`; nothing written.
  - The ZIP's `igdbId` is null, ≤ 0 or differs from the id queried → `Skipped`; nothing written.
  - IGDB has no cover, or the IGDB id isn't returned → outcome `NoCover`; nothing written or recorded (retried next run).
  - The download fails or the bytes fail `ImageFormats.Read` → outcome `Error` with the message; the job continues.
  - An image with the same SHA1 is already in the ZIP → it becomes the cover (`isCover` moves to it; every other image `isCover` false).
  - Otherwise a new `BoxArt` image is built as `LibraryEditor.AddImageAsync` builds a from-URL upload (`GameImages.NextName`, `source` `upload`, `sourceUrl` the IGDB URL, the placeholder removed when there is one) and made the only cover. **It replaces whatever was the cover, an Admin upload included** (user decision). The `GameImages.MaxImages` (20) limit is checked after the placeholder is removed, as `AddImageAsync` does; still over it → outcome `ImageLimit`, nothing written.
  - A ZIP write or mirror failure (`IoError`, `VerifyFailed`, `DbWriteFailed`) → outcome `Error` with that code; the job continues.
  - The write sets `actions.coverImagePulled` to now, mirrors the row (A4) and records `MediaFetched` in the audit log with Details `IGDB cover <file name>` once the ZIP is written (as `GameMediaRetry` does). When the placeholder was the cover, or the game had no image, the game's open `DefaultBoxArt` and `MissingBoxArt` integrity issues are resolved with `IIntegrityIssueRepository.ResolveOpenAsync(zipPath, type, now)` (B14, as `StartGameCheckAsync` does under the lock); a failure there is logged as a warning. Outcome `Pulled`.
- **P5** Any `GetGamesAsync` failure stops the job, which ends `Failed` with that title as its error (the exception's message, as `JobRunner` records it). Cover downloads go through one `CircuitBreaker` per run, as `MediaRetryJob` uses it: an `IgdbCoverDownload` with `Status` null or ≥ 500 is `RecordFailure`, a 200 `RecordSuccess`, anything else (a 404 included) neither; when it opens, the job stops and ends `Failed` with "IGDB images couldn't be reached." The comment in `Api/Http/HttpClients.cs` listing the IGDB client's hosts adds `images.igdb.com`. Summary: `{pulled, noCover, imageLimit, skipped, error}`. One `job_items` row per game, written as `ZipRepackJob` writes them (`FileId` and `GameId` the game id, `SystemId`, `SourcePath` `AuditPaths.Library(zipPath)`, `Outcome`, `Reason` the error code, `Details` the message).

### Refresh IGDB Ratings (job `IgdbSync`)
- **R1** `POST /api/jobs/igdb-sync` (Admin, antiforgery), beside P1 → `202 {jobId}`, `409 JobRunning`, `409 IgdbNotConfigured` ("Refreshing ratings needs Sources:IgdbClientId and Sources:IgdbClientSecret.", checked as P1). Cancellable between batches.
- **R2** Every game with `igdb_id > 0` (`IGameRepository.ListIgdbLinkedAsync`, new), every run, ordered as P2, in batches of 500 through `IgdbClient.GetGamesAsync`. Per game: upsert `game_actions` with `igdb_rating` = `total_rating` (null when IGDB has none), `igdb_rating_count` = `total_rating_count` (null when none) and `last_igdb_sync_at` = now (`IGameRepository.SaveIgdbSyncAsync(gameId, rating, count, syncedAt, ct)`, new; one call per game, never touching `cover_image_pulled_at`). Outcomes: `Updated` (has a rating), `NoRating`, `NotFound` (id not returned by IGDB; columns set null, sync time set). **Never writes a ZIP or `info.json`** (user decision).
- **R3** Failure handling as P5 (no downloads, so no breaker). Summary `{updated, noRating, notFound}`. One `job_items` row per game, as P5.
- **R4** `GET /api/games/{id}` adds `igdbRating: {score: number, votes: number, syncedAt: string} | null` (null unless `igdb_rating` is set; `score` is the raw value, `votes` the count or 0, `syncedAt` `last_igdb_sync_at` as UTC ISO-8601), read in `DetailAsync` through `IGameRepository.GetActionsAsync(gameId, ct)` (new, returning `GameActionsRow?` with the four columns).

### Image cache
- **C1** New setting `Paths:ImageCache` (env `Paths__ImageCache`, default `/app/imagecache`), the eighth path in `PathsOptions.All()`: same rules (absolute, created, probed at startup, checked by `/health/ready`, different from and not inside the others). Dockerfile creates `/volumes/imagecache` and adds `/app/imagecache` to `VOLUME`; `scripts/setup-dev.ps1` creates `.dev/imagecache`. Not in database backups (it is rebuilt from the ZIPs).
- **C2** `CoverCache` (new, `Core/Library/CoverCache.cs`, singleton registered in `AppHost.cs`): `string? CachedPath(Guid gameId, string coverSha1)` (the file when it exists) and `Task<CoverCacheResult> GenerateAsync(Guid gameId, string coverSha1, Stream cover, CancellationToken ct)` (`CoverCacheResult(byte[]? Webp, bool Stored)`, new: `Webp` null when decoding or encoding failed). A cached cover is `<ImageCache>/<gameId>/<coverSha1>.webp`: the cover decoded with SkiaSharp, its longest side scaled down to at most 512 px (never up, aspect kept, high-quality sampling), encoded WebP quality 80. Written to `<coverSha1>.webp.<random>.tmp` in the same folder, then moved over (two simultaneous generations are harmless). Guards: the dimensions are read with `SKCodec` before decoding, and a side over `ImageFormats.MaxWebpSide` (4096, `internal` to Core) is a failure (C3 fallback, nothing cached). At most 2 generations run at once (`SemaphoreSlim(2)`); a caller waits for a slot, cancelled with its token (`RequestAborted` for C3).
- **C3** `GET /api/games/{id}/cover/{sha1}` (any signed-in user, on the `games` group): when `sha1` isn't exactly (ordinal) the game's current cover SHA1 from `IImageRepository.ListByGameAsync` (or the game has no cover) → `404 NotFound`; only the database's value is used to build a path. A cached file → `Results.File` as `image/webp` with `Cache-Control: private, max-age=31536000, immutable` and ETag `"<sha1>"` (a matching `If-None-Match` → `304`). Missing → the cover entry is opened with `LibraryFiles.OpenEntry(ctx, game, LibraryZip.ImageEntry(fileName), ImageFormats.MaxBytes, ...)` (its problems, e.g. a missing ZIP, returned as they are), generated (C2) and the WebP bytes served with the same headers. If decoding or encoding fails, the original entry (opened again, since generation consumed the first stream) is served exactly as `GET /api/games/{id}/images/{imageId}` does (its own content type, `private, max-age=86400`), nothing is cached and a warning is logged. If the cache folder can't be written (`Stored` false), the generated bytes are still served and an error logged. No job lock is taken.
- **C4** `boxArtUrl` becomes `/api/games/<id>/cover/<sha1>` in `LibraryEndpoints.ToListItemDto` (every `/api/games` list: Library, collection pages, global search and the typeahead; discovery group pages; the Timeline) and in the duplicates report in `ReportEndpoints.cs`. The list query in `LibraryRepositories.cs` adds the cover's SHA1 (`BoxArtSha1`, beside `BoxArtImageId` on `GameListItem`); the duplicates query in `Data/Repositories/ReportRepository.cs` does the same, with a `BoxArtSha1` added to `DuplicateGame` in `Core/Reports/IReportRepository.cs`. Assertions that change: `LibraryEndpointsTests` line 1281 (`boxArtUrl` equal to the cover's `/images/` URL → `/api/games/<id>/cover/<sha1>`) and `ReportEndpointsTests` line 468 (starts with `/api/games/{bravo}/images/` → `/api/games/{bravo}/cover/`); `LibraryEndpointsTests` line 472 (fetches `boxArtUrl`, expects 200) keeps passing. A cover change produces a new SHA1 and therefore a new file; the old one is removed by C5.
- **C5** Integrity (Quick and Deep, after database repair; not Game mode) adds an **Image cache** step: for each game with a cover (`IImageRepository.ListCoversAsync`, new: game id, cover file name and SHA1) whose `CoverCache.CachedPath` is null, generate it (opening only the ZIP's cover entry); then delete every file and folder under `Paths:ImageCache` that isn't a current game's `<id>/<coverSha1>.webp` (stale `.tmp` files older than an hour included), except the startup probe file (`StorageFolders.ProbeFileName`). Links are deleted, never followed. `IntegrityJob` gets `CoverCache` and `ILibraryMirror` through its constructor; `IntegrityJobFactory` in `AppHost.cs` builds it with `ActivatorUtilities`, so it needs no change, but the two direct constructions in `IntegrityJobTests.cs` (lines 125 and 566) do. A cancelled run generates what it reached and deletes nothing. A failure on one game is logged and counted, never an integrity issue. Summary adds `cacheGenerated`, `cacheRemoved`, `cacheFailed`.

## Risks
- **Pull Cover Images rewrites every linked game's ZIP** (one full re-deflate each) and replaces hand-picked covers; the confirm says so. Old covers stay in the ZIP as non-cover images, so nothing is lost.
- **Large cache folder on first run**: about 30–60 KB per game; built lazily or by integrity. The first Quick run after upgrading opens every game's cover entry once.
- **DB-only IGDB ratings** are lost if the database is rebuilt without a backup; re-running the action restores them.
- **Deployments without the new volume** keep the cache in an anonymous volume (lost on recreate, just rebuilt); the docs say to add the mapping.
- **`TryAcquire` signature change** touches 25 production and 63 test call sites; compile errors find them all.
- **`/api/activity` polling** renews every visible signed-in tab's sliding session every 15 s, as the Admin job poll already does.
