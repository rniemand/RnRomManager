# Image Resolutions report, job names and report polish

## Summary
Admins and users get a new **Image Resolutions** report to find low-resolution box art, screenshots and other images stored in game ZIPs, with System / Type / Max width / Max height filters remembered in the browser. Job names are Title Case everywhere, and the running-job progress cell no longer resizes its table as file names change. Newly Added and Activity switch to tabs, and the Multiple Releases and Missing Metadata filter bars get compact, evenly sized controls.

## Out of scope
- Fixing images from the report (replacing or re-downloading): the row links to the game's Images tab, which keeps its own Admin rules.
- A "next low-resolution image" button, column sorting or a page-size choice on the new report.
- The other reports' filter bars (Missing Images, Duplicates, Games With Hacks), the server-side job types and the `GET /api/reports/newly-added` contract.
- Placeholder art (`images.is_default = 1`): Missing Images already reports it.

## Behaviour

### Job names (J)
- **J1** `jobLabels` in `lib/jobs.ts` become Title Case: `Ingest`, `Integrity Check`, `DAT Refresh`, `Media Retry`, `Review`, `Moving ROMs`, `Repacking ZIPs`, `Moving Saves to User Folders`. Unknown types still show as is.
- **J2** Every place that shows a job type uses `jobLabel(type)` (plus ` (<mode>)` where it does today): the job detail heading, the Activity report's Recent jobs table (`routes/reports/activity/+page.svelte:222`), the Integrity page's run table (`routes/integrity/+page.svelte:370`) and the "running" banners on Ingestion (`routes/ingestion/+page.svelte:229`), Integrity (`:182`) and DATs (`routes/admin/dats/+page.svelte:105`). The footer and `/jobs` already use it.
- **J3** The job detail heading is `{jobLabel(job.type)}{job.mode ? ` (${job.mode})` : ''} Job`, e.g. "Ingest Job", "Ingest (Quick) Job", "DAT Refresh Job".

### Running-job progress (P)
- **P1** The `/jobs` Running table and the `/jobs/[id]` header table get `table-layout: fixed` through a new `job-fixed-table` class in `src/RnRomManager.Web/src/app.css` (`table-layout: fixed; min-width: 50rem;`, which leaves Progress at least 14rem on `/jobs` and 20rem on the detail page), so on a phone the existing `table-responsive` wrapper scrolls instead of squeezing Progress.
- **P2** Fixed column widths via a `<colgroup>`: `/jobs` Running — Job `14rem`, Progress (no width, takes the rest), Started `11rem`, Details `5rem`, Cancel `6rem`. `/jobs/[id]` while live — Started `11rem`, Finished `11rem`, Trigger `8rem`, Progress (rest). When not live, the detail table has no `job-fixed-table` class and no `<colgroup>` (as today): add it with `class:job-fixed-table={live}` and wrap the `<colgroup>` in `{#if live}`. Every table keeps the house classes `table table-sm table-striped table-hover` and `<thead class="table-dark">`, which `lib/table-style.test.ts` checks in every `.svelte` file.
- **P3** The progress text line (`current / total · currentItem`) and `JobStepProgress`'s `formatStep` line use `text-truncate` instead of `text-break`, with `title` set to the full text, so long names end in "…". The inline `style="min-width: 14rem"` on the Progress cells is removed. `JobStepProgress` is also shown on the Ingestion, Integrity and Review pages (`routes/review/[id]/+page.svelte`); its step line truncates there too, which is intended.

### Image Resolutions report (R)
- **R1** API `GET /api/reports/image-resolutions` (every signed-in user, like Missing Images). Query: `system` (registered id), `type` (`BoxArt`, `Snap`, `TitleScreen` or `Other`, matched by name ignoring case: `Enum.TryParse<ImageType>(type, ignoreCase: true, …)` plus `Enum.IsDefined`, and a value that is all digits is rejected, so `1` is a 400), `maxWidth`, `maxHeight` (whole numbers 1–100000), `page`, `pageSize` (the shared `Paging.Validate` rules, default 50).
- **R2** Validation is a 400 ProblemDetails from `Problems.Validation`, keyed by field: `system` "Choose a registered system." (existing `Validate` helper), `type` "Must be BoxArt, Snap, TitleScreen or Other.", `maxWidth` / `maxHeight` "Must be 1–100000.". They bind as `int?` like `page`, so a non-numeric value gets the same framework 400 that `page=abc` gets today (no field key); the SPA never sends one (R9).
- **R3** Rows: every `images` row with `is_default = 0` of a game, filtered by system and type when set. With `maxWidth` and/or `maxHeight` set, a row is listed when `width <= maxWidth` **or** `height <= maxHeight` (an unset limit is ignored; none set lists every image). Order: `width * height` ascending (compute as `CAST(i.width AS SIGNED) * i.height`, no overflow for INT columns), then system id, display title, image id. `images.type` is a `VARCHAR`, so the repository passes the filter as `type?.ToString()` (Dapper would send an enum as its number) and reads it back into `ImageType` as `ImageRow` does.
- **R4** Response: `{ items: [{ imageId, gameId, displayTitle, system, systemName, type, width, height, sizeBytes }], page, pageSize, total }`, `systemName` as other reports (`SystemName`).
- **R5** Page `/reports/image-resolutions`, tab **Image Resolutions** with icon `report-image-resolutions` → `bi bi-aspect-ratio`, placed after **Games With Hacks** (before the Admin-only tabs). `<svelte:head>` title "Image Resolutions · RnRomManager".
- **R6** Filter bar (the toolbar of L1): System `FilterDropdown` (as other reports, `systemFilterOptions`, "All systems"), **Type** select (All types / Box art / Screenshot / Title screen / Other), **Max width** and **Max height** number inputs (`min=1`, `max=100000`, `step=1`, empty = no limit, applied on `change`, each an input group with a trailing `<span class="input-group-text">px</span>`, the input `style="width: 6rem"`; ids `image-resolutions-type`, `image-resolutions-max-width`, `image-resolutions-max-height`), and a **Clear** button (disabled when nothing is set) that resets all four. Any filter change goes to page 1. A typed value that isn't a whole number in 1–100000 is treated as empty (no limit) and the input is reset to empty.
- **R7** Columns: preview (`<img>` from `/api/games/{gameId}/images/{imageId}`, `loading="lazy"`, `alt=""`, max 4rem × 4rem, `object-fit: contain`), **Game** (link `href="{resolve('/games/[id]', { id })}?tab=images"` with the same eslint-disable comment as `routes/reports/missing-images/+page.svelte:97`), **System** (`SystemBadge`), **Type** (the labels of R6), **Resolution** (`<width> × <height>`), **Size** (`FileSize`). A count line above the table as Missing Metadata's ("1,234 images" / "1 image"), 50 per page with `<Pagination … label="Image pages" />`.
- **R8** Empty states, as Newly Added's (`<div class="card"><EmptyState message=… /></div>`, no icon): no filter set → "No images yet."; a filter set → "No images match these filters.".
- **R9** State lives in the URL (`?system=&type=&maxWidth=&maxHeight=&page=`, defaults left out). `type` uses the API spelling, matched exactly (`BoxArt`, `Snap`, `TitleScreen`, `Other`); `maxWidth`/`maxHeight` must be whole numbers in 1–100000 and `page` a whole number ≥ 1; any other value falls back to its default. `system` is passed as is: an unknown one (from the URL or a restored query) gets the API's 400 shown in `ErrorAlert`, and **Clear** still works. A page past the last one goes to the last page (replace), as Multiple Releases B20. The state is remembered in `localStorage` under `rnrm.reports.image-resolutions` (the query string, via `remembered`). Opening the page with none of those params restores the saved query (replace navigation), exactly as `routes/review/+page.svelte` does with `reviewFilter.ts`; after that every URL state is saved. Storage failures are ignored.
- **R10** The image type labels (`Box art`, `Screenshot`, `Title screen`, `Other`) move from `GameImages.svelte`'s local `typeLabels` to an exported `imageTypeLabels` in the new `lib/imageResolutions.ts`, used by both.

### Report layout (L)
- **L1** Toolbar convention for report filter bars this spec touches: a `d-flex flex-wrap align-items-center gap-2 mb-3` container (as the Library and Audit pages), every control small: `FilterDropdown` as is, selects and inputs inside `input-group input-group-sm w-auto` (except Missing Metadata's Title, L3) with the visible label as `<label class="input-group-text" for=…>`, buttons `btn-sm`. A `form-select` inside such a group also gets `w-auto` (Bootstrap gives it `width: 1%` in an input group, which collapses inside a shrink-to-fit group); number inputs get the fixed width of R6. All controls then share `btn-sm` height.
- **L2** Multiple Releases: System dropdown then the **Minimum releases** input group (label text unchanged, still `for="multiple-releases-min"`), side by side with a `gap-2` gap.
- **L3** Missing Metadata: the toolbar holds **Title** (input group with classes `input-group input-group-sm flex-grow-1 flex-md-grow-0 missing-metadata-title`; new `app.css` rule `@media (min-width: 768px) { .missing-metadata-title { width: 16rem; } }`, so it fills the row on phones and is 16rem from `md`), System, **Missing** (input group) and **Clear** (`btn btn-sm btn-outline-secondary`, its `w-100` dropped). The `<form role="search">` and the ids `missing-metadata-q` / `missing-metadata-missing` stay.
- **L4** Newly Added: the System dropdown is replaced by tabs, one per system in the response order (systems A–Z), using the game-page tab markup (`ul.nav.nav-tabs` with `use:scrollActiveTab` and `role="tablist"`, `button.nav-link` with `id="newly-added-<system>"`, `role="tab"`, `aria-selected`, `aria-controls="newly-added-panel"`, and `title` the system's full name on the button). Each tab's content is `<SystemBadge system name={shortName} />` (short name from `/api/systems`, the upper-cased id when unknown). One panel (`role="tabpanel"`, `id="newly-added-panel"`, `aria-labelledby="newly-added-<selected system>"`, inside one `card`) shows the chosen system's table (Game, Added, Releases as today), without the card header.
- **L5** Newly Added tab state is `?system=` (replace navigation, `reset: false`); a missing or unknown id selects the first tab without changing the URL. The page fetches `GET /api/reports/newly-added` once, unfiltered; switching tabs does not refetch. Empty: "No games yet." (unchanged).
- **L6** Activity: the accordion becomes tabs in the same order (Added ROMs, Sign-ins, Plays, Saves, Edits, Deletions, Recent jobs, Last backup), same markup as L4 with text labels, Added ROMs selected first. Tab buttons `id="activity-<key>"` with `aria-controls="activity-<key>-panel"` (no icons), panels keep `id="activity-<key>-panel"` (`role="tabpanel"`, `aria-labelledby="activity-<key>"`), each its own `card`, all mounted and `hidden` when not selected. Each panel starts with `<h2 class="h5 visually-hidden">` holding the section title (as the game page's releases panel). Tab state is page state (not URL), as today's open section. The note above stays above the tabs.

## Risks
- **Performance:** the report scans `images` joined to `games` with no index on width/height and sorts on `width * height`. A home library (tens of thousands of images) stays well under a second; no index is added. Revisit if it grows to millions.
- **Bandwidth:** previews load the full image; `loading="lazy"` and 50 rows per page keep it bounded, and low-resolution images are small by definition.
- **Renamed labels:** J1 changes visible text that tests assert (listed per step). No API or stored value changes.
- **AccordionItem** stays: still used by Backups, DATs, Ingestion and Integrity.

Every step runs `pwsh scripts/codemap.ps1` and commits `docs/codemap.md` (it lists endpoints, routes and lib files).
