# Collection game picker and Game Gear

## Summary
Two changes. (1) The collection page's **Add games** search no longer suggests games already in the collection, and every game picker (`GameTypeahead`) shows each result's cover and a short system name (`SNES`, not "Super Nintendo Entertainment System"). (2) Sega Game Gear (`gg`) joins as the ninth system, in a new `RnRomManager.Systems.Sega` project.

## Out of scope
- Short system names anywhere other than `GameTypeahead` results (Library cards/rows, game page, global search, reports keep full names).
- Sega Master System, SG-1000 and a Master System handler (the 25 SMS-mode `.sms` entries in the Game Gear DAT are Game Gear games and are handled here).
- A dedicated `gg` icon (the controller fallback is used) and an automatic DAT refresh after upgrading (documented manual step).
- Thumbnail-sized cover images: the picker uses the same `boxArtUrl` the Library grid already loads.

## Behaviour

### Short system names
- **N1 Contract.** `ISystemHandler` gains `string ShortName => DisplayName;` (a default member, so test fakes keep compiling). Every shipped handler overrides it: `gb` → `GB`, `gbc` → `GBC`, `gba` → `GBA`, `n64` → `N64`, `nes` → `NES`, `snes` → `SNES`, `a2600` → `2600`, `coleco` → `CV`, `gg` → `GG`.
- **N2 API.** Each `GET /api/games` item gains `systemShortName`: the handler's `ShortName`, or the system id when the handler isn't registered (as `systemName` does). Nothing else changes in the response. `GameListItem` in `types.ts` gains `systemShortName: string`.

### Game picker
- **P1 Exclude members.** `GET /api/games` gains `notInCollection=<id>`: only games **not** in that collection are returned (`NOT EXISTS` on `collection_games` for that id); every other filter, sort and paging still applies, and it may be combined with `collection` (the result is then empty when both name the same collection). Parsed like `collection` in `ParseQuery`: not a GUID → `400` field `notInCollection` "Must be a collection id."; well-formed but unknown or another user's → `404`, exactly as B15 of the collections spec. Memberships of games no longer in the library don't matter (the query starts from `games`).
- **P2 Picker prop.** `GameTypeahead` gains an optional `excludeCollection?: string` prop, sent as `notInCollection` when set. The collection page's Add games picker passes its collection id. The existing "Already in this collection" toast stays for the race where a game is added elsewhere between search and pick.
- **P3 Cover.** Every result row shows the game's cover on the left: `<img src={boxArtUrl} alt="" loading="lazy">` in a fixed 32×40 px box (`object-fit-contain`, as the Library grid and global search game thumbnails), or `<Icon name="system-{game.system}">` in the same box when `boxArtUrl` is null (the fallback `GameResults.svelte` and `GlobalSearch.svelte` use). Decorative (`alt=""`): the button's text already names the game. Applies to all four picker uses (collection page, Game admin move/merge/attach, Review).
- **P4 Short name.** When the picker shows the system badge (no `system` prop, B24 of the collections spec), the badge text is `systemShortName` and the badge has `title` = `systemName` (full name on hover; `SystemBadge` gains an optional `title` prop). Pickers with a `system` prop still show no badge.

### Game Gear
- **G1 Registration.** `GameGearHandler`, in a new `src/RnRomManager.Systems.Sega` project, is registered after ColecoVision. Registry order: `gb`, `gbc`, `gba`, `n64`, `nes`, `snes`, `a2600`, `coleco`, `gg`. `/api/systems` (display-name order) puts "Game Gear" between "Game Boy Color" and "Nintendo 64".
- **G2 Contract values.** `Id` = `gg`, `DisplayName` = `Game Gear`, `ShortName` = `GG`, `Family` = `gamegear`, `RomExtensions` = `[".gg", ".sms"]`, `MinRomSizeBytes` = `8192`, `MaxRomSizeBytes` = `1048576`, `DatName` = `Sega - Game Gear`; `NormalizeForHashing` is the default. Facts (libretro DAT 2026.10.07, checked 2026-11-10): all five DAT files and the `Sega - Game Gear` thumbnails folder exist; 607 entries, 582 `.gg` + 25 `.sms` (SMS-mode games), 10,873–1,048,576 bytes.
- **G3 Header.** `ReadHeader` looks for the ASCII `TMR SEGA` signature at offsets `0x7FF0`, `0x3FF0`, `0x1FF0` (first hit wins; an offset is skipped when the file is shorter than offset + 16). Found → `RomHeader("gg", null, true, Fields)` with `offset` (`"7FF0"` etc.), `checksum` (bytes +10..+11, little-endian, as 4 upper-case hex digits), `productCode` (BCD digits as hex text: high nibble of +14, then byte +13, then byte +12, each as hex, leading zeros trimmed, `"0"` if all zero; bytes +12..+14 = `25 00 01` → `"25"`), `version` (low nibble of +14, number), `region` (high nibble of +15: `3` "SMS Japan", `4` "SMS Export", `5` "GG Japan", `6` "GG Export", `7` "GG International", other → the nibble as hex) and `sizeCode` (low nibble of +15, number). Not found → `null` (many Japanese carts have no header). Never throws.
- **G4 Ingestion.** The existing pipeline. A DAT-matched dump is stored as `roms/gg/<bucket>/<title>.zip` with the DAT's ROM name (`.gg` or `.sms`). An unmatched file (with or without a header) → Review (`NoDatMatch`, suggestions from the file name); never `InvalidHeader`, since a missing header is valid. Resolved through Review with a DAT entry (the `Dat` action, and `Attach` for an `AmbiguousGroup` item), the stored name takes the **DAT ROM name's extension** instead of `RomExtensions[0]` (`ReviewResolver.ResolveAsync`, the two branches building from `datRom.RomName` / `romName`), so an SMS-mode game is stored as `….sms` like its DAT name. This applies to every system; DAT entries are already filtered to `RomExtensions`, so the result is always an accepted extension, and for every existing system's handler it equals today's result except where the DAT entry's extension differs from `[0]`. Manual and Flag resolves (no DAT entry) keep using `RomExtensions[0]`: an unmatched `.sms` is stored as `….gg`. Under 8192 bytes → `TooSmall`, over 1 MiB → `TooLarge`. A `.gg` in another family's folder → `UnsupportedType`; another family's extension in `ingest/gg/` → `UnsupportedType`. Releases with a header show the Header button.
- **G5 Badge colour.** Sega blue, same in both themes: `app.css` `--bs-gg: #0060a8` on `:root` and `.text-bg-gg { color: #fff !important; background-color: var(--bs-gg) !important; }` next to the Coleco rules (white on it is AA, 6.3:1); `systemColours` gets `gg: { name: 'gg', foreground: '#fff' }` (the `name` union gains `'gg'`).
- **G6 Default box art.** `gamegear.svg` (drawn for this project, MIT) and its 512×512 `gamegear.png` render (headless Edge, as the Atari README shows), embedded and loaded like Coleco's, with a `README.md`.
- **G7 Upgrade.** Ingestion refuses with `DatsMissing` until an Admin runs **Admin → DATs → Refresh DATs** (documented).

## Risks
- **Membership leak via `notInCollection`:** a foreign collection id answers `404` before any query runs (P1), so another user's memberships can't be probed. Tested with two users.
- **`ISystemHandler` change:** the default member keeps third-party/test handlers compiling; a handler that forgets to override shows its full name in pickers (harmless).
- **`.sms` in `ingest/gg/`:** a real Master System dump placed there is matched only against the Game Gear DAT; unmatched it goes to Review as a Game Gear game. Accepted: there is no Master System handler yet, and when one is added its own folder scopes `.sms` to it.
- **No header required:** junk files of a valid size in `ingest/gg/` go to Review rather than `_failed/`. Same trade-off as Atari 2600.
- **Picker loads full box art:** up to 10 images per search, the same files the Library grid already shows; `loading="lazy"`.
