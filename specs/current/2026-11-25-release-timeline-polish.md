# Release Timeline and UI polish

## Summary
Adds a **Timeline** page (games linked to IGDB, counted per release year, zoomable, with a paged games table), a **Developers** collections tab, IGDB-id matching in the Duplicates report, a game count on Admin → ROM Zip Config, and a batch of UI fixes: Edit Metadata's Lookup Info actions move to the modal footer and tick every field, the game page gets a top button row (Google, Emulators, View on IGDB), clickable metadata, a two-line description, a highlighted cover card, and four reports gain a total count line. For every signed-in user except where a rule says Admin.

## Out of scope
- Games without an IGDB link (`igdb_id` null or 0) or without a release year on the Timeline.
- Mouse-wheel zoom or drag-to-pan on the Timeline (buttons only).
- Starter art for developers (text banner fallback only).
- Storing IGDB URLs or slugs; the link is resolved on demand (T7).
- Cross-system duplicate matching.

## Behaviour

### Timeline (T)
- **T1** Navbar: a **Timeline** link (icon `timeline`) between **Collections** and **Reports**, for every signed-in user, active on `/timeline`. Page `/timeline` with `<PageTitle icon="timeline" text="Timeline" />` and `<title>Timeline · RnRomManager</title>`. New `icons.ts` entries: `timeline: 'bi bi-calendar-range'`, `'zoom-in': 'bi bi-zoom-in'`, `'zoom-out': 'bi bi-zoom-out'`, `earlier: 'bi bi-chevron-left'`, `later: 'bi bi-chevron-right'`.
- **T2** Scope: games with `igdb_id > 0` and `release_year IS NOT NULL`. Everything below (counts, table) uses only these games.
- **T3** URL state `?system=&from=&to=&page=` (`lib/timeline.ts`, new). The **data range** is the min and max year of `GET /api/timeline?system=` for the current system. `from`/`to` are whole years; missing or non-numeric → the data range's bound; outside the data range → clamped to it; `from` > `to` → swapped. `page` ≥ 1, default 1. An unknown `system` → treated as absent. Page 1, the full data range and no system are omitted from the URL. Every change (system, zoom, pan, tick, Show all, page) navigates with `goto(…, { reset: false })` and so adds a history entry, as the Library (`routes/+page.svelte` `go`) does. Changing system resets `from`/`to` to the new system's full range and `page` to 1; changing range resets `page` to 1. The page loads `GET /api/systems` first (to tell an unknown `system` from a known one) and requests the timeline only after it; while loading it shows `Loading`, and a failed request shows `ErrorAlert` with retry, as the reports do.
- **T4** Controls, in one row above the strip: the reports' System `FilterDropdown` (as the Duplicates report uses it), then a button group: **Zoom in** (icon `zoom-in`, `aria-label="Zoom in"`), **Zoom out** (`zoom-out`, `aria-label="Zoom out"`), **Earlier** (`earlier`, `aria-label="Earlier"`), **Later** (`later`, `aria-label="Later"`), **Show all** (text). With `span = to - from + 1` and data range `[min, max]`:
  - Zoom in: `n = max(1, ceil(span / 2))`, `from' = from + floor((span - n) / 2)`, `to' = from' + n - 1`. 1990–1999 → 1992–1996.
  - Zoom out: `n = min(max - min + 1, span * 2)`, `from' = from - floor((n - span) / 2)`, then shifted into the range (`from' = max(min, min(from', max - n + 1))`), `to' = from' + n - 1`. 1992–1996 in 1980–2020 → 1990–1999; 1980–1984 → 1980–1989.
  - Earlier / Later: `step = max(1, floor(span / 2))`; the window moves by `step` keeping its span, shifted back inside the range. 1982–1991 in 1980–2020, Earlier → 1980–1989.
  - Show all: the full data range.
  - Disabled: Zoom in when `from == to`; Zoom out and Show all at the full range; Earlier when `from == min`; Later when `to == max`. A `<span class="small text-body-secondary" aria-live="polite">` beside them reads `<from>–<to>` (or `<year>` when equal).
- **T5** The strip: one tick per year in `[from, to]`, zero-count years included, in a horizontally scrollable row (`<div class="d-flex gap-1 overflow-x-auto pb-2 mb-3" role="group" aria-label="Release years">`). Each tick is a button showing the year and, under it, its count via `formatCount` (a `0` count gets `text-body-secondary`). Accessible name `<year>: <formatCount(n)> games` (`1 game` singular); `aria-pressed="true"` on the tick when `from == to == year`, else `false`. Clicking a tick sets `from = to = year`. The pressed tick is `btn-primary`, others `btn-outline-secondary`.
- **T6** Table: the games in `[from, to]` (and system), sorted by release year ascending, then title, then id (G1), 50 per page, through `GameResults` with `view="list"` (its usual list columns and quick play, as in the Library) plus an `action` snippet: **View on IGDB**, an icon-only `<a class="btn btn-sm btn-outline-secondary">` with icon `external`, `title="View on IGDB"`, `aria-label="View <displayTitle> on IGDB"`, `target="_blank" rel="noopener noreferrer"`, href `/api/igdb/games/<igdbId>/page` (rendered after the Play button in the actions cell, as Collections' Remove button is). The snippet is passed only when the timeline response says `igdbConfigured`, else `action` is undefined. `Pagination` (default label) below the table; above it a count line `formatCount(total)` + ` game`/` games` (Missing Metadata's markup). No linked game with a year at all: `EmptyState` "No games linked to IGDB have a release year yet." and no strip or table. A range with no games: the strip shows and the table area shows `EmptyState` "No games in this period.".
- **T7** `GET /api/igdb/games/{igdbId:int}/page` (any signed-in user): `igdbId` < 1 → `404`. IGDB not configured (`IGameInfoLookup.Configured` false) → `409 IgdbNotConfigured` "Metadata lookup needs Sources:IgdbClientId and Sources:IgdbClientSecret." (as `igdb-matches`). Otherwise `GamePageUrlAsync` asks IGDB (`fields url; where id = <id>; limit 1;`, through the existing token and 401-retry path). `GamePageResult(Url, FailedTitle)`: `Url` set → `302` to it; both null (no game, a game with no `url`, or a `url` not starting with `https://www.igdb.com/`) → `404`; `FailedTitle` set → `502 IgdbFailed` with that title. Results with `Url` set and both-null results are cached in memory per process (`IgdbPageUrlCache`, defined in `IgdbClient.cs` beside `IgdbTokenCache`, cleared when it holds 10,000 entries); the endpoint, not the client, reads and fills it, so a hit never calls `GamePageUrlAsync`; failures aren't cached. No audit row.
- **T8** `GET /api/timeline?system=` (any signed-in user) → `{igdbConfigured, total, years: [{year, count}]}`: years with ≥ 1 game in scope, ascending; `total` is their sum; `igdbConfigured` is `IGameInfoLookup.Configured`. Unknown `system` → `400 ValidationFailed` (`errors.system`: "Choose a registered system.").
- **T9** `GET /api/timeline/games?system=&from=&to=&page=&pageSize=` (any signed-in user) → the Library's paged list shape (`{items, page, pageSize, total}`, each item the `/api/games` item, which gains `igdbId`), scope T2, `from`/`to` inclusive and optional. `from` or `to` outside 1–9999 → `400` keyed by that field, "Must be 1–9999."; `from` > `to` → `400 errors.from`: "Must not be after to.". `page`, `pageSize` and `system` validate as `/api/games`; default pageSize 50. Sorted as T6. The endpoint always sets `YearFrom = from ?? 1` and `YearTo = to ?? 9999`, so games without a year stay out (T2), and builds items through `LibraryEndpoints.ForViewerAsync` and `ToListItemDto`, as `/api/discovery/{kind}/games` does.

### Game list sort (G)
- **G1** `GameSort.Year` orders `g.release_year IS NULL, g.release_year {dir}, g.title, g.id` (title and id always ascending, as Rating does), everywhere it's used (Library, collections, Timeline). `GameSort`'s summary ("tie-break is always `id`") and `Year` get a doc comment like `Rating`'s.

### Duplicates (D)
- **D1** `GET /api/reports/duplicates` takes `match=title|igdb` (case-insensitive, default `title`; anything else → `400 ValidationFailed`, `errors.match`: "Must be title or igdb."). `igdb` groups are 2+ games in the same system sharing one `igdb_id > 0`, sorted by system, then the group's title, then `igdb_id`; their `gamesKey` is computed exactly as for title groups (SHA-256 of the sorted game ids, in SQL), and dismissed groups drop out before paging the same way. Each group gets `igdbId` (null for title groups). For an IGDB group `baseTitle` is the smallest `display_title` of its games (display only).
- **D2** Dismissals are kept per match type: new migration `0028_duplicate_dismissal_match` adds `match_kind VARCHAR(8) NOT NULL DEFAULT 'title'` to `duplicate_dismissals` and makes the primary key `(match_kind, system_id, base_title, games_key)`, in one `ALTER TABLE duplicate_dismissals ADD COLUMN match_kind … FIRST, DROP PRIMARY KEY, ADD CONSTRAINT pk_duplicate_dismissals PRIMARY KEY (…)` as `0026_discovery_logos` does. Existing rows become title dismissals. An IGDB dismissal stores `base_title` = the IGDB id in decimal.
- **D3** `POST /api/reports/duplicates/dismiss` body `{system, gamesKey, baseTitle}` (title, unchanged) or `{system, gamesKey, igdbId}` (IGDB). Both or neither of `baseTitle`/`igdbId` → `400 errors.igdbId`: "Give baseTitle or igdbId, not both."; `igdbId` not a whole number ≥ 1 → `400 errors.igdbId`: "Must be a positive whole number.". "Given" means present and not JSON `null`; `DismissDuplicateRequest` gains `JsonElement? IgdbId` (valid when it's a number with `TryGetInt32` ≥ 1), so a string or fraction gets this error instead of a binding failure. A given but empty or too-long `baseTitle` keeps today's `errors.baseTitle` "Must contain 1–255 characters.". Still Admin-only. Merge is unchanged.
- **D4** Duplicates page: a **Match by** select in the reports' labelled-select markup (as Multiple Releases' Minimum releases: `<div class="input-group input-group-sm w-auto">`, `<label class="input-group-text" for="duplicates-match">Match by</label>`, `<select id="duplicates-match" class="form-select w-auto">`), in its own `col-auto` before the System filter's column, with options **IGDB ID** (`igdb`, default) and **Title** (`title`), held in page state like the System filter; changing it resets to page 1 and reloads. The request is `/api/reports/duplicates?match=<m>&page=<n>&pageSize=25` then `&system=` when set. The page's local `DuplicateGroup` interface gains `igdbId: number | null`. IGDB group headers show a `<span class="badge text-bg-secondary">IGDB <id></span>` after the `<h2>` (a sibling, so the heading's name stays the base title); dismissing an IGDB group posts `{system, gamesKey, igdbId}`. Empty text for IGDB: "No games share an IGDB ID." (Title keeps "No duplicate games found.").

### Game page (P)
- **P1** The top row (`<p>` with **Back to Library**) becomes a `<div class="d-flex flex-wrap gap-2 mb-3">` row: Back to Library, then **Google**, then **Emulators**, then **View on IGDB** (`btn btn-sm btn-outline-secondary`, icon `external`, `target="_blank" rel="noopener noreferrer"`, href T7) shown only when `game.igdbConfigured && game.igdbId > 0`. Google and Emulators keep their classes, icons and behaviour (Emulators keeps `bind:this={emulatorsButton}` for focus return), render only once the game has loaded, and are removed from the action row, which becomes: Download ZIP, Download ROM, Collections, Next…, Manage.
- **P2** Metadata table: each developer, publisher and genre is its own link, comma-separated, to `/collections?tab=<developers|publishers|genres>&name=<value>` (`href="{resolve('/collections')}?{new URLSearchParams({ tab, name })}"`, as the ROM Zip Config badge links to the Library). Year links to `{resolve('/timeline')}?from=<y>&to=<y>` only when the game has a year and `igdbId > 0` (else plain text, since T2 excludes it). `—` stays plain text.
- **P3** Collections resolves `?name=`: it calls `GET /api/discovery/{kind}/key?name=<value>` and replaces the URL (`goto(…, { replace: true, reset: false })`, as `goDiscovery` does) with `?tab=<kind>&key=<key>`. A 404 replaces it with `?tab=<kind>&find=<value>` (cut to the existing `find` limit); any other failure falls back the same way. Only the Publishers, Developers and Genres tabs read `name`; a `key` already in the URL wins and `name` is dropped.
- **P4** `GET /api/discovery/{kind}/key?name=` (any signed-in user; `kind` publishers, developers or genres, else 404): `name` 1–255 characters after trimming (else `400 errors.name`: "Must be 1–255 characters."); returns `{key}` of the group whose normalized name equals the normalized `name` (normalization done by MariaDB as in `DiscoverySql`), or 404 when no game has it. `FindKeyAsync` computes the parameter's key in one `SELECT` using `ValuesCte`'s trim, lowercase and `SHA2` expressions (a shared helper in `DiscoverySql`), then answers from the same cached index as `GetGroupAsync` (`ByKey`), so a found key always opens a group.
- **P5** Description: `<p id="game-description">` clamped to 2 lines (`-webkit-line-clamp: 2`, `white-space: pre-line` kept). When the full text is taller than the clamp (`scrollHeight > clientHeight` of the clamped `<p>`, measured in an `$effect` after the description renders and on `<svelte:window onresize>`, only while collapsed; no `ResizeObserver`, which jsdom lacks; tests stub both heights), a `btn btn-link btn-sm p-0` toggle **Show more** / **Show less** follows it, with `aria-expanded` and `aria-controls="game-description"`. It collapses again when navigating to another game.
- **P6** Images tab: the cover's card gets `border-primary border-2` and its body `bg-primary-subtle`; the "Cover" badge stays.

## Risks
- **IGDB rate limits (T7):** any signed-in user can trigger one IGDB call per uncached id. Hits and not-found results are cached, so only distinct new ids cost a call; looping over many ids shares the rate limit with Admin lookups. Accepted (signed-in users only).
- **Duplicates PK change (D2):** a single `ALTER` on a small table; covered by `SchemaMigrationTests`.
- **Timeline query cost:** counts are one `GROUP BY release_year` over `games` (no index on `igdb_id`); fine at library sizes of ~100k rows. Not cached.
- **Developers index build:** same cost as publishers; shares the 60 s cache.
